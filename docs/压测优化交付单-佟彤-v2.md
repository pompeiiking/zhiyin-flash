## 2. 相对 v1 的差异

`docker-compose.perf.yml` 恢复对象存储共享卷：

```yaml
x-zhiyin-image: &zhiyin-image
  volumes:
    - zhiyin-object-data:/app/data/objects

volumes:
  zhiyin-redis-data:
  zhiyin-postgres-data:
  zhiyin-object-data:
```

`zhiyin-flash` 与 `zhiyin-background` 都继承 `x-zhiyin-image`，因此两个 API
副本和后台服务使用同一个对象存储卷。该挂载用于避免上传材料后，后续请求落到
另一个 API 副本或后台服务时找不到对象文件。

除上述 Compose 变更外，其余 v1 内容无变化。

## 5. 服务器构建与部署检查

从最终冻结提交同时构建后端与 Web/Nginx 镜像：

```bash
docker build -t "zhiyin-flash:opt-佟彤-v2" .
docker build -t "zhiyin-flash-web:opt-佟彤-v2" \
  ./zhiyin-src/template/zhiyin-web
```

部署前执行 Compose 校验：

```bash
ZHIYIN_AUTH_JWT_SECRET="$ZHIYIN_AUTH_JWT_SECRET" \
ZHIYIN_IMAGE_TAG="opt-佟彤-v2" \
ZHIYIN_WEB_IMAGE_TAG="opt-佟彤-v2" \
docker compose -p release -f docker-compose.perf.yml config --quiet
```

部署 R2W1 后，使用 `docker inspect` 确认两个 `zhiyin-flash` 容器和唯一的
`zhiyin-background` 容器均把同一个 `release_zhiyin-object-data` 卷挂载到
`/app/data/objects`。随后执行一次“上传材料 → 携带 `material_ids` 发消息”的
跨副本冒烟验证，通过后再开始正式压测。
