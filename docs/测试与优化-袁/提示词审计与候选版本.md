提示词调用链：数据库注册表 → `agno_engine._prompt_bundle` → `core` + 对话 `guide` 或 `task.*` + 角色描述 → 契约 Schema → 模型工厂参数 → Agent 运行 → 结构校验 → 业务服务落库/缓存/展示。每轮日志记录提示词指纹、模型 ID、温度/超时/重试、契约指纹与有效性，不打印密钥、完整个人资料或原始提示词。`role.info_scout` 的调用缺口留在《缺陷清单.md》，本次不将其列为“受测通过”。

结构校验失败时还有一层**内部纠错指令**，位于 `agno_engine._repair_once`，最多运行一次。D20 暴露了这层文字可能渗入用户回复，因此本次把校验反馈标成内部信息，纠错时带回原始任务与上下文，并要求用户可见字段直接回答原问题。该层是编排器的格式修复控制，不作为第 27 条产品提示词登记；其模拟真实模型探针五轮 5/5 未泄露内部措辞，未来仍需监测偶发修复轮。

复盘层还要区分“模型所需的机器任务 ID”和“用户应读到的任务正文”。D21 在真实服务发现 `t1` 被直接写进回复；本次在结构化产出交给界面前，以已登记行动计划的任务正文替换可见文字中的 ID，保留结构化 ID 供勾选和成就核对。该输出映射不改变 Prompt-R12 的 26 条正文，也不计入 A/B 提示词提分。

## 质量门槛与当前结论

最终 Prompt-R12 以固定 R0 对照：五环节 40 例、九任务 27 例、七入口及异常边界 17 例各三次；九个代表性高风险例各五次。R0 合约有效 296/297，R12 为 297/297；候选 297 份输出的可程序判定事实边界均通过。R12 一次结构修复 2 次、总 token 903,337、平均 2.75 秒、P95 4.70 秒；R0 分别为 13 次、1,036,798、3.43 秒、8.67 秒。多次中断和失败轮次没有混入最终指标，详情见《模型评测记录.md》。

本目录《盲评样本与评分表.md》的 10 组匿名 A/B 已由 Codex 按用户指示自评：R12 为 77/80，事实硬失败 0/10；R0 为 69/80，事实硬失败 6/10。评审者不是独立真人，不能据此宣称真人盲评完成。候选在空态简报和匹配说明的表达还有改善空间；本次硬门槛已按用户指定评审方式核对。

真实服务五环节 35/35、九项页面任务至少一轮 9/9，图表与浏览器结果见《测试用例与结果矩阵.md》。无依据的方案匹配分数与维度数值允许 `null`，前端显示“待核验”；外部岗位要求未取回时不计算排名或图点。R12 的生成结果不等于对所有未来输入的保证，建议继续保留可追溯日志和问题样本回放。Prompt-R12 是本地候选配置，正式发布与独立真人复核仍由项目负责人决定。
