## 五环节与页面任务

```mermaid
flowchart LR
  A[七个任务入口或自由聊天] --> B[读取共享黑板]
  B --> C[意图和阶段规则]
  C --> D[选主理与工具]
  D --> E[DeepSeek 结构化输出]
  E --> F[契约校验]
  F --> G[画像或资产落库]
  G --> H[缓存失效和行为记录]
  H --> I[接口响应及三页面显示]
```

阶段为采集、诊断、决策、行动、复盘。`orchestrator.py` 负责黑板读取、路由、资产版本、告知与持久化；`agno_engine.py` 负责拼装 `core.system`、该环节角色、对话 `guide.closing`、契约与工具。九项页面 AI 任务由 `services/ai_tasks.py` 直接调用指定 `task.*` 提示词，不注入对话收尾规范；输入快照、缓存键与 SSE 终帧在该服务统一处理。

## 四类数据账与异步链

1. **画像事实：**`ProfileField` 保存 key、中文 label、value、source、confidence、evidence 与更新时间；采集落库后影响读缓存和后续资产依据。图表只使用这份已存的 0–1 数值。
2. **对话及行为：**任务会话、逐轮消息、`client_msg_id` 幂等、行为日志分开保存。复盘和停滞 Worker 读取行为日志，不依赖页面当前显示值。
3. **报告、方案、行动资产：**版本仓储保存正文与版本号；画像变化标记受影响资产，再由后续真实重算更新，结论变化告知随响应发送。任务勾选改变资产内状态，不凭空创建新版本。
4. **外部事实与理论：**学职平台、Web、知识库为增强来源；失败时保留“未取得”的边界。RAG 先由 DashScope 1024 维嵌入写入 pgvector，再用来源引用返回；外部获取失败不应转成虚构引用。

后台 `ActiveEventWorker` 从真实关键动作计算停滞天数，按策略参数、通知历史冷却与窗口限次决定是否推送；`vector_sync.py` 维护向量同步状态。前端 `PortalView`、`ConsoleView`、`ReportView` 读取同一 API，浏览器回归已覆盖三页。功能开关目前在 bootstrap 回包中，但部分前端入口尚未按开关门控，见《缺陷清单.md》。

## 状态位置、失败边界与回归入口

数据库表名以 `zhiyin-infrastructure/zhiyin_infrastructure/postgres/schema/` 为依据。Redis 读缓存键由 `RedisCacheGateway` 生成，格式是 `{prefix}:{namespace}:{key}`，命名空间清理键是 `{prefix}:__ns__:{namespace}`；本次隔离前缀为 `zhiyin_audit`。页面 AI 任务结果另存 `ai_task_result`，键由任务名及参数组成，例如 `day.advice.2026-09-25|480`。以下列出五条关键状态链，功能级正反例在《测试用例与结果矩阵.md》逐方法展开。

| 链路 | 主要状态表或缓存 | 正向检查 | 反向及失败检查 |
| --- | --- | --- | --- |
| 身份与会话 F02～F04 | `biz_user_account`、`infra_auth_credential`、`infra_auth_session`、`biz_task_session`、`biz_conversation_turn`、`biz_conversation_memory` | 注册→进入七类任务→逐轮历史；`client_msg_id` 重放读回同一回复 | 错误凭据、登出后令牌失效、跨账号 task_id 拒绝、重复消息不重跑模型；见 S/L/B/N |
| 画像→诊断→决策 F05/F07～F09 | `biz_profile`、`biz_profile_field`、`biz_profile_gap`、`biz_asset_version`、`biz_asset_content`、`vec_record` | 用户事实与材料入画像，报告存版本，认领差距后生成可改选的方案 | 缺外部要求时不补造岗位事实、理论卡或分数；画像变化先标待重算，真正重算才增版本并告知；见 L、固定评测与 D16 |
| 学业→行动→简报 F06/F10/F11 | `biz_academic_snapshot`、`biz_calendar_node`、`biz_asset_content`、`ai_task_result`、Redis 读缓存 | 导入课程、勾选任务、日历节点与今日建议联动；日建议按日期和时区分键 | 文件超限 422、删除学业后回退、任务变更后 AI 缓存失效、跨日或跨时区不复用旧结果；见 A/L/S/T6 |
| 外部情报与知识 F12 | `vec_record`、`infra_vector_sync_state`、`biz_registry_item`、`infra_ai_model` | DashScope 嵌入 1024 维写入 pgvector；理论卡与带来源情报读取 | 数据源超时、向量失败或无效学信码只返回未取得/错误，不补造来源；见 T3、U、D11 |
| 行为→通知→复盘 F14/F15 | `biz_behavior_log`、`biz_track_event`、`orc_event_outbox`、`orc_schedule_job`、`orc_notification` | 行为时间线驱动复盘与停滞判断；通知已读后待处理数下降 | 事件 ID 去重、冷却与窗口限次、跨账号已读拒绝；真实通知 2→1 与 50 次跨账号读隔离，见 S/L/U/T6 |

这里的“已连接”只表示启动装配能找到网关或仓储，不等于功能已上线。`flow.proactive` 没有模型调用点，提醒由 Worker 和 `notify.stall.*` 模板完成；Redis 限流网关虽装配，业务端点尚未调用；`role.info_scout` 虽登记，主流程未独立调用。它们的处理口径与用户批准的例外见《缺陷清单.md》。
