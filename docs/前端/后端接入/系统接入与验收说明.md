## 本轮修复与复验方法

- 工具页改为实际读取画像、方向和行动计划，修复已有方向却显示 0、已全部完成却显示“暂未形成”的问题。
- 已发布工具按模块 ID 去重，并区分数据查看、页面跳转与可执行动作。
- 学籍页面移除“已展示核验示例”的个人状态，按后端学信网来源证据显示“已有核验资料”；资料读取失败显示错误状态。
- 管理端动态配置按钮遵循管理员身份和请求状态，工作台跳转使用当前应用的 hash 路由。
- 管理接口、普通接口和 AI 流式响应均校验发起请求时的账号，防止旧请求影响新登录账号。

自动验收脚本为 `scripts/acceptance/frontend/frontend-remaining-acceptance.py`，在隔离 API 容器内运行。须挂载该脚本目录到 `/acceptance`、本证据目录到 `/results`，并配置独立数据库和 Redis；脚本要求 `ZHIYIN_DATAFLOW_ISOLATED=1`、`ZHIYIN_MODULE_ENV=workbench`，数据库 DSN 指向 `@db:5432/acceptance`，否则拒绝写入。完整运行命令：`python /acceptance/frontend-remaining-acceptance.py`。脚本内创建临时账号和业务前置资料，再通过 HTTP 执行操作与读取结果；不会启动 Source Worker 或 Executor。真实模型操作仍使用环境中的模型配置，学信核验不模拟成功。临时账号密码仅保存在容器 `/tmp/acceptance-accounts.json`，不会写进验收报告或提交仓库。
