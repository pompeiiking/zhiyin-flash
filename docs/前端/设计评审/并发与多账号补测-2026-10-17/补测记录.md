# 异常恢复、并发保存与多账号补测

日期：2026-10-17。分支：`codex/frontend-integration`。

本轮使用本地真实后端与持久化数据库，通过浏览器检查桌面和 390 × 844 手机视口。两个新增账号的资料为明确构造的验收输入，AI 回复与检索结果来自实际服务，未使用演示响应。手机视口检查不等于真机验收。学信网核验、生产部署不在范围内。

## 已复现并修复

1. **同一任务被旧表单覆盖**：两个标签页打开同一任务，甲保存标题，乙用旧表单保存状态时会恢复旧标题。新增任务原值检查，在后端原子更新内拒绝过期编辑；界面保留乙的输入并提示重新读取。桌面和手机均实际复测，甲的内容保留。
2. **创建成功但响应丢失后的重复创建**：临时代理先将请求提交真实后端，待成功响应返回后主动断开下行连接。新增稳定请求标识和后端幂等创建；桌面、手机分别重试，刷新后均只有一条任务。编辑成功后的重复请求也不产生新的变更。
3. **响应不完整时暴露 JSON 解析错误**：改为说明结果尚未确认、需读取记录后再决定重试，避免错误暗示保存一定失败。
4. **并发新增任务的身份误判**：返回列表包含多个新任务时，不再随意选择第一条作为本次创建结果。后续仍以原请求标识核对，避免编辑另一标签页创建的任务。新增组件回归测试。

## 浏览器实测结果

| 场景 | 结果 |
| --- | --- |
| 两标签页新增同一待办记录 | 去重后仅一条，刷新搜索确认 |
| 两标签页编辑同一任务 | 过期保存明确被拒，输入保留，无静默覆盖 |
| 服务已保存、响应丢失、重试 | 桌面和手机各完成一次，仅创建一条任务 |
| 真实流式回复输出首段后断开 | 桌面和手机均显示未完成，可重试恢复完整回复，无重复用户消息 |
| 空资料账号咨询 | 明确资料不足，没有继承原账号的专业和经历 |
| 视觉传达设计账号咨询 | 使用该账号的专业、两份 Figma 课程原型；未混入原账号资料 |
| 多标签页退出、切换账号 | 另一个标签页退出至登录；新登录后读取新账号画像 |
| 画像来源 | 手工资料标为本人修改，明确未附原始证据 |
| AI 来源浮层 | 手机可打开、滚动、关闭；展示专业/职业检索资料与参考方法，并提示不等于每项都能支持结论 |

来源核对覆盖当前回复中的来源展示及其与账号专业的相关性；未逐条独立核验外部网页全文，也没有进行学籍核验。

## 仍需跟进

- AI 质量边界：初次回复无依据判断“撑不起作品集”。已修改总纲及诊断提示词，取消强制认领差距，明确课程身份不代表质量不足，历史 AI 内容不能当用户事实。真实后续回复主动撤回该判断；追问时也明确未见作品不能评价。但仍将未提供的可展示成品称为“差的两条”之一，证据缺口与能力差距的措辞尚未完全稳定，不能宣称所有生成结果已可靠。
- 本次并发保护针对任务、阶段编辑器及对应保存接口，不代表画像、偏好、复盘等所有表单都已完成并发验收。
- 登录过期恰逢保存、上传中断后恢复、长时间断网与连续多次重试、真实手机浏览器仍未在本轮完整覆盖。
- 冲突后目前需要关闭编辑卡片、重新读取任务再核对；未实现自动合并或保留草稿后的一键重放。

- 阶段编辑新增原值检查、稳定请求标识与幂等处理；重复提交不新增阶段版本，阶段内任务保持。后端新增测试覆盖旧表单冲突、创建重试及任务保留。
- 实际浏览器：两标签打开“阶段并发补测”，甲改为“阶段并发补测：甲的新标题”，乙保存旧表单被拒。桌面和手机均显示错误并保留草稿，甲刷新后标题仍为新值。
