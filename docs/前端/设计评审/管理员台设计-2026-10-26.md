# 管理员台设计（2026-10-26）

## 目标与边界

管理员台是独立于学生端的运维与治理工作区，路由 `/admin`。它解决四件事：

1. 今天有没有需要管理员处理的事项；
2. 哪些模块被授权、哪些已授权但实际不可用；
3. 发布任务是否需要确认，执行进行到哪一步；
4. 当前环境、执行器和动态配置是否一致。

**不新增后端接口，也不展示没有接口依据的用户管理、营收、活跃度或“健康分”。**
所有数字来自现有 `/developer/context`、`/developer/modules`、`/developer/checks`、
`/developer/releases`、`/developer/platform-status` 与 `/app/config/reload`。
模块平台未装配（例如本地内存模式）时，页面显示可重试的真实错误，不用示例数据补空。

## 版面

- **左轨**：品牌、当前环境与构建号、五个分区（总览 / 模块与授权 / 数据编排 / 发布与验收 / 系统与环境）、当前账号身份、开发工作台与学生端出口。
- **主区**：页头说明当前分区的任务，右侧只保留刷新和低频出口；下面是分区内容。
- 管理台不套学生端侧栏、顶栏与提醒浮层；它有自己的 `meta.admin` 壳层。手机端左轨收成品牌行 + 可横向滚动的分区导航。
- 统一使用现有蓝/红/中性主题令牌，红蓝切换与深浅主题都生效；不引入第四种强调色。

## 分区

### 总览

- 四项真实计数：已安装模块 / 待确认发布 / 已授权但受阻 / 检查未通过。
- **现在需要处理**：只列会阻塞使用或需要管理员确认的事项（待确认发布、受阻模块、检查未通过、执行器离线），每条直达对应分区。
- **最近发布**：最近五条发布记录，可在工作台环境直接确认待确认任务。
- **运行状态**：环境、构建版本、执行器心跳、待处理版本、最近检查。
- 快捷操作：运行检查、管理授权、查看环境。

### 模块与授权

- 默认是紧凑清单，不是整屏授权卡片：名称/说明、类型、状态、授权摘要、所属应用。
- 搜索与筛选（全部、应用、技能、未启用、受阻）。
- 点一行打开右侧抽屉：启用开关、读取范围、业务操作、可用智能体、模块信息；保存走真实 `PUT /developer/modules/{id}/policy`。
- 始终说明“所属应用停用 → 子模块同步不可用”，并展示 `blocked_by` 的具体应用。
- 开发者可查看，只有管理员能保存；服务端仍做最终权限校验。

### 数据编排

复用现有 `Workflows.vue` 的真实编辑/调试能力，外面包一层管理台语言：说明、列表、编辑、运行记录都在同一页；不复制一套假流程编辑器。原有绿色开发页样式在管理台外壳内被主题令牌覆盖。

### 发布与验收

- 待确认、执行中、已结束、失败四类筛选；显示提交号、发起人、时间、阶段。
- 管理员在开发工作台环境可直接确认；其他环境只读，并明确说明原因。
- 展开记录查看执行器事件和失败位置；成功任务可打开测试环境地址。
- 失败显示“已回滚/失败”，不把未完成说成成功。

### 系统与环境

- 当前环境、管理台构建、环境运行版本、环境地址；版本不一致时给出明确警告。
- 执行器心跳、待处理版本、基线提交。
- 动态配置重载（仅管理员），说明只重读环节口径、气泡编排与采集规则。
- 功能开关按中文名称展示（完整报告、导出资料、日历与课表等），保留原始代码作为次级信息；开关由部署配置维护，界面不伪造修改入口。

## 状态与失败

- 首次读取显示骨架；分区接口部分失败时，其余数据照常展示，并明确列出“本次未读取”的部分。
- 403/无权限使用独立说明页，不显示可点击但无效的管理导航。
- 写操作失败保留原值，显示服务端错误；成功后刷新对应真实数据。
- 所有时间、状态和计数来自后端；没有“最近活跃”“权限分”等无法核验的指标。

## 验证范围

- `npm test`（含管理员统计/待处理派生规则）、`vue-tsc --noEmit`、`npm run build`。
- 使用本地 fixture API（不进入仓库）在 1280×900 与 390×844 浏览器中检查总览、模块抽屉、编排、发布、系统页的桌面与手机布局。
- 真实后端学生账号访问 `/admin` 显示无权限页；真实管理员/模块平台数据需在 PostgreSQL 环境复核。
