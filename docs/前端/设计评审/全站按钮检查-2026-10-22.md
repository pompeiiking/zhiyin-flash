# 全站按钮检查

日期：2026-10-22。

## 结论

当前按钮存在一定混乱，集中在动作命名、入口重复、移动端主次和危险操作表达。现有蓝色主按钮、普通按钮、文字操作已具备基础层级，不需要重新设计全站，也不应该把所有页面套成同一种工具栏。

最先处理：统一“刷新／生成／导入／删除”的含义，精简报告页手机工具栏，让按钮名称准确表达后果；再逐页合并冗余入口。

## 检查范围与证据

- 运行页面：`http://127.0.0.1:5276/`，个人画像重构工作目录对应的前端；后端为本机 8000 服务。
- 浏览器检查了个人画像、成绩、报告、方向方案、职业探索、今日行动、阶段计划、日历课表、待办目标、复盘、完成记录、工具、账号设置、提醒、指南和对话共 16 个学生页面的当前控件。
- 桌面查看画像、报告、阶段计划；390 × 844 模拟窗口查看画像、成绩、报告和日历课表。手机模拟仅证明布局，不代表真机触控验收。
- 源码核对了页头、路由、业务处理函数、导入表单、任务编辑、通知中心、账号浮层、门户与开发者页面入口。开发者页面没有管理员身份，未实际进入管理操作；门户登录注册未重新提交。
- 当前测试账号的方向、计划、待办等部分业务为空。非空任务、删除确认等分支以源码核对为主，未逐个点击写入、删除、生成或导出，不声称所有按钮已通过功能回归。
- 本轮为检查，未修改业务代码、用户资料或配置。

P1 表示容易误解业务后果、应优先处理；P2 为明显的使用成本；P3 为较低优先级的整理项。本次未确认会直接导致数据损坏的 P0 问题。

## 逐页处理方向

| 页面 | 保留的主要动作 | 次要或就近动作 | 优先整理 |
|---|---|---|---|
| 对话 | 发送、停止、必要审批 | 添加材料、线索、画像、复制 | 合并过程入口；审批按具体对象命名。 |
| 个人画像 | 补充信息 | 逐项更正、来源、学籍核验、导出 | 统一补充入口语言；删除使用危险样式；刷新不能叫重新核对。 |
| 我的成绩 | 导入／重新导入成绩 | 生成学习分析、查询筛选 | 统一刷新与导入；清空与导入分开。 |
| 你的报告 | 生成／重新生成报告 | 版本记录、导出、打印 | 精简手机页头；明确 JSON 导出。 |
| 方向方案 | 当前为空时“开始梳理方向” | 刷新、版本、打印 | 有方案后的比较与确认仍需非空数据实测，不能仅据空态判定合理。 |
| 职业探索 | 搜索或获取职业资料 | 用画像比较、专业信息、原始来源 | 数据刷新与 AI 比较保持明确区分；不因控件少就增加更多入口。 |
| 今日行动 | 当前任务执行／完成 | 安排新任务、阶段计划 | 当前空态较克制；非空任务的完成、等待、编辑关系待场景回归。 |
| 阶段计划 | 开始规划／维护阶段 | 手动新增阶段、版本 | 手动和 AI 创建路径可以并存，应说明各自用途，不合并业务能力。 |
| 日历课表 | 日期导航；课表区的导入 | 时间安排、冲突检查、当日建议 | 日期导航成组；刷新日程和导入课表明确区分；清空降级。 |
| 待办目标 | 添加待办／目标 | 生成建议、转向今日行动 | 当前主次相对清楚；避免三个“去今日行动”近似入口同时出现。 |
| 任务复盘 | 选择任务、填写复盘 | 历史记录、返回行动 | 无任务时去掉无效切换控件与重复跳转。 |
| 完成记录 | 查看记录 | 刷新、下一步建议 | 不把所有下一步引导都做成抢眼按钮；保留有上下文的入口。 |
| 工具 | 进入对应工具 | 使用说明、刷新资料 | 入口名称和实际落点一致。 |
| 设置 | 保存当前设置 | 导出资料、退出登录 | 设置保留统一保存规则；退出登录不与保存挤在同一操作组。 |
| 提醒 | 查看事项或前往关联页面 | 标为已处理、稍后 | 状态操作分层，少用一排同权重按钮。 |
| 指南 | 按步骤进入业务 | 返回、术语说明 | 减少重复的底部跳转。 |
| 门户与登录 | 开始咨询、登录／注册 | 规则、返回 | 源码检查未见必须增加的操作；本轮未重新提交账号流程。 |
| 开发者管理 | 模块配置、检查、发布等按任务区分 | 预览、历史 | 应和学生端权限与入口分离；本轮仅源码检查，不宣称管理功能已实测。 |

## 建议采用的按钮约定

1. 每个任务区域有明确主操作；页头通常一个主要动作，其余按使用频率作为普通按钮、文字操作或更多菜单。不限制整页只能有一个蓝色按钮，也不强制每页必须有更多菜单。
2. “刷新”只读取；“分析／生成”调用 AI 产生新结果；“导入”引入资料；“保存／替换／启用”明确写入；“删除／清空”表达移除范围；“撤销”只用于确有恢复机制的操作。
3. 主次由任务、位置、文字和样式共同表达，不只依靠颜色。链接的业务后果应可预期，进入对话的按钮需说明下一步。
4. 关键确认写出对象与后果：例如“确认替换 2 门课程”，同时保留替换范围和保留内容说明。不能为了按钮短而丢掉审批边界。
5. 手机端保留一个明显的主要入口，低频操作按需展开；不把全部次要按钮强制铺成等宽大格子。日期导航、确认与取消保持成组。
6. 关闭、取消、暂不执行语义分清：关闭表单、取消尚未提交的编辑、拒绝一项提案不是同一个状态。已保存结果必须来自服务端回执。

## 整改验收建议

- 同一动作跨页命名一致；任何“刷新”都不意外生成、导入或写入。
- 生成、替换、清空的按钮文案与真实接口后果一致；危险动作仍有明确确认。
- 报告手机页头不再连续占三行操作；日期导航不拆成难以识别的两组。
- 入口去重不损失真正独立的功能，长页面保留必要的就近入口。
- 重复点击、加载中、错误重试、无数据、审批过期、执行结果未知均有正确状态；失败不显示成功。
- 键盘可操作、焦点可见、控件有可读名称，触控热区及相邻间隔合理；隐藏项不占焦点。
- 确认／取消不会互换位置；删除样式一致，屏幕阅读器能识别对象和忙碌状态。
- 使用有计划、有待办、有历史版本、有待审批提案的账号补充非空回归；真机补测底部导航、浮层和输入键盘遮挡。

## 工具说明与限制

本轮采用 Impeccable 的按钮与界面检查思路，结合浏览器、源码和实际处理函数核对，不提供未经全维度验证的全站可用性评分。机械检测器另产生 32 条边框装饰类提示（27 条 side-tab、5 条 border-accent-on-rounded），不是按钮失效证据，也不能据此否定已确认保留的界面风格，因此未计入上述按钮问题。

## 后续整理与验证

已按用户“你整一下吧”的要求实施：

- 报告页保留重新生成、版本记录和更多。刷新报告、导出 JSON 数据、打印报告移入更多；删除原先手机端强制双列的工具栏规则。390 像素下三个入口同排，均高 44 像素，320 像素下无横向溢出。
- 新增共用 `ActionMenu.vue`，使用 Reka 的菜单语义、方向键、禁用状态、Esc 关闭和焦点返回。报告、课表和提醒共用，不再各自堆一排次要操作。
- 成绩和课表明确区分刷新、重新导入、确认替换、清空。同步调整导入表单标题；第一次导入、无旧记录时确认按钮称“确认导入”，有替换记录时称“确认替换”。去掉课表区重复的更新入口，清空放入更多。
- 清空确认说明范围及需要时重新导入；画像删除和任务删除统一使用危险按钮。未更改后端接口、审批边界或清空功能本身。
- 日历日期导航成为一个不可拆散的操作组，周／月视图切换在旁边独立呈现。手机上已实际切换下一周并返回今天。
- 对话移除“处理记录”和“操作记录”展开入口；保留线索、已保存版本和简短执行回执。执行中及结果未知的回执不会因后来产生新记录而消失；一般历史回执仅保留最近一条在输入区上方展示。服务端历史没有删除。
- 对话审批按操作显示替换课表、保存报告、标记完成、删除记忆等具体名称，删除使用危险样式；确认和暂不执行的事件协议保持不变。
- 提醒主动作改为查看详情，已处理为次操作，已读、恢复和稍后再提醒进入更多。稍后提醒以独立表单编辑，不在更多菜单内再嵌套浮层。
- 复盘无任务时去掉队列、禁用切换按钮、空任务选择器及重复跳转，保留安排阶段任务。画像统一补充信息与刷新个人资料；分析使用重新分析；工具入口准确写明前往哪个页面；指南删除重复的底部画像与方向按钮。

部分检查项采用保留而非删除：画像的下一步核验入口与学籍卡的核验入口各自有上下文；不同页面仍保留适合自身的布局。原有跨文件样式层叠没有在本次按钮整理中进行全量迁移，避免扩大成全站重设计。新的更多菜单已收敛为共用组件。

验证结果：

- 前端 105 项测试通过；类型检查和生产构建通过；接口对齐仍为 98 个 schema、91 个学生操作。
- 浏览器验证：报告更多菜单方向键、Esc 与焦点恢复、刷新、版本记录；重新导入成绩及取消；成绩清空确认与取消；课表更多、清空确认与取消；复盘空态；提醒更多、稍后提醒表单、过去时间拦截与取消；工具六个入口名称；对话过程入口清理及保存回执。
- 桌面及 390 × 844 手机布局已检查；报告另检查 320 像素无横向溢出。未执行清空、删除或重新生成报告，保留测试账号当前资料。新审批文案已完成编译检查，本轮没有另外制造一项真实 AI 提案执行。
