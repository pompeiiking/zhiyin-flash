## 3. 设计系统（改动必须遵守）

### 令牌
- `src/styles/tokens.css` —— 三层令牌（原始值 → 语义 → 组件）。颜色、间距 `--sp-*`、圆角 `--r-*`、字号 `--fs-*`、时长 `--dur-*`、缓动 `--ease-*`。
- `src/styles/base.css` —— 工具与组件类（`.card` / `.tiles` / `.rail` / `.split` / `.focal` / `.quiet` / `.stagger` …）。

### 三条皮肤轴（**只许三条，动效轴已删**）

| 轴 | 属性 | 档位 |
| --- | --- | --- |
| 主题 | `data-theme` | 浅色 / 深色 / 跟随系统 |
| 主色 | `data-accent` | 河大蓝 / 河大红 |
| 风格 | `data-style` | 极简 / 柔和 / 紧凑 |

- **"动效"轴已于 2026-10-11 删除**：它与 `prefers-reduced-motion` 重复、用户看不出差别，而且
  `data-motion="calm"` 会把门户**整页绘制成纯白**（Chrome 绘制缺陷）。减少动效从此只有一个来源：系统的 `prefers-reduced-motion`。
- **风格轴是改造过的**：原来只改 `--card-pad`，与默认档**平均只差 2.3–3.0 灰阶**（看不出）。
  现在把 `--sp-3..--sp-7`、行高、圆角与卡片内距一起算进密度（**字号不参与**：
  缩字号是拿可读性换密度，还会造出"12 与 13 只差 1px"）。复测差异 **8.3 灰阶 / 12.4% 像素**。
  **不要把它改回只改一个值。**

### 文案三档语气（**改文案前先认领档位**）

| 档 | 范围 | 口径 |
| --- | --- | --- |
| 一 · 说人话 | 操作引导 `GUIDES`、空态 `EMPTY_COPY`、按钮与状态标签 | 亲切短句。**不要**改成正式 |
| 二 · 正式 | 平台自述、数据与隐私、故障降级 `FALLBACK_COPY`、演示声明、费用责任 | 中性精确；不用"好像/随便/接着来"，**也不出现工程词** |
| 三 · 随意 | 代码注释、规范页 `#/spec` | 不必收敛 |

### 五条门禁（改完必须全绿）
```
cd zhiyin-src/template/zhiyin-web
npm run build                     # vue-tsc + vite，零错误
node scripts/check-contrast.mjs   # 4 套皮肤组合 ≥4.5:1 + 令牌用途登记表 + 字号档登记 + 硬编码 font-size 拦截
node scripts/check-classes.mjs    # 类名撞车：全局样式表的类名不许被组件在 scoped 里重复定义
node scripts/shots.mjs            # 26 张回归截图 → public/shots/（**已带 reduced-motion**，别删那个开关）
```

> **`check-classes.mjs` 是 2026-10-12 新加的**，因为同一类事故已经发生**两次**：
> `CollectRail` 的 `.rail` 撞上全局 `.rail`（右栏被压成 0 宽，客户报的"要左右滑动"）、
> `PlanView` 的 `.ledger` 撞上我新加的全局 `.ledger`。
> 机制：scoped 的 `.x[data-v-*]` 只赢下**它自己声明过**的属性，全局那几条
> （`display` / `grid-template-columns` / `max-width` / `gap`…）照样漏进去。
> **这类事故不会报错、不会白屏，只会"看起来不太对"——所以必须由机器盯着。**

```powershell
  --no-sandbox --hide-scrollbars --force-prefers-reduced-motion --window-size=1600,1100 `
  --virtual-time-budget=6000 --screenshot=<输出.png> "http://127.0.0.1:5273/#/review?as=mid&theme=dark"
```

**踩过的坑（照做能省时间）**
- **截图是异步落盘的**：`Test-Path` 立刻判断会误报失败，要轮询等待（250ms × 40 次）。
- **`--virtual-time-budget` 会冻住 CSS 入场动画**：只带它拍图，`.stagger` 的最后一个条目可能是**全透明**的，
  而且**每次冻的位置还不一样**。必须同时带 `--force-prefers-reduced-motion`（本轮的真实缺陷，见 §4/README）。
- **判"点了有没有反应"必须等一拍**：Vue 的 DOM 更新是异步的，在同一个同步求值里"点完立刻量"会**全部误报**。
- **`.ps1` 文件会被执行策略拦住**（`未对文件进行数字签名`）：把脚本内容内联进命令跑，或 `Invoke-Expression`。
- **管道捕获 stdout 在沙箱里不可靠**（`--dump-dom` 之类）；要拿 DOM 就 `-RedirectStandardOutput <文件>`。
- **`localhost` 与 `127.0.0.1` 都可**，`[::1]` 不通。`strictPort: true` 是为了防止端口悄悄漂移导致"有时打得开有时打不开"。
- **不要把 `Select-String` 的模式嵌在双引号的 `$(...)` 里**：嵌套引号会被 PowerShell 吃掉，统计恒为 0。
  我用这个方法误报过"0/5 页已改造"。**凡是用计数判断状态，先拿一个已知为真的样本验一次。**

## 9. 一份负面清单（我犯过的错，别再犯）

| 错误 | 教训 |
| --- | --- |
| 用 `Set-Content` 覆盖源文件 → 文件被截成 3 字节 | 只用 `edit`/`write` 或"临时文件 + Move-Item"，写后必核 |
| 不读原文就改 → 本该**删除**的块又被**插入**一份（`copy.ts` 的 TRUST 重复） | 删除类编辑前**先 read 目标区域**，不要凭记忆拼 old_string |
| 自创的度量指标没验证就用它汇报（"rail 0/5"） | 计数/模式类判据，先用已知为真的样本验一次 |
| **点击尺子没等 Vue 更新** → 24 条索引全部误报"点了没反应" | 量交互必须等一拍；先用一个**已知会变**的页面（plan/review）验尺子 |
| **顺序判据拿去判"多条索引指向同一块"** → 误报 report/profile 顺序相反 | 判据有适用范围，写下来；报数前先问"这条判据在这里成立吗" |
| **以为 `--virtual-time-budget` 拍到的是稳定态** | 它会冻住动画时钟；截图要显式关掉入场动画，并**连拍两遍比对**才能说"可复现" |
| 给对话页头部加了 24px 边距，忘了上方进度条还是按 760px 对齐 | 改一处对齐要**同时检查它在页面里的邻居** |
| 采信评审结论没复核（"第三张卡造成 614px 空行"实为误报，照改反而会造出空行） | **评审也要验**：这条我用像素量过才没改错 |
| 只截图不量化，把"看着还行"当验收 | 把验收变成**可判定**的判据（像素差、间隙序列、顺序一致性、点击后签名变化） |
| 以为 subagent 能中途收窄 | subagent 不可寻址；要能干预就用 `spawn_teammate` |
| **新加了一个全局类名，撞上了同名的旧组件**（方案 B 的 `.rail` vs 对话页右栏的 `.rail`） | 右栏被套上 `display:grid + 248px 首列`，15 段进度条与一段说明被压成 **0 宽**。**scoped 样式只覆盖它自己声明过的属性，没声明的照样从全局泄漏进来。** 新加/改名类名之前先 grep 一遍；`.tmp-research/lead-overflow.mjs` 现在守着它 |
| **拿"和基线逐像素一致（0.00%）"当"没碰过"的证据** | 那句话是错的：对话页右栏当时已经坏了，正是它盖住了真回归。**先确认基线自己是对的、截图参数也没变**，再去比 |
