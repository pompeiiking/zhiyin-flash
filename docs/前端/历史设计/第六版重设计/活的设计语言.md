# 「活」的设计语言（v6）

记录时间：2026-10-14。来源：与需求方的对话结论。
**本文件是 v6 全站重构的判定依据**——每一页做完都要拿第 6 节的清单过一遍。

> 标注约定：**【需求方原话】** 是对方明确说的；**【推导】** 是设计方从原话推出并负责的结论。
> 这个区分是硬要求：v5 的失败之一就是把对方随手举的例子当成了需求清单。

---

## 0. 一句话

**【推导】"活"不是"动得多"，是界面里存在只有"看一段时间"才能获得的信息。**

---

## 1. 判定标准：截屏测试

**【推导】可操作的自查方法：**

> 截一张静止图。如果信息一点没丢，这个界面就是**死的**。
> 活的界面，静图一定会丢东西——因为它此刻正在生成、正在思考、正在交接、正在推进。

这条测试的价值在于：它把"感觉"变成了可判定的东西，也直接否掉了"加过渡动画"这条路——
淡入、位移、数字滚动**全都不影响截屏结果**，所以全都不是"活"。

## 2. 静态界面的本质：只有一个时态

**【推导】** 静态界面只有**现在时**：渲染完成那一刻，所有状态都已确定，之后再不变。
活的界面有三种时态：

| 时态 | 例子 |
|---|---|
| 进行时 | 正在生成、正在思考、正在等待、正在推进 |
| 完成时 | 刚刚发生了什么（新消息落下、任务刚被勾掉、进度刚推进一格） |
| 将来时 | 接下来会怎样（下一步解锁什么、还剩多少） |

**中间状态可见，就活了一半；只给最终态，就是死的。**

## 3. 两类页面，两种活

**【需求方原话】** "对话界面本来就有活的感觉，容易设计，别的界面的话，我感觉更像是呈现信息上的活感。"

**【推导】** 这句话点出了关键结构差异：

- **对话页**天生有**一个主体**（顾问）和**一条时间线**（你一句我一句）→ 只要让主体显得在动就活了。
  → **对话页的活 = 过程可见。**
- **画像、报告、方向、计划、日历、资讯**是**静态名词的陈列**：没有主体、没有时间线。
  照对话页那套做（流式、头像、气泡）根本不成立。
  → **数据页的活 = 组织可见。**

**统一的底层：让"我为什么该这么理解"变得可见、可碰、可一层层打开。**

## 4. 核心难题：信息不动的时候怎么活

**【需求方原话】** "如果没有信息的变化呢，已经有的信息该如何更好的呈现？"

这是**大多数时候的真实情况**——数据本来就不动，它只是"已经在那了"。

**【推导】答案：数据是死的，但"看"的过程可以是活的。**
静态页面替用户决定了三件事：**看什么、按什么顺序看、看到多细**。
活的页面把组织权交还给用户，并且每次还他一个**重新组织过的形态**。
**数据不动，组织方式在动——这本身就是活。**

### 4.1 让结构显形，而不是让内容排队
呈现**关系、层级、因果**：这条结论靠哪几条证据、这个差距连到哪条任务、这个字段影响了哪个判断。
用户看到的不是一个列表，是**信息的形状**。

### 4.2 把组织权交给用户（多视角 + 重组）
同一批信息：按来源看 / 按时间看 / 按主题看 / 按对结论的贡献看。
关键在**切换时信息是重新组织**（聚拢、重排、分组、连线），而不是"换个列表内容"。
**这里才是动效该用的地方**——让用户看见同一批东西被重新组织了。

### 4.3 粒度与溯源（连续缩放 + 厚度）
- 摘要 ↔ 细节 ↔ 原文是**连续缩放**，不是一个折叠框。
- 每条信息剥开能看到来历：哪次对话、什么时候、谁给的。
- **溯源链就是给静态信息补上时间的厚度**：它不动，但你知道它是怎么来的。

### 4.4 状态与不确定性显形（这份认识有多结实）
哪些已核实、哪些来自对话、哪些还是推断、哪些过期要重算、哪些彼此冲突。
后端契约里已有 `source` / `confidence` / `gaps` / `needs_recompute` / `coverage`，
但前端现在**一律印成灰色小字**。
**【推导】活感来自：信息之间是有品质差异的，不是一律等重。**

### 4.5 景深：先解决"平"
**【需求方原话】** "最好不要是直接把大量文字信息罗列出来。"

**【推导】** "文字罗列"的根因不是字多，是**平**：所有信息等距、等权、同形，视线没有落点。
所以景深不是装饰，是**让人读得下去**：主信息立在前，支撑退到后，
用户一眼知道该看什么，再决定要不要往里走。

## 5. 什么不是"活"（反例表）

| 做法 | 为什么不是 |
|---|---|
| 页面淡入 + 位移 5px | 界面还是那张画，只换了进场方式——**装饰** |
| 数字滚动、指示线滑动 | 好看，但不传达信息——**装饰** |
| 持续背景运动、粒子、发光边框 | 与内容无关——**这是吵，不是活** |
| 一进页面把所有动画播一遍 | 表演；播完就死了 |
| 数据页加图表 + 图表生长 | **如果信息之间的关系没有变，仍是装饰** |
| 多视角做成 tab 换个列表 | 只换了内容，没有重组 |
| 溯源做成一个折叠的"来源" | 要用户自己点开才知道，信息还是平面的 |
| 状态做成灰色小字 | 品质差异没被看见 |

**一句话：v5 把动效当装饰，v6 把动效当信息。动的每一处都要回答"这里发生了什么"。**

## 6. 判定清单（每页做完自查）

对任一页面逐条问：

1. 截屏测试：静图会丢信息吗？丢了什么？
2. 有没有**进行时**（正在发生的事可见）？
3. 变化是否**可被感知**（新消息、状态迁移、关系变化有落点）？
4. 用户能否**上手操作**，并看到**即时且连锁**的反馈？
5. 信息之间的**关系**是否可见（而不只是并列）？
6. **组织方式**能否被用户改变（视角、粒度、顺序）？
7. **状态与不确定性**是否被看见（而不是一律灰字）？
8. 每一处动效，能否回答"**这里发生了什么**"？答不上来的删掉。
9. `prefers-reduced-motion` 下是否有可用的静态形态？
10. 桌面与手机是否都成立？

## 7. 边界与纪律

1. **需求方给的例子不是要求。**
   **【需求方原话】** "我这只是一种感觉，你也可以理解为示例，但是不用完全按照我这个例子做。"
   **【需求方原话】** "别的界面我也没有说明，因为我不知道如何设计，需要你来设计。"
   → 对话页的"机器人头像 / 卡片切换"等只作**感觉参照**；其余页面由设计方出方案。
2. **动效必须承载意义**（状态、关系、空间、因果），禁止装饰堆砌。
3. **禁止**：无意义持续背景运动、粒子、发光边框、自动轮播。
4. **`prefers-reduced-motion` 必须降级**到可用形态，不是"关掉就白屏"。
5. **不许用"加动画"交差。** 若一页做完只能靠"动效更丰富"来证明变化，这页就没做完。
6. 允许引入动效库；已选 **`motion-v` 2.7.0**（官方 Vue 版，MIT，活跃维护）。

## 8. 落到「职引」的方向（设计方提案，待逐页确认）

产品本质：**陪一个学生走过一段过程**——顾问在了解他、判断方向、排计划、陪推进、回头复盘。
所以界面该像**"有人正在为你工作"**，而不是"一份报告摆在那里"。

| 页面 | 现在的病灶 | v6 方向 |
|---|---|---|
| 对话 `/chat` | 单列文字流；交接要点击展开；顾问只是个名字 | 顾问是**在场的人**（有形象、有状态：在听/在想/在说/交接）；交接是**默认展开的说明卡**；输出流式；回答由多种块组成 |
| 画像 `/profile` | 一串字段 + 灰色小字 | **「我知道什么 → 所以判断了什么 → 还缺什么」**的可追溯结构；来源/可信度/待补充有**存在感**；可多视角重组 |
| 报告 `/report` | 长文 + 五层折叠 | 点结论 → 它依赖的证据亮起来 → 一路追到原始来源；自身/要求/差距**同刻度**；版本差异可见 |
| 方向 `/directions` | 三张静态卡争抢注意 | 比较项对齐；**改权重即时重排**（"我更看重稳定"→ 排序与差距实时变） |
| 计划/今日 `/plan` `/home` | 任务表；取数按钮占首位 | 计划是一条**在推进的线**；勾掉一件 → 进度推进、下一件浮出、剩余重算 |
| 日历 `/schedule` | 静态月格 + 被挤窄的课表 | 课程/截止/任务在**同一时间轴**互相影响（课多的一周任务自动排少） |
| 复盘 `/review` | 时间线 + 长说明 | 证据**在积累**的过程可见；完成记录由真实行为推导 |
| 资讯 `/intel` | 整段正文罗列 | 事实与个人匹配分层；来源、时间、类别成为结构而不是灰字 |

## 附：本文件的来历（防退化）

v5 的问题是**设计表达没有落到产品页面**：展示稿好看，页面还是静态文档。

所以本文件的作用是：**把"感觉"变成清单，把清单变成每页的验收项。**
