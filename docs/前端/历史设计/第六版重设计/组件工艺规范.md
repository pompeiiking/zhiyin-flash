## 2. 对话页五个核心组件的工艺规范

### 2.0 先定三条共用底座（五组件都靠它，否则单改一个组件不成立）

**A. 工作表面（work surface）**——现在整页 `--c-bg` 从头铺到尾，没有任何一层"纸"。改法是把对话流装进一张纸：

```css
/* 对话流 = 工作面。页面底仍是 --c-bg，纸面抬到 --c-surface */
.ws-chat-flow {
  background: var(--c-surface);
  border: var(--bw-1) solid var(--c-border);
  border-radius: var(--r-lg);
  box-shadow: var(--e-1);
}
```

> ⚠️ **冲突标注**：`--card-shadow` 默认是 `none`，`tokens.css` 注释写明"默认不用投影分层，靠 1px 发丝线"。这里只给**一张**纸面加 `--e-1`，不给每张卡都加——即"纸面有影、卡在纸上无影"，见 3.2 判据。

**B. 强调色配额**——现在满屏是蓝的近似值（浅蓝底、蓝边框、蓝图标、蓝文字四处同时出现）。配额见 3.4。

**C. 内距与行宽**——阅读列 `max-width: 700px`（现在 800px 偏宽，中文长行读起来累），卡片内距 `--sp-4`（16px），块间距 `--sp-4`。

### 2.1 顾问消息与气泡

**现状病灶**：`.chat-bubble--me` 是 `--c-primary-weak` 平涂、无描边无影；顾问消息干脆没有容器，`.chat-turn__body` 里直接堆块。整条消息读完的观感是"白底上一段字"。

**结构分层（三层，从上到下）**

| 层 | 内容 | 形态 |
|---|---|---|
| L0 身份行 | `.chat-who`：头像 + 名字 + 职责 | 12/14px 灰，**只在组首出现**（现有 `isGroupStart` 逻辑正确，保留） |
| L1 主张 | `.chat-block--lead` 结论块 | 见 2.2 |
| L2 支撑 | `.chat-cards` 支撑卡组 | 纸中纸：`--c-surface-2` 底 + 发丝线 |
| L3 学生气泡 | `.chat-bubble--me` | 现在唯一的"气泡"，改进后见下 |

**尺寸与间距**

| 项 | 值 | 令牌 |
|---|---|---|
| 头像列宽 | 40px（窄屏 34px） | 现有值，保留 |
| 头像与正文间距 | 12px | `--sp-3` |
| 一轮发言的下边距 | 26px | 现有值，保留 |
| 气泡内距（学生） | 12px 16px | `--sp-3` / `--sp-4` |
| 气泡最大宽 | 76%（窄屏 88%） | 现有值，保留 |
| 正文行距 | 1.7 | `--lh-normal` |

**字号字重行距**：学生气泡 `--fs-16` / `--fw-regular` / `--lh-normal`；顾问正文同上；身份行名字 `--fs-14` / `--fw-semibold`，职责 `--fs-12` / `--c-text-3`。

**颜色**：学生气泡底 `--c-primary-weak`，文字 `--c-text`（**不是白字**——白字在 `#eef5fc` 上过不了对比）；顾问侧一律不铺底，靠纸面。

**边框/圆角/阴影**

- 学生气泡：`border: 1px solid var(--c-primary-border)` + 圆角 `var(--r-lg) var(--r-lg) var(--r-sm) var(--r-lg)`（现有值，那处小圆角是"尾巴"，保留，它是全站少数有语义的不对称圆角）。
- 顾问消息：**不加卡片**。加卡片会把"一个人说话"变成"一堆盒子"，与 DESIGN-LANGUAGE §8 的"顾问是在场的人"相反。

**状态差异**

| 状态 | 表现 | 令牌 |
|---|---|---|
| 默认 | 如上 | — |
| 悬停 | 不改变消息形态；只让消息工具条（复制）由 `--c-text-4` 升到 `--c-text-2` | `--dur-1` |
| 聚焦 | 消息工具条按钮 `:focus-visible` 用全站唯一焦点环 | `outline: var(--bw-2) solid var(--c-focus)` |
| 流式中 | 句尾光标 `.chat-caret`（现有，保留）；头像切 `speaking` | 现有 |
| 已停止 | 整段立即落位（现有 `liveText` 逻辑正确，保留） | — |
| 禁用 | 复制按钮在 `isLive` 时为 disabled，`opacity: var(--btn-... )` → 用现有 `.btn:disabled` 的 0.45 | 现有 |

**最小可复制 CSS**

```css
/* 学生气泡：从"平涂"改成"平涂 + 发丝线 + 微内影"，靠 1px 与 1 层内影做出厚度 */
.chat-bubble--me {
  padding: var(--sp-3) var(--sp-4);
  border: var(--bw-1) solid var(--c-primary-border);
  border-radius: var(--r-lg) var(--r-lg) var(--r-sm) var(--r-lg);
  background: var(--c-primary-weak);
  color: var(--c-text);
  box-shadow: inset 0 1px 0 rgba(255, 255, 255, 0.6); /* 顶上那 1px 高光 = 凸起 */
  max-width: 76%;
  width: fit-content;
}
/* 顾问正文：只给"可读的宽度与节奏"，不给盒子 */
.chat-turn--host .chat-turn__body { max-width: 66ch; }
.chat-turn--host .readable-text p + p { margin-top: var(--sp-3); }
```

**为什么比现在好看**：`--c-primary-weak`(#eef5fc) 与纸面 `--c-surface`(#fff) 的明度差只有约 3%，平涂时气泡几乎是"看不见的形状"；补一条 `--c-primary-border`(#b8d5f2) 发丝线和一条 1px 内高光之后，气泡靠**边缘**被识别，而不是靠面积——这正是不增加饱和度的前提下的分层做法（Refactoring UI 的"用边界而非填充"）。

### 2.2 结论块

**现状病灶**：`.chat-block--lead` 就是一句 `--fs-20 / 600` 的黑字，前面没有语义标签、后面没有收束线，用户不知道"这是一条判断"。它孤立在正文里，反而比正文更弱。

**结构分层**

```
<section class="chat-block chat-block--lead">
  <p class="chat-block__eyebrow">结论</p>        ← 新增：语义标签（12px/加字距）
  <ReadableText />                                 ← 主张（20px/600）
</section>
```

**尺寸与间距**：内距 `0`（它靠标签与下边距立起来，不靠盒子）；`padding-bottom: var(--sp-3)`；与支撑块间距 `var(--sp-4)`。

**字号字重行距**：标签 `--fs-12` / `--fw-medium` / 字距 `0.06em` / `--c-text-3`；主张 `--fs-20` / `--fw-semibold` / `line-height: var(--lh-snug)`(1.45) / `letter-spacing: -0.01em`（**中文可查觉的最大负字距**，不要更负）。

**颜色**：主张 `--c-text`；标签 `--c-text-3`。**结论块本身不上蓝色**——见 3.4 配额。

**边框/圆角/阴影**：无边框、无圆角、无阴影。只加一条"收束线"（下边缘 1px）把它与支撑材料切开。

**状态差异**

| 状态 | 表现 |
|---|---|
| 流式中 | 逐字出现 + `.chat-caret`；标签先于文字出现（标签是结构，不是内容） |
| 已停止 | 整段落位 |
| 缺结构 | 现有 `leadOf()` 取不到句子时整段落在结论块里——**保留**，不要因此取消结论块（取消等于把层级交回给段落） |

**最小可复制 CSS**

```css
.chat-block--lead {
  display: flex; flex-direction: column; gap: var(--sp-2);
  padding-bottom: var(--sp-3);
  border-bottom: var(--bw-1) solid var(--c-border);
  font-size: var(--fs-20); line-height: var(--lh-snug);
  font-weight: var(--fw-semibold); letter-spacing: -0.01em; color: var(--c-text);
}
.chat-block--lead .chat-block__eyebrow {
  font-size: var(--fs-12); font-weight: var(--fw-medium);
  letter-spacing: 0.06em; color: var(--c-text-3);
}
```

## 3. 让"平"变"有层次"的具体手段

DESIGN-LANGUAGE §4.5 已经定性："文字罗列的根因不是字多，是平——所有信息等距、等权、同形。"
下面是把它变成数字的部分。

### 3.1 表面分层：三层固定，不得新增

| 层 | 令牌 | 色值（浅色） | 谁住在这一层 | 允许的手段 |
|---|---|---|---|---|
| L0 页面底 | `--c-bg` | #f7f6f6 | 页头、页脚、对话流之外的留白 | 无边框、无阴影 |
| L1 工作面 | `--c-surface` | #ffffff | 对话流纸面、卡片正面 | `--bw-1` 发丝线 + `--r-lg`；仅纸面可带 `--e-1` |
| L2 局部关注区 | `--c-surface-2` | #fafafa | 卡中卡（支撑卡）、composer 凹槽、chip、代码/引用块 | `--bw-1` 发丝线；凹槽可带 `--e-2` |

**为什么只需要三层**：现有令牌只有 `surface / surface-2 / surface-3`。用到第四层就必然出现"明明是同一种重要性的东西却深浅不一"——这正是"同形"的问题反过来。`--c-surface-3` 只用于**交互态**（hover 底、骨架块），不用于静态分层。

**浅色与深色都要成立**：深色下这层关系是**反的**（`--c-bg` #151517 < `--c-surface` #1b1b1d < `--c-surface-2` #232324，越靠前越亮），所以分层必须写 `background: var(--c-surface)` 而**不能写死 `#fff`**。深色下的边框已经由令牌加强（#313133/#444446），不要另加。

### 3.2 何时用阴影、何时只用描边（判据，不是"看情况"）

给三条可机械执行的规则：

**规则 1 —— 元素是否"离开纸面"？**
判据：它有没有**独立于页面流的边**（浮层、吸底条、粘性条）。
→ 是（`--z-drawer` / `--z-modal` / `--z-sticky` / 吸底 composer / 行动卡）用 `--e-2` 或 `--e-3`。
→ 否（消息、结论、说明、依据列表、表格行）**只用 `--bw-1` 发丝线**。

**规则 2 —— 有没有第二种手段可以表达同一个关系？**
判据：颜色差、内距差、字号差、左线**只要有一个已经说清楚**，就不要再加阴影。
例：`.chat-block--detail` 已经用"左线 2px + 小一号字 + 缩进 14px"三重手段表达"这是展开说明"，再加阴影就是冗余。

**规则 3 —— 同一屏内最多两个抬升面。**
对话页的配额是：**行动卡（`--e-2`）** 与 **composer（`--e-2`）**。`--e-3` 保留给真正的浮层（sheet、popover），对话流内**永远不用 `--e-3`**。

> 一句话：**静态内容用线，浮动与可操作内容用影。** 现在的问题不是"影太少"，而是"该有影的两处（行动卡、composer）只有 1px 线，不该有影的地方（每张卡）偶尔冒出一个 `--e-1`"。

### 3.3 卡片内外的间距节奏（一组数字，直接用）

| 位置 | 值 | 令牌 |
|---|---|---|
| 卡片内距（普通） | 16px | `--sp-4` |
| 卡片内距（行动卡 / 重点卡） | 20px | `--sp-5` |
| 卡头 ↔ 卡体 | 12px | `--sp-3` |
| 卡体 ↔ 卡脚 | 16px | `--sp-4` |
| 同级卡片之间 | 12px | `--sp-3` |
| 回答内的块之间（结论↔支撑↔说明↔行动） | 16px | `--sp-4` |
| 一轮发言（turn）之间 | 26px | 现有值 |
| 组内连续消息（同一个人）之间 | 10px | 现有 `.chat-turn__body gap` |
| 纸面内边距（上下） | 16 / 28px | `--sp-4` / 现有 |
| 阅读列宽 | 700px（旧 800px） | — |

**节奏规则**：`轮间(26) > 块间(16) > 卡间(12) > 卡内段间(12) > 行间(8)`。这个严格递减是"读得下去"的物理基础——现在 `.chat-answer` 的 gap 是 14px，与块内距 16px 几乎相等，所以块与块、段与段读起来是一个密度。

### 3.4 强调色出现在哪、占多少

**配额（按对话页可见像素粗略计）**：

| 用途 | 颜色 | 预算 |
|---|---|---|
| 实心主色（按钮底、当前步） | `--c-primary` | **≤ 1.5%** |
| 浅主色（气泡底、选中底、chip） | `--c-primary-weak` / `-weak-2` | ≤ 6% |
| 主色线（聚焦环、选中边） | `--c-primary-border` / `--c-primary` 1–2px | ≤ 1% |
| 主色文字/图标 | `--c-primary` | ≤ 2% |

合计 **≤ 10%**，其余 90% 是灰与白。现状估算超过 25%（每个块都有蓝边、蓝图标、蓝字）。

**允许出现主色的位置（白名单，共 6 处）**
1. 页面里唯一的实心主按钮（行动卡的「加入行动计划」、composer 的「发送」）——**一屏最多两个**。
2. 学生气泡的底与边。
3. 卡组当前选中项的底 + 圆点指示器。
4. 键盘焦点环。
5. 流式光标 `.chat-caret`。
6. 数据卡里"当前值"那一根条。

**禁止**（现状正在发生）
- 卡片边框用蓝（`.dialogue-action` 的 `--c-primary-border`）→ 改 `--c-border`。
- 卡头文字/图标用蓝（`.dialogue-action__head` 的 `--c-primary`）→ 改 `--c-text-2`。
- 占位符/提示行用蓝 → 保持 `--c-text-3`。
- 分隔线用蓝 → 保持 `--c-border`。

**注意色（红）配额 ≤ 1%**：只在 `.chat-error`、`演示数据` 徽章、门槛差距标注出现。**红色不参与任何 hover/focus**。

## 4. 字体与数字排印

### 4.1 中文正文与标题的配方（严格用现有 6 档，不新增）

| 角色 | 字号 | 字重 | 行距 | 字距 | 颜色 | 备注 |
|---|---|---|---|---|---|---|
| 门户主张 | `--fs-38` | `--fw-semibold` | `--lh-tight` | `-0.02em` | `--c-text` | 大字号才允许 -0.02em |
| 页标题 | `--fs-30` | `--fw-semibold` | `--lh-tight` | `-0.01em` | `--c-text` | |
| 节标题 / 结论 / 行动标题 | `--fs-20` | `--fw-semibold` | `--lh-snug`(1.45) | `-0.01em` | `--c-text` | 中文负字距下限 |
| 正文 / 对话 | `--fs-16` | `--fw-regular` | `--lh-normal`(1.7) | **0** | `--c-text` | 中文正文行距不可低于 1.6 |
| 次要信息 / 控件 | `--fs-14` | `--fw-regular`/`medium` | `--lh-snug`(1.45) | 0 | `--c-text-2` | |
| 来源 / 时间 / 注解 | `--fs-12` | `--fw-regular` | `--lh-snug` | 0；**标签用 +0.06em** | `--c-text-3` | 12px 是最小档，不再往下 |

**三条硬规则**
1. **中文不加正字距**（唯一例外：12px 全大写式短标签，如「结论」「支撑材料」，此时 `letter-spacing: 0.06em` 用它当"小标题仪式感"）。
2. **负字距只给 ≥20px 的字号**，且不超过 `-0.02em`。中文的满框字在负字距超过 0.02em 时会出现部件粘连。
3. **行距与字号反相关**：38px 用 1.25，20px 用 1.45，16px 用 1.7，12/14px 用 1.45–1.7。现在 `.chat-turn` 用 `line-height: 1.85`（字面量）在 16px 上偏松，收到 `--lh-normal`(1.7)。

### 4.2 数字（分值、进度、日期）怎么排才显专业

**四条参数**

```css
/* 1. 所有会互相比较的数字：等宽数字 */
.chat-bars__value, .chat-bars__grid i, .chat-cards__pos,
.ws-chat-head__demo, .dialogue-action__head > span {
  font-variant-numeric: tabular-nums;
}
/* 2. 分数/比值：统一右对齐 + 单位降一档 + 单位不参与对齐 */
.chat-bars__value { text-align: right; font-weight: var(--fw-semibold); }
.chat-bars__value small { font-size: var(--fs-12); font-weight: var(--fw-regular); color: var(--c-text-3); }
/* 3. 日期：不写 2026/10/14，写 2026-10-14（等宽下字符数一致，列表不抖） */
/* 4. 千分位与小数位：同一列位数必须一致（46 与 50 不要写成 46 与 50.0；要统一） */
```

**四条规则**
1. **凡是有"多行数字要对齐"的地方，一律 `tabular-nums`**。现在只有部分位置加了，`.chat-bars__value` 加对了，但它旁边的 `small` 单位没加——数字本身对齐了，单位却会抖。
2. **单位降一档并变轻**（`--fs-12` / 400 / `--c-text-3`），让"数"是主角、"分"是注解。
3. **分数不要用 `--fs-30`/`--fs-38`**：大字号只给观点，不给读数（大数字会把"这是一个示例值"变成"这是一个结论"）。
4. **稀疏数字（页码 1/3、条数）用 `tabular-nums` + `--fw-semibold` 的当前项**——`.chat-cards__pos strong` 现有做法正确，保留。

### 4.3 要不要换字体？——**不换**

| 候选 | 许可 | 体积（实测） | 判断 |
|---|---|---|---|
| **系统栈（现状）** | — | **0 KB** | ✅ **保持** |
| MiSans 可变字体（小米） | `misans@5.0.0` 的 `package.json` 写 `Apache-2.0`，可商用可自托管 | 包内 **56 个 `MiSansVF` 子集 woff2，合计 4.3 MB**（整包 51.28 MB / 1569 文件，含阿拉伯、天城文等本项目不需要的脚本） | ⚠️ 中文常用字全覆盖要加载多个子集，**首屏成本以 MB 计**；收益是"跨平台字形一致" |
| Inter / General Sans 等西文 | Inter 为 OFL；Fontshare 为自有 ITF 许可 | 拉丁子集约 100 KB 级 | ❌ 数字与西文在系统栈下已经够好（`-apple-system`/`Segoe UI` 的数字形态都不差），为几个数字加载一套西文字体不划算 |
| Departure Mono / 站酷快乐体等 | 各异 | — | ❌ 与"克制、可读"冲突（`tokens.css` 已明确移除手写体） |

**结论**：**继续用 `--font-sans` 系统栈**。理由三条：(1) 中文 web 字体的子集化交付在本项目当前构建里没有做（无子集配置），直接引 MiSans 是 MB 级成本；(2) 系统栈在 macOS/Windows/Android 上都有合格的中文字形（PingFang SC / 微软雅黑 / Noto Sans CJK）；(3) 现在的"丑"来自排印参数（行距 1.85、字体极差、无 tabular-nums），不来自字形。
**若将来一定要换**：走 [Fontsource](https://fontsource.org/) 自托管 + 子集化，只用 `Normal` 一个字重档的**少数几个子集**，并附 `font-display: swap`；这是独立议题，不在本次施工范围。

### 5.1 采用（12 条）

| # | 微交互 | 传达了什么信息 | 时长 | 缓动 | 落点 |
|---|---|---|---|---|---|
| 1 | 块顺序落位（结论→支撑→说明→行动） | "这条回答正在一块块长出来" | 260ms，步进 70ms | `--ease-out` | `.chat-block`（`--block-step`，现有） |

| 7 | 条形从 3% 长到目标宽 | "这个判断刚被算出来" | 420ms，`--block-step`×60ms+80ms | `--ease-out` | `.chat-bars__fill`（现有） |

| 11 | 行动卡 hover 抬升 1px + 阴影升一档 | "这张卡可以被点"（仅真指针设备） | 180ms | `--ease-out` | `.dialogue-action:hover`（新增） |

### 5.2 明确排除（项目已有禁令 + 本次新增）

| 排除项 | 理由 |
|---|---|
| 持续背景运动、粒子、发光边框 | DESIGN-LANGUAGE §5 已有禁令；与内容无关 = 吵 |
| 自动轮播 | 同上；且夺取用户的阅读控制权 |
| 数字滚动 / 翻滚数字（NumberFlow、Rolling Number） | §5 判为装饰：静图不丢信息 |
| 页面淡入 + 位移 5px（作为"活"的证据） | §5 判为装饰 |
| 一进页面把所有动画播一遍 | §5 判为表演 |
| 图标 hover 动画（Lucide Animated / Heroicons Animated） | 图标本来已经能认出功能，动画不传达新信息 |
| 加载指示器的花样（Gradient Spin / Dot Matrix / Painterly / 25 种 loader buttons） | 加载只需要"在转"这一条信息 |
| 音效（soundcn / cuelume / @web-kits/audio） | 产品是安静工具；音效无法静音降级 |
| 弹簧/回弹（Easing Wizard 生成的 spring） | 本产品的语气是"一个人稳稳地陪你"，回弹与之冲突 |
| 共享元素过渡（layout 动画库） | 需要引入 `motion-v` 之外的复杂度；当前 CSS 足够 |

**`prefers-reduced-motion` 必须逐条降级**（不是全局压到 0.01ms）：现有 `dialogue.css` 第 420–441 行已经逐条处理（骨架停成静态块、卡片切换靠指示器、条形不生长、按钮扩散隐藏）。新增的第 10、11 条要补进去：

```css
@media (prefers-reduced-motion: reduce) {
  .dialogue-page .ws-composer { transition: none; }
  .dialogue-action,
  .dialogue-action:hover { transition: none; transform: none; }
}
```

## 6. 不要做什么

### 6.1 不引入第二套 UI 框架皮肤（含 Tailwind 全家桶）

| 不采用 | 理由 |
|---|---|
| daisyUI / Flowbite / HyperUI / Preline / Tailwind UI / Float UI / Meraki UI / Tailwind 系 | 全部要求 Tailwind；项目是"Reka UI 原语 + 自写 CSS"，引入 Tailwind 等于同时换样式方案与构建链。需求方明确"不允许引入第二套 UI 框架皮肤" |
| shadcn/ui 的默认视觉（含 shadcn-vue、shadcnblocks、21st.dev、blocks.so） | **源码可读、可借结构**（已列入 1.7），但它的默认皮肤是 Tailwind + slate 灰 + 大圆角。项目令牌是河大蓝 + 灰，直接搬会撞车 |
| Magic UI / Aceternity / Cult UI / React Bits / Motion Primitives / Kibo UI / Skiper UI / Eldora / Kokonut / Vengeance / Lightswind | 全是 React 组件；本项目是 Vue 3。移植成本 > 收益，且多数带"发光/粒子/滚动特效"（见 6.2） |

### 6.2 不采用"用动效证明变化"的做法

见 5.2 表；根因见 DESIGN-LANGUAGE §5 末句："v5 把动效当装饰，v6 把动效当信息。"

### 6.3 不引入体积/依赖不划算的东西

| 不采用 | 体积/依赖 | 理由 |
|---|---|---|
| 中文字体包（MiSans 等） | 56 个 `MiSansVF` 子集 = **4.3 MB**（整包 51.28 MB） | 现在没有子集化配置，见 4.3 |
| 图表库（ECharts / Recharts / Tremor / Evil Charts / Dither Kit） | 数百 KB 起 | 现在只有 `bars_chart` 一种可视件，手绘 CSS 条形已经够；引库会顺带引入它的默认主题（见 6.1） |
| 日历库（FullCalendar / Schedule-X） | 见总调研报告 §5.2 版本表 | 属日程页议题，本次对话页不涉及 |
| `motion-v` 以外的动效库（GSAP / Rive / Lottie / Theatre.js / glimm） | Lottie 运行时 + JSON 素材 | 现有 CSS 动画已经覆盖第 5 节全部 12 条 |

### 6.4 需要账号 / 付费 / 无法离线复现，因此不能作为方案依据

Mobbin、Refero（付费素材库，历史记录里"未取得完整素材"）；[Lazyweb](https://www.lazyweb.com/)（上一轮公开问答无来源且 abstained）；**Stitch**（只读连接传输失败）；designmd 系生成器（designmd.me / designmd.supply / getdesign.md / Hyperbrowser / designmd），产出的是"另一份规范"而不是可施工参数。
上述都不能写成"已研究并采用"，只能写成候选。

### 6.5 中文不适配的做法

- **全部大写 + 大字距的西文小标题式**（`text-transform: uppercase` 对中文无效，强加字距会让中文散架）→ 中文标签改用 `--fs-12` + `0.06em` + `--c-text-3`。
- **超细字重（100/200）**做"高级感"：中文在系统栈下细体渲染发虚，笔画糊在一起。项目只用 400/500/600，**不新增 300 以下**。
- **`letter-spacing` 全局正值**：西文排版习惯，中文会变成"字距散"。负值只在 ≥20px 用（见 4.1）。
- **拉丁字体驱动中文行高**：西文行高常给 1.4，中文需要 ≥1.6。**不要让西文行高规则作用到中文正文**。

### 6.6 与现有令牌冲突的建议（须标注取舍）

| 建议 | 冲突点 | 取舍 |
|---|---|---|
| 给所有卡片加 `box-shadow` | `tokens.css` 注释："默认**不用投影**分层，靠 1px 发丝线"；`--card-shadow` 默认 `none` | **不采纳**。只给"离开纸面"的 2 处（行动卡、composer）用 `--e-2`，见 3.2 |
| 新增第 4 个字号档（如 18px）或第 5 个间距档 | `tokens.css` 明确"加一档字号就是在加一层层级"，`check-contrast.mjs` 的 `FONT_SIZE_USES` 要求每档登记用途、死档要删 | **不采纳**。全部用现有 6 档 + 6 个间距档解决 |
| 把圆角统一加大到 16–24px | `--r-lg` = 12px，注释写明"圆角取 OpenAI Codex 的口径：控件 6–8px、卡片 12px、浮层 16px" | **不采纳**。`html[data-style='soft']` 已经提供 12/18/24px 的柔和档，需要大圆角时切换到 soft，而不是改默认 |
| 给结论块上浅蓝底 | `--c-primary-weak` 已被学生气泡占用；同一个色块出现在两个不同语义上 = 语义混淆 | **不采纳**。结论块用"标签 + 收束线"，不上底色 |
| 用红色标注"不达标"的数据行 | 红色在本产品专用于"需要你注意"（`--c-attention`），且 `tokens.css` 硬口径："只有三支主色相，不再有第四、第五色相" | **不采纳**。差距靠"两根条的长度 + tabular 数值"表达 |
| 引入 Inter 等西文数字字体 | 现有 `--font-mono` 已有 `SF Mono / JetBrains Mono / Menlo / Consolas`；数字问题靠 `tabular-nums` 解决 | **不采纳**，见 4.3 |

## 7. 施工顺序建议（不要一次全改）

1. **2.0 三条底座**（纸面 + 配额 + 内距）——不做这步，后面每一步的收益都会被"整页平"吃掉。
2. **2.4 行动卡 + 2.5 composer**——两处抬升面，改完"平"的感觉立刻变，风险最低（纯视觉，无交互改动）。
3. **2.2 结论块 + 2.3 数据卡**——层级与精度，改完"文字罗列"感消失。
4. **2.1 顾问消息与气泡**——涉及结构（max-width、行距），最后做。
5. 全程用 [Mesurer](https://mesurer.dev/) 量真实像素校验，改完用 [Color.review](https://color.review/) 复核新增组合的对比度。
