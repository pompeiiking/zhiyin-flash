# 学生空间内容评估 · 2026-10-12

本轮以学生使用目标、后端能力及实际演示状态检查页面，保留门户与品牌配色。以下调整已实现；正式接口接入仍是后续工作。

| 页面 | 问题与判断 | 调整 |
| --- | --- | --- |
| 门户 | 入口必须明确，登录后不能先进入任务页 | 保留布局，入口与登录均进入咨询 |
| 咨询 | 核心任务明确，但历史与工具同时占用标题区，系统表达过于口语化 | 桌面历史移到侧栏，移动保留历史入口；顾问名称、系统回复与状态改为中性表达；切换会话清空独立草稿与附件 |
| 个人画像 | 来源与待补充项有价值；与学籍重复切换，空账号显示预置姓名不合理 | 学籍成为二级菜单中的独立页面，去掉重复页签；空账号不显示预置学生信息；本人更正与可信度保留 |
| 学籍与资料 | 导入、撤回与核验应集中；完整课程时间与记录数量不能混淆 | 独立页面；统计完整时间，缺失项待补充，等级成绩原样保留 |
| 诊断报告 | 应以结果与依据为中心，混入方向导航造成重复；历史版本不是另一份完整报告 | 页面只含诊断结果与版本记录；选旧版进入版本记录；诊断结果版本标示始终为第3版示例；打印当前视图 |
| 方向方案 | 与报告在导航已拆分，页面再次给报告页签不合理 | 移除报告导航与报告版本选择，只保留方案比较、选择与影响范围 |
| 行动计划 | 状态操作与阶段目标均有价值，但重复日历会造成维护分叉 | 今日/阶段是同一功能的视图；日历独立；状态与来源标签规范化 |
| 阶段计划 | 本周字样与实际全量当前任务不一致，日历重复 | 改为执行任务；仅保留里程碑、执行任务、来源三个视图 |
| 日历与课表 | 课程快照与关键节点合理，但空白不代表空闲，单节课容易遗漏 | 区间重叠显示课程、标明实际节次；保留时间约束与来源说明 |
| 待办与目标 | 个人内容应与方案任务分开，类别与操作清晰 | 两类内容、去重与完成/恢复保留；操作、说明、空态改为标准表达 |
| 岗位资讯 | 未实时获取时不能暗示招聘结论，来源比装饰更重要 | 保留空态、示例加载、来源与日期；模拟统计明确标为演示，真实供给待核验 |
| 复盘与记录 | 原因、建议与记录有价值，语言偏评价化 | 改为任务分析、调整建议与执行时间线；统一来源与归因显示标签，保留实际逻辑标识 |
| 应用工具 | 两个已发布模块入口合理，不应混入管理员管理功能 | 保留 action_progress 与 achievements 对应入口 |

导航采用二级结构：生涯分析、计划管理、资讯与记录。同一时间展开一个一级菜单；当前页面的一级菜单自动展开。历史会话放在菜单下方；桌面账号入口仅在左下角，移动端仅在右上角。

组件研究：采用 [Reka UI Accordion](https://www.reka-ui.com/docs/components/accordion) 的键盘导航与内容尺寸动效；[Motion for Vue](https://motion.dev/docs/vue) 作为动效能力参考，本轮未安装 Motion，已有 CSS 与 Vue TransitionGroup 满足当前需求。动效用于菜单展开、页面进入、任务位置与状态反馈，减少动效偏好下关闭。没有增加不相关的图片或装饰。

约束：报告分值、岗位统计、阶段百分比、历史时间线仍为示例；学籍与资讯没有真实外部调用。待重算、文件解析与 AI 生成不能仅凭前端显示冒充完成。对应接口与生成目录见 [BACKEND-ALIGNMENT.md](演示阶段接口对应.md)。
