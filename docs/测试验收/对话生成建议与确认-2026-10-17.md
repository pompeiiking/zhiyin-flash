# 对话中的报告与计划确认

日期：2026-10-17。使用隔离的虚构测试账号，未核验学信网，也未进行生产部署。

## 实现

- 资料达到采集门槛、没有现有报告且当前对话适合推进时，询问是否生成诊断报告；用户明确想继续聊时不催促生成。
- 讨论具体行动目标、没有现有计划时，询问是否创建行动计划。同一会话近期已提议过则暂不重复询问。
- 仅对当前会话最近一条服务端提问识别简短同意或拒绝；同意时支持附带具体约束，也保留直接明确要求生成的路径。其他会话、过期按钮、含糊答复不构成确认。
- 执行前检查是否已有其他标签页创建的对应内容；服务端依据真实版本保存结果回复成功或失败。读取资料不应阻止提议或经确认的生成。
- 逐轮记录在 PostgreSQL 中取最近记录再正序展示，避免长会话误将早期提问当作最近提问。复盘中的明确计划调整继续走原复盘流程。
- 为避免在保存失败前提前播出“已生成”等不实结果，报告与计划的生成回合等待校验和保存后显示最终回复；普通对话保留原有流式回复。

## 检查

- 使用真实前端、真实模型与测试账号，在手机视口完成“咨询行动方向 → 提议创建计划 → 选择可以 → 计划页出现阶段和任务”。桌面视口核对了同一会话记录和计划页。
- 准备虚构画像后，真实对话出现报告提议；刷新后选项仍可用，选择可以后回复显示报告已生成，报告页出现 V1 正文。
- 独立 PostgreSQL 临时表测试 205 条记录时，能正确读出最新 200 条且按时间正序排列。
- 自动化测试覆盖简短确认、拒绝、附带约束、跨会话和过期选项、另一标签页先创建、保存失败、读取资料、长会话及复盘调整。

## 仍需注意

- 真实模型报告中出现过把“未提供材料”写成“材料不存在”的判断。虽然本次确认与保存流程已验证，报告内容仍需进一步核对；不能把成功生成等同于结论全部准确。
- 并发检查覆盖另一标签页先完成创建后再确认的场景；两个请求严格同时开始时的数据库级互斥尚未专项验证。
- 本次自动提议只覆盖诊断报告和行动计划，其他业务能力没有因此全部获得对话确认流程。
