# 对话与报告矛盾修复（2026-10-18）

## 现象

用户说「我想讨论：更新报告」后，对话回复先说：

> 这轮先补依据，再谈改结论。诊断报告已生成，可以到对应页面查看。

同一条回复里既说“不能核/先补依据”，又说“报告已生成”。随后报告 V4 的结论又写成：

> 报告里「匹配度最高」……我这边没看到算法和外部岗位要求原文，所以这轮能更新的是依据，不是结论。

这是把“报告生成过程/对旧报告的点评”写进了报告结论，属于内容越界。

## 根因

1. **意图误判**：`_explicit_report_request` 的正则把“更新报告”直接当成生成指令，没有识别前面的“讨论”。于是编排器按“明确生成报告”走诊断环节；模型在对话中认为资料不足，服务器又在末尾追加“诊断报告已生成”，形成前后矛盾。
2. **报告结论越界**：诊断环节的模型把“本轮能更新的是依据”“报告里匹配度最高”这类生成过程/旧版点评写进了 `verdict`。原校验只检查“未提供→能力不足”，没有拦截这类“对报告本身的评论”。
3. **历史数据兜底**：已经落库的 V4 仍带着这段文字；读接口还有 Redis 报告缓存，新映射不会自动覆盖旧缓存。

## 修复

### 1. 意图识别
- `_explicit_report_request`：出现「讨论/聊聊/先说/商量/想问/咨询/比较」且没有「帮我/直接/现在/马上/重新 + 生成/更新」时，一律按讨论处理，不生成报告。
- `_explicit_plan_request`：同一口径，避免“讨论更新计划”被直接改写计划。
- “更新报告”“帮我更新报告”“重新生成诊断报告”仍按明确生成处理。

### 2. 报告结论校验
- 新增 `_diagnose_verdict_is_meta`：结论里出现「报告里/本报告/这轮/本轮/上一版/匹配度最高/没看到算法/情报原文/更新的是依据/先补依据」等生成过程标记时，拒绝落库。
- 命中时本轮不生成报告，回复改成明确的讨论口径：
  > 这轮先不更新报告，也不把上一版结论当成新依据。你直接把想核对的那一段报告原文，或岗位要求贴过来，我们先按原文看。
- `_save_report` 增加同一道兜底，防止其他调用方绕过对话校验。
- 历史版本在 `report_full_text_view` 读取时做内容兜底：不再把这类文字当诊断结论展示，改为“本版结论待重新生成”，并提示补充材料后重新生成。

### 3. 缓存
- 报告全文读缓存 key 增加 `v2:` 前缀，避免 Redis 里旧 DTO 在新映射上线后继续被读到。

## 验证

- 新增测试：
  - `我想讨论：更新报告` / `先聊聊报告怎么更新` → 不生成；
  - `帮我更新报告` → 生成；
  - 报告结论含“报告里/这轮/匹配度最高” → 判定越界；
  - 正常证据型结论不误判。
- 线上实测：
  - 发送「我想讨论：更新报告」→ 回复“这轮先不更新报告…”，**不含“已生成”**；
  - 报告版本保持 V4，未新增；
  - 历史 V4 的 verdict 读取为「本版结论待重新生成」，不再显示生成过程点评。
- 相关测试：`test_ai_eval_boundaries`、`test_conversation_asset_confirmation`、`test_loop_advances_on_real_progress` 共 72 passed。
## 同类问题排查（本轮一并修）

- **“帮我更新计划”反而没被识别**：计划意图正则缺少“更新”，导致明确要求更新计划时不会进入计划生成；已补上。
- **讨论/询问任务完成被当成完成任务**：`先聊聊怎么完成任务`、`我想讨论怎样完成任务`、`任务完成了吗` 原来都可能返回“完成”意图，进而可能改动任务状态；已加讨论/疑问保护，`第二项做完了` 仍识别为完成。
- 画像更正类语句（“我想讨论改专业/先聊聊改专业”）已确认不会误写；报告、计划、任务三类都加了讨论保护。
- 方向方案内容里出现的“本轮”属于方案说明，不是报告生成过程；本轮未按脏数据拦截，避免误杀正常方案。

## 为什么之前的测试没查到

1. **测试只覆盖了“典型正向短语”**：例如 `test_loop_advances_on_real_progress` 直接把 `更新报告` 当作生成请求，没有覆盖“我想讨论：更新报告”这种同一句里既有动作词又有讨论词的情况。
2. **测试没有覆盖“讨论/疑问 + 动作词”组合**：`先聊聊怎么完成任务`、`任务完成了吗` 既不在完成意图用例里，也不在否定用例里。
3. **报告内容测试只查结构，不查文案是否在评论报告本身**：现有契约测试关注字段完整、证据边界（未提供不能写成能力不足），但没有“结论不能写生成过程/旧版点评”的断言；测试里的假模型输出都是手写的安全文本。
4. **没有端到端一致性断言**：测试分别验证“意图识别”和“报告落库”，没有一条用例把“对话回复”和“实际资产版本/正文”放在一起断言，所以“回复说不能、资产却生成了”这种跨层矛盾不会失败。
5. **缓存未纳入测试**：报告读缓存不会因映射升级自动失效，旧 DTO 可能继续返回；本轮通过 key 版本化解决，并补了读取兜底。
