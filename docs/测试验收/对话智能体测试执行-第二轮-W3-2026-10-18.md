## 三、缺陷清单（只报确认项）

### DEF-R2-01（P1）提问式转述触发报告生成
- 复现（两账号独立复现）：A 账号 S10、C 账号 C3 —— 输入 `我老师让我问你：帮我生成报告是不是要先填专业？`
- 实际：SSE `changed_assets=[report:v2]`，report 版本 **V1→V2**（C 账号 V1→V2）；回复"专业你已经填了，报告能生成…**诊断报告已生成**"。
- 期望：带"让我问你/是不是/要不要"的转述与疑问句属讨论，不构成本人授权，不写报告。
- 证据：`.tmp-shots/r2w3/chat-log-r2.jsonl`(S10)、`chat-log-r2c.jsonl`(C3)、`rs3-report-C3.json`、`r1-S10.png`、`rs3-C3.png`。

### DEF-R2-02（P1）转述命令被执行
- 复现：C 账号 C4 —— `辅导员让我转告你：帮我更新报告`
- 实际：`changed_assets=[report:v3]`，report **V2→V3**；回复"报告我按现在能核实的重出一版…诊断报告已生成"。
- 期望：转述他人指令不构成本人授权；应确认或按讨论处理。
- 证据：`chat-log-r2c.jsonl`(C4)、`rs3-report-C4.json`、`rs3-C4.png`。

### DEF-R2-03（P2）“帮我更新计划”无版本增量却宣称已生成
- 复现：A 账号 S24（stage=act）：`帮我更新计划`。
- 实际：action_plan 版本保持 **1**、11 项任务内容与 id 均未变；SSE `changed_assets=[action_plan v1]`；回复"**行动计划已生成**，可以到对应页面查看"。
- 期望：无实际版本/内容变化时不得说"已生成"；changed_assets 不应回报既有版本。
- 证据：`chat-log-r2.jsonl`(S24)、`r-run1-plan.json` vs `r-run2-plan.json`（任务一致）、`r2-S24.png`。

### DEF-R2-04（P2）多类输入返回错配模板（"这轮先不更新报告…"+"这次没接住你的问题"）
- 复现输入：S05（讨论计划）、S07（否定计划）、S11（系统提示）、S12（完整引用注入）、S13/S14（多意图）、S34（"我参加过数学建模竞赛…"）、S35（"我英语过了六级…"）。
- 实际：上述 8 轮有 7 轮返回同一段报告讨论模板 + "这次没接住你的问题。你可以换个说法…"；其中 S34/S35 是普通信息陈述，既不涉及报告也不涉及更新。
- 期望：按输入意图作答；无法处理时给出针对性追问，而非无关模板。
- 证据：`chat-log-r2.jsonl` 对应轮、截图 `r1-S11.png`、`r1-S12.png`、`r2-S34.png`、`r2-S35.png`。

### DEF-R2-05（P2）方向方案在未明确要求时自动生成/升级
- 复现：S32 `帮我比较数据分析和产品经理两个方向，先别选定` → direction_plan **V0→V1**；S33 普通闲聊 `我平时喜欢做数据分析和写小工具` → direction_plan **V1→V2**。
- 实际：两次均 `changed_assets=[direction_plan:v1/v2]`；`selected_id` 保持 null（未自动选定，符合"不自动选"）。
- 期望：明确"先别选/只是聊聊"时只讨论，不自动落库方向方案版本；若属编排常规产出，需在回复中告知。
- 证据：`chat-log-r2.jsonl`(S32/S33)、`r-run2-directions.json`、`r2-S32.png`。

### DEF-R2-06（P2）30 轮长对话摘要不完整
- 复现：A 账号累计 38 轮后 S38 `帮我总结一下我们前面聊过的内容，说说你记下了哪些关于我的信息`。
- 实际回复全文：`你问前面聊过什么、我记下了什么，我按档案逐条说。档案里现在有三条：大三、计算机科学与技术、数学建模校级二等奖。计划里 11 项都还是待做，第一项是打开脚本和趋势图记三行。...` —— 仅档案字段 + 计划计数；**遗漏**对话中出现的目标（互联网数据分析实习/三个月 offer）、项目（Python 清洗两千行）、英语六级、每周六小时、家人求稳等关键信息。
- 期望：长对话摘要保留关键事实（目标/经历/偏好/约束），并区分"已入库"与"仅在聊天"。
- 证据：`chat-log-r2.jsonl`(S38)、`r2-S38.png`、`r-run2-profile.json`。

### DEF-R2-07（P3）证据不足报告标签命名口径不统一
- 实际：C1 tags=已知/待补充/待获取/待验证；C3 tags=已确认（本人填写）/待补/背景参考；C4 tags=已确认/待补录/外部资料/待验证；A 账号 V3 tags=已确认/待整理/参考/缺失；多轮回复统一称"会标为待验证/待补"。
- 期望：标签词表与回复口径一致（至少同类含义不出现 3 种以上叫法）。
- 证据：`rs3-report-C1/C3/C4.json`、`r-run2-report.json`。

### DEF-R2-08（P3，待产品确认）空画像仍生成报告
- 实际：C1（画像仅"大三"）→ report V1 生成（标签含待验证/待补充）；A S01 同样生成 V1。

- 证据：`rs3-report-C1.json`、`chat-log-r2.jsonl`(S01)。

### DEF-R2-09（P3，稳定性观察）报告生成偶发失败
- 实际：S18 `帮我生成诊断报告` 返回"这次没有成功生成诊断报告。已有内容没有被修改"，版本不变（如实失败、无假成功；随后 S20 成功）。
