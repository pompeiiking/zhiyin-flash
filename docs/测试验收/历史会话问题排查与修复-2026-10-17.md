# 历史会话问题排查与修复（2026-10-17 晚）

- 报障：用户反馈「历史会话这一块好像存在问题，包括不限于点不开、没保存会话记录、无上下文」。
- 排查方式：接口复现（新建账号逐步调用 `/app/sessions`、`/app/task/enter`、`/app/conversation/message`、`/app/sessions/{id}/turns`，并核对数据库）＋ 真实浏览器（headless Chrome + CDP，1440×900 / 390×844）点击复现 ＋ 代码走查。
- 结论：**共定位 4 个真实缺陷**（另 1 个是"上下文其实正常、但恢复到了错误会话"的表现），全部修复并重建部署。

## 一、根因

| # | 现象 | 根因 |
|---|---|---|
| 1 | 刷新后回到"选主题"页，之前的对话像丢了 | `/app/sessions` 把**只点了主题、一句没发的空会话**也返回；前端刷新时恢复 `sessions[0]`（按会话行 `updated_at` 排序），空会话常是最新一条 → 恢复到空会话，页面渲染成主题选择页，旧对话"看不见" |
| 2 | 恢复位置不稳定 | `SessionListView.current_task_id` 恒为 `null`（facade 从未填），前端只能拿列表第一条猜"最近会话" |
| 3 | 点「＋ 新建咨询」又看到旧内容 | `POST /app/task/enter` 对同一 `task_code` 永远 `find_active` **续接**，没有"新建"分支；选同主题 = 打开旧会话。用户以为开了新对话 → "新会话没保存/串会话" |
| 4 | 发完消息刷新/停止/模型失败后，这句话消失 | 用户消息只在**轮末**（`_remember_turn`）才写逐轮原文；模型超时、点「停止」、发完立刻刷新都会中途返回 → 用户消息从未落库。停止生成只把文本放回输入框（sessionStorage 草稿），刷新即丢 |
| 5 | 同主题多条会话无法区分 | 会话项只显示主题名 + 日期；同一天创建的多条会话文字完全一样，点开前不知道是哪条、有没有内容 |

**上下文本身是正常的**：打开正确的会话后，模型能接上前文（实测回复"你上回说的是：学汉语言文学… 我问到写的是哪一类，你还没答，就从这儿接着聊"）。"无上下文"主要是 1/2/3 导致恢复到了错误或空会话。

## 二、修复内容

### 后端

| 文件 | 改动 |
|---|---|
| `zhiyin-api/dto/conversation.py` | `TaskSessionView` 增加 `message_count` / `last_message` / `last_message_at`；`TaskEnterRequest` 增加 `new_session` |
| `zhiyin-api/dto/mappers.py` | `task_session_view` 透传轮数与最后一句预览 |
| `zhiyin-api/facade/application.py` | `list_sessions`：**过滤空会话**；按最后一句消息时间倒序；`current_task_id` = 最近一条有内容的会话；`enter_task` 透传 `new_session` |
| `zhiyin-business/services/orchestrator.py` | ①`enter_task(..., new_session=True)`：不续接，先把同入口进行中的旧会话标 `completed`（仍留在历史可打开），再建新会话；②**用户消息在调模型前先落库**（`_user_turn_saved` 防重复），模型失败/停止/刷新中断都不再丢这句话；③"上一条主理消息"改为从历史里往回找 `agent` 轮（先落用户消息后 `recent_turns[-1]` 不再是主理，否则提议/工具确认会失效）；④`_turn_group` 排除本轮用户消息，避免同一句在提示词里出现两次 |
| `contracts/openapi.json` + `zhiyin-web/src/api/types.ts` | 按代码重新生成接口契约与前端类型 |

### 前端

| 文件 | 改动 |
|---|---|
| `lib/system-data.ts` | `newSession(code, fresh)`；`fresh=true` 时请求 `new_session: true` |
| `api/backend-client.ts`、`api/backend-types.ts` | `enter(task_code, new_session)` 与新增会话字段 |

| `components/DesktopSidebar.vue`、`WorkspaceNav.vue`（移动端） | 历史会话同样显示最后一句预览、条数、时间；排序改用最后消息时间 |
| `styles` | 历史项预览单行省略、新会话开关/空态样式 |

## 四、剩余观察（不影响本次修复）

1. `current_task_id` 是**账号级**"最近会话"：多标签页同时聊不同会话时，刷新会恢复到最近发过消息的那条（单标签页正常）。若要按标签页记忆，后续可在前端按 tab 持久化当前会话 id。
2. 停止/中断的消息现在会以"只有提问"进入历史（这是为了不丢话的取舍）；界面停止提示已说明"问题已放回输入框"，刷新后能找回原话。
3. 同主题多条会话靠"预览 + 时间"区分，暂未提供重命名/删除会话；如需要可后续补。
