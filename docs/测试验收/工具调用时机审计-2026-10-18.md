# 工具调用时机审计（2026-10-18）

> 背景：新账号第一句“认识自己的兴趣与优势”被提议“查看你已有的个人画像”，画像实际只有“大一”一条。  
> 目标：所有工具/工具提议都必须“有数据、有上下文、有明确意图”才出现；没有数据时不打扰用户。

## 一、统一原则

工具确认（offer）只在同时满足以下条件时出现：

1. **数据存在**：对应画像/报告/计划/方向/日历/记录/成绩确实有内容。
2. **上下文足够**：不是用户本次会话的第一句话；至少完成一轮交流。
3. **意图相关**：用户没有说“先不要/先别/只聊聊/不想”，模型也不是在纯讨论。
4. **不重复打扰**：同一会话冷却期内不重复提议；已有待确认提议时不叠加。
5. **转述/注入不触发**：别人转告、引用、系统提示不构成本人授权。

实际工具调用（非 offer）也要尊重数据边界：图表无数据拒绝、任务不存在不假完成、联网未配置不编结果。

## 二、逐工具门禁

| 工具 / 提议 | 数据前置 | 当前门禁 |
|---|---|---|
| `read_profile` / `profile_detail` | 画像 ≥2 条有效字段 | 不足则移除；首轮不提议 |
| `chart_profile` | 画像 ≥2 条有效字段 | 不足则移除 |
| `read_academic` | 成绩单有课程/成绩 | 注入 `academic_service` 检查；无数据移除 |
| `read_report` | 已有报告 | 无报告移除 |
| `read_plan` / `plan_detail` / `progress_card` / `progress_detail` | 已有计划且计划里有任务 | 计划为空或无任务移除 |
| `chart_plan` | 计划里有任务 | 无任务移除 |
| `read_directions` | 已有方向方案 | 无方案移除 |
| `read_calendar` | 有日历节点 | 无节点移除 |
| `read_notes` / `read_reviews` | 有成长/行为记录 | 无记录移除 |
| `read_achievements` | 有完成记录 | 无记录移除 |
| `behavior` | 有近期行为 | 无行为移除 |
| `web` | 配置了搜索服务 | 未配置时 `web.search` 不在可用工具中 |
| `knowledge` / `xuezhi` | 公开资料，不依赖本地数据 | 仍要求用户问题相关、模型明确提议 |
| `task_done` / `task_undo` | 有计划且能唯一定位任务 | 任务不存在/不唯一时不提议、不执行 |

## 三、本轮修复点

1. 画像只有 1 条时不再提议“查看已有画像”。
2. 无日历/成长记录/成就/近期行为时不再提议对应查看。
3. 计划存在但没有任务时，不再提议查看计划/进度/图表。
4. 第一轮发言不主动弹 `read_*` 工具确认。
5. 注入 `academic_service`，无成绩/课表时不再提议“查看已有成绩和课表”。
6. 所有工具提议继续受“转述/注入不授权”守卫；`read_*` 在用户说“先不要/只聊聊”时不出现。

## 四、验证

- 新账号首句“认识自己的兴趣与优势”：无画像/记录/成绩提议，无底部“有一条确认还没回复”，只引导用户说具体经历。
- 工具提议相关 pytest：`test_conversation_tool_confirmation` / `test_conversation_asset_confirmation` 全通过。
- 图表无数据拒绝、任务工具不虚构、联网未配置不编结果，沿用前两轮 PASS。
- 后端全量：1185 passed / 5 既有环境失败。

## 五、仍需注意

- `read_academic` 依赖生产容器注入 `academic_service`；精简测试装配未注入时跳过数据检查，但生产装配已注入。
- 模型仍可能在回复正文里自行说“要不要看已有…”，这属于内容生成而非服务端 offer；若后续出现，需要在提示词层再加一条“无数据不主动提议查看资料”。
- 真机长会话下的工具时机仍需继续抽样（本轮以新账号与短会话为主）。
