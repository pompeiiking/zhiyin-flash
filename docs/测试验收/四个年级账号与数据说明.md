## 数据范围

每个账号包含基础画像、当前课表、与就读阶段相符的既往成绩、5 个咨询主题、项目材料、24 条待办及 4 个目标、3 条方向方案、4 阶段共 24 项行动、对应日历节点、15 维诊断报告及历史版本、阶段复盘、通知与成长记录。

完成状态按年级分别设置为 4、5、6、7 项，保留未完成事项；日历包含近期与后续节点。大一成绩保留入学阶段的少量记录，大二到大四逐步增加，不为刚入学的学生填入高年级课程成绩。

咨询通过真实消息接口生成回复并保存历史，附件通过材料上传接口写入。画像修正、课程导入、待办创建和完成、方向选择、行动完成、通知已读均走现有业务接口。报告、方向、行动与复盘内容由可重复的数据夹具通过领域服务或对应仓储写入。成长记录由写入操作产生的行为日志推导。项目与复盘时间线按最近一个月分布；咨询和实际接口操作保留生成时间。

本次不提供学信网验证码，不写入“已核验”状态；外部岗位信息继续由现有信息源获取。

## 工具与续跑

- [数据准备脚本](../../scripts/fixtures/seed-students.py)：支持 `base`、`chat`、`assets`、`finalize`、`verify` 五阶段，默认顺序执行。
- [四个账号的内容配置](../../scripts/fixtures/student-personas.json)：姓名、经历、课程、任务、目标与复盘内容。
- `STUDENT_SEED_PASSWORD`：执行时提供，脚本不保存密码或登录令牌。
- `--state`：续跑状态文件。保存在仓库外；保留它才能安全续跑。遇到不在状态清单中的同名已有账号会直接停止，不重置密码、不覆盖其他用户。
- `--write`：显式允许写入。目标仅限容器内 `http://127.0.0.1:8000` 或 `localhost:8000`。

将两个脚本文件复制到当前后端容器同一目录，执行：

```powershell
# STUDENT_SEED_PASSWORD 由当前终端环境传入。
docker cp scripts/fixtures/seed-students.py zhiyin-flash:/tmp/seed-students.py
docker cp scripts/fixtures/student-personas.json zhiyin-flash:/tmp/student-personas.json
docker exec -e STUDENT_SEED_PASSWORD zhiyin-flash python /tmp/seed-students.py --write --state /tmp/student-seed-state.json
```

脚本不启动后台执行器、不改变系统配置、不删除数据。请勿在已有四个账号但缺少续跑状态文件时通过移除保护逻辑强行重跑。

分阶段执行或续跑时，画像导入事件可能仍在后台等待处理。若最终验证提示资产待重算，应等一个后台 Worker 周期，再执行 `--phase finalize` 和 `--phase verify`；最终复核保存新版本并继承任务完成状态，不直接清除过期标记。

## 验收方式

写入完成后用四个账号重新登录，经 HTTP 回读画像、课程、成绩、咨询历史、待办、报告、版本、方向、计划、日历、时间线、通知和成长记录。核对数量、方向选择、完成状态、课表节次和版本正文；使用另一个账号的会话 ID 验证不能读取他人的消息。

本轮最终数量与检查结果记录在同目录的《四个年级账号数据验收结果.json》。浏览器另行核对账号切换、学业资料、计划与日历的实际显示。
