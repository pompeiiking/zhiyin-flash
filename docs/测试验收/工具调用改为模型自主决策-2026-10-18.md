# 工具调用改为模型自主决策（2026-10-18）

> 回应：“能不能让 AI 自己判断什么时候调用工具，不要再写关键词？本机不是部署了 Kev 吗？”

## 一、Kev 是什么

- 本机 Kev 正在运行：`http://127.0.0.1:8009`，模型 `kev-latest`（Kev-0.8B / Qwen3.5-0.8B，CPU）。
- 后端已接：`ZHIYIN_DECISION_BASE_URL=http://host.docker.internal:8009`、`ZHIYIN_DECISION_MODEL=kev-latest`。
- 但 Kev 暴露的是 `POST /v1/systemone`：输入 state + 一组选择题 + 选项，返回选项与概率。
- 它只做**意图分类/路由**，不接触工具 Schema、工具结果、权限；因此不能直接承担“什么时候调用哪个工具”。

## 二、这次改了什么

### 之前

- 业务侧先写 `direct_tool_request` 关键词，决定模型能不能直接调工具；
- 引擎再写 `business_calls` 关键词（“查看/查询/画像/报告…”），决定是否开启 function calling；
- 关键词没覆盖到就退化成“只能提议、不能调用”。

### 现在

1. **主模型决定工具时机**：只读工具每轮都挂给模型，由模型结合上下文决定是否调用；删除 `direct_tool_request` 与 `business_calls` 的关键词判断。
2. **写入工具单独授权**：`workspace.task.set_done` 默认不挂给普通轮次，只有用户确认（`allow_write_tools=True`）才挂上；模型不能自行改任务。
3. **服务端保留确定性门禁**：
   - 数据是否存在（画像/报告/计划/方向/日历/记录/成绩/计划任务）；
   - 是否本人、是否在允许范围；
   - PII / 注入 / 转述 / 用户明确拒绝工具；
   - 写资产仍需用户明确请求或确认。
4. **Kev 继续做意图先验**：不是工具执行器；保留现有的意图路由用途。

## 三、新增一个工具时怎么做

不需要再加“什么时候调用”的关键词。只需要：

1. 在工具注册表/装配层注册实际 handler；
2. 在 `agents.json` 白名单里声明哪个 agent 可用；
3. 若是业务数据工具，补数据可读性（查询函数）与空数据返回；
4. 若是写工具，明确它是否需要用户确认；需要确认的不要默认挂给普通轮次。

模型会在看到工具描述与当前上下文后自行选择调用；服务端只校验“能不能读/能不能写”。

## 四、验证

- “看看我的诊断报告”：模型自行调用 `workspace.read area=report`、`achievements`，基于真实报告回答；日志可见 `业务工具调用：workspace.read area=report`。
- 新账号第一句“认识自己的兴趣与优势”：模型没有调用工具，先继续采集。
- “不要查询我的成绩，先聊聊兴趣”：用户明确拒绝工具，本轮不挂工具、不调用。
- 工具确认/拒绝/失败相关 pytest：通过；后端全量 **1185 passed / 5 个既有环境失败**；前端 **78/78**、typecheck 通过。
- 写任务仍走确认：未确认轮 `workspace.task.set_done` 不在模型工具列表中。

## 五、边界

- “模型自主”不等于“模型可以越权”。只读工具可自主；写资产、改任务、报告/计划生成仍需要用户明确请求/确认。
- Kev 可以继续作为快意图先验（例如“这轮更像查数据还是聊感受”），但它不适合做工具选择器：看不到工具 Schema 与数据，只会变成另一套关键词。
- 如果以后要给 Kev 增加工具选择能力，需要改 `/v1/systemone` 的问题定义与训练数据，并接受额外 0.7–2.5 秒延迟；不建议作为主路径。
