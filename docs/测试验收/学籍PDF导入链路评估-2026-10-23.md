## 当前核验流程

1. `zhiyin-web/src/components/AcademicVerification.vue` 收集在线验证码并做格式校验，通过 AI 任务客户端提交。
2. `zhiyin-api/zhiyin_api/controllers/ai_controller.py` 的 `POST /api/v1/app/chsi/bind` 接收 arg，调用 `bind.chsi` 流式任务。
3. `zhiyin-business/zhiyin_business/services/ai_tasks.py::_bind_chsi` 调用核验网关。
4. `zhiyin-infrastructure/zhiyin_infrastructure/chsi/gateway.py::OnlineVerificationGateway.verify` 校验码格式、错误页、可解析字段和报告有效期。
5. `chsi/client.py::ChsiReportClient.fetch_report_html` 由服务器的 httpx 客户端请求 `https://www.chsi.com.cn/xlcx/bg.do`，参数为 vcode 和 srcid=bgcx；不是浏览器直连，也不是已接入正式数据 API。
6. HTML 文本按标签提取字段，再由业务层检查与现有画像的姓名、学号是否明显冲突。
7. 按 `data/registry/chsi_fields.json` 白名单写画像，source=record、verification=verified、confidence=1.0；保留不含验证码的来源入口。白名单包括学校、院系、专业、层次、学制、学习形式、入学日期、预计毕业、学籍状态、学号和姓名；身份证号等不写入画像。
8. 年级从入学日期另行推算，标为 pending；已有本人填写的年级不被推算值覆盖。

客户端目前把 403、超时等 httpx.HTTPError 统一转换为 unreachable，显示“连不上学信网”。本次没有重新请求真实验证码或重新诊断服务器出口；先前的 403 结论不是本轮新测试结果。

## PDF 链路可行性

可增加独立材料导入流程，避免依赖服务器访问学信网：

用户在学信档案下载《教育部学籍在线验证报告》PDF → 个人画像/学籍信息上传 → 服务端提取字段 → 页面预览字段、报告日期与冲突项 → 用户确认 → 写入画像并保留材料来源。

学信网官方说明支持下载 PDF：https://www.chsi.com.cn/xlcx/bgys.jsp 。官方介绍的真伪核验仍需在线验证：https://www.chsi.com.cn/xlcx/yzzw.jsp 。因此 PDF 可作为用户提交材料导入，但文件可被修改，解析成功不能直接等同于在线核验通过。

当前 `zhiyin-infrastructure/zhiyin_infrastructure/textfile.py` 的 LocalTextExtractor 明确拒绝 PDF，项目依赖中没有专用 PDF 读取库。现有教务上传接口只负责课表/成绩；对话材料接口也不是学籍结构化入库接口。不能只在前端增加 accept=.pdf 就声称支持。

## 推荐实现边界

- 在 AcademicVerification 中并列保留验证码入口和“上传学籍报告 PDF”，不把 PDF 接入伪装成验证码核验。
- 新建专用 PDF 提取网关和学籍导入服务。首先支持学信网直接下载的中文、含文字层的学籍报告；扫描件/截图 PDF 明确提示暂不支持或后续 OCR，不猜字段。尚未用真实原版 PDF 做提取验证，需要样本确认标签和阅读顺序。
- 对文件大小、实际 PDF 内容、页数、解析耗时和提取文本长度设限；损坏、加密、非学籍报告、字段缺失返回具体错误，解析失败不改画像。
- 复用字段白名单、姓名/学号冲突检查、日期解析和年级推算规则。现有文本标签解析器只能作为起点，不能假定 PDF 提取顺序与 HTML 一致。禁止把说明段落或验证码当作字段值。
- 采用服务端解析预览和确认导入两个步骤。确认时仅接收绑定当前用户的预览标识，服务端保存或重新计算预览内容；不接受前端任意回传字段并赋予材料来源。确认时复查画像版本及冲突，支持幂等，避免重复导入和部分写入。
- 画像字段标记“用户上传学信网报告 / 资料记录 / 待在线核验”。可复用 verification=record 表达材料记录；不能设置 verified，也不能沿用在线核验分支的 1.0 权威口径。本人确认、材料解析和外部核验分别呈现。
- 不以低等级上传材料覆盖已有在线核验字段或本人修正值；冲突展示并由用户处理。报告过期、缺少可读有效期或身份信息不足时明确展示，不据文件上传自动断言当前在读。
- 当前 `zhiyin-web/src/lib/backend-demo.ts` 的 chsiVerified 仅检查 source=record 与 chsi 域名 evidence，没有检查 verification；必须改成可靠的核实状态判断，并检查工具页、画像页、采集清单等所有关联提示。
- `policies/collection.py` 的 counts_as_got 目前对权威字段主要检查来源。导入后“资料已提供”与“已在线核验”需区分，避免材料导入让核验提醒永久消失；不能通过更改 source 全局收紧已有教务和对话流程。
- 材料来源用当前用户所属的导入记录 ID、摘要哈希和导入时间表达，不用带验证码的官网 URL。若保留原 PDF，应提供访问控制和删除入口；避免把照片、身份证号、验证码及报告全文扩散到日志或模型上下文。
- 新增接口后同步 OpenAPI、前端类型/调用、装配和能力说明。根据最终上传限制同步 nginx，目前其 client_max_body_size 为 4m。

## 验证要求

后端覆盖标准报告、不同标签排版、假 PDF、损坏/加密/扫描件、超限、错误报告类型、过期、身份冲突、预览越权、重复确认、确认前画像变更、部分写入失败和已有已核验字段保护；证明导入路径不调用在线核验网关。

前端验证预览和确认、失败后保留已有资料、状态文案、上传后仍显示“待在线核验”、画像刷新和移动端入口。执行 npm test、npm run check:backend、npm run build；真实 PDF 联调与部署验收另行记录，不能以合成测试替代真实文件验证。
