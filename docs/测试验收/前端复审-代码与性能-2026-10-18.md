## 二、P1 详情

### P1-1 设计截图随构建发布（12.64MB，无引用）

- 位置：`public/shots/`（61 个 PNG/JPG，12.64MB），构建后原样复制到 `dist/shots/`（61 files / 12.64MB）；`dist` 总计 14.31MB，其中业务静态资源仅 1.66MB。
- 证据：`dist/shots/skin-dark-report.png` 624KB、`report.png` 555KB 等；全仓检索 `shots/` 仅命中两条源码注释（`src/components/DesktopSidebar.vue:124`、`src/components/EvidenceList.vue:21`），无任何 `<img src>`/`import`/CSS `url()` 使用；`public/` 其余文件仅 licenses 与 1 个小文件。
- 影响：部署镜像与静态目录膨胀约 12.6MB（占 dist 88%）；截图内容随站点可被直接抓取（设计稿/演示数据外泄面）；与"首屏无关但拖慢构建/发布"。
- 建议：把 `shots/` 移出 `public/`（放 `docs/` 或设计资产库）；若确需在线预览，改为懒加载并压缩（WebP，目标 <200KB/张），加 `robots`/访问控制；CI 增加"dist 体积预算"门禁。

### P1-2 全局 CSS 分层叠加与选择器重复

- 位置：`src/main.ts:4-16` 连续 13 个 `import './styles/…css'`；`src/styles/` 16 个 CSS 共 517KB 源码（base 1762 行、workspace-modern 1074 行、dialogue 1040 行、workspace 878 行、tokens 703 行）。
- 证据（静态统计脚本，仅统计选择器字面量）：
  - 跨文件重复选择器 **782** 个（同一选择器在 ≥2 个文件出现）；示例：
    - `.app.app--workspace .ws-heading h1` — 8 处（c2-fidelity / refinement / workspace-modern 等）
    - `.report-chapter` — 8 处（c2-fidelity / print / redesign / workspace-modern）
    - `.app.app--workspace .dialogue-presence` — 8 处
    - `.app.app--workspace .ws-heading__actions` — 7 处
    - `button` 11 处、`textarea` 9 处、`select` 9 处、`input` 6 处
  - `!important` **106** 处（print.css 22、FullReportBody.vue 17、workspace-modern 14、conversation/dialogue 各 6）。
  - 入口 CSS 产物 304.9KB（gzip 50.5KB），全部为阻塞渲染样式。
- 影响：样式覆盖链依赖加载顺序与 `!important`，任何样式调整都可能牵连其它页；首屏 CSS 无法按路由裁剪；新人定位"这条规则为何不生效"成本高。
- 建议：把 refinement / workspace-modern / product-interactions 的重复覆盖并入 tokens→components 两层；用 `@layer tokens, base, layout, components, overrides` 显式分层并删掉 `!important`；拆分全局样式为"壳层/对话/报告/计划"按路由动态 import；加 stylelint 规则（重复选择器、`!important` 预算、hex 白名单）。

## 三、P2 详情

### P2-1 入口 chunk 含完整工作区壳层

- 证据：`index-DgAcFSan.js` 400,435B（391KB raw / 125.5KB gzip）；`src/router.ts:32-99` 共 18 个视图动态 import、无静态视图 import；但 `src/App.vue:4-19` 静态引入 `WorkspaceHeader / WorkspaceNav / CommandMenu / AuthLayer / FloatingReminders / CareSheet / DesktopSidebar` 以及 `store`(16.8KB)、`lib/system-data`、`lib/auth`；`data/student` 仅 1.3KB，可忽略。
- 影响：门户（`#/`）与登录/注册首屏同样下载内页壳层与命令面板；移动端弱网首开成本偏高；入口 chunk 变更会导致全站缓存失效。
- 建议：按路由 meta 拆壳：public 路由不加载工作区组件；`CommandMenu`、`CareSheet`、`FloatingReminders` 改 `defineAsyncComponent` 或交互时 import；`manualChunks` 把 reka-ui/@phosphor-icons 固定为 vendor chunk。

### P2-2 重复请求与缺失的共享缓存

- 证据：
  - `src/lib/system-data.ts:54-71`：`loadShell()` 每次执行 `Promise.allSettled([sessions, action, notes, workspace, notifications])`，且 App.vue 在登录恢复/路由会话变化时多次调用（`App.vue:94,101`；`ConversationView.vue:474,612` 也调用 `loadShell`）。
  - 各页各自拉 `backendClient.workspace()`：`StudentView.vue:212,831`、`ConversationView.vue:332`、`GradesView.vue:268`、`ScheduleView.vue:172,187`、`IntelView.vue:130`、`SystemView.vue:92`、`TodayView.vue:104`、`AssessmentView.vue:75`、`ToolsView.vue:31`、`LiveActionPlan.vue:123`、`AcademicVerification.vue:13`。
  - `src/api/backend-client.ts:36-77`：每个请求独立 `fetch`，无请求合并/内存缓存/失效标记；仅 `session-cache.ts` 做 sessionStorage 上下文恢复。
- 影响：页面切换重复打同一接口；多请求并发下页面需自行处理时序（部分页面已用 `serial`，部分没有）；弱网/服务端限流时更容易出现"部分资料没读到"。
- 建议：在 store 层加按 `token 身份 + 资源名` 的共享查询缓存（TTL 30–60s，写操作后失效 `workspace/action/notes`）；`loadShell` 与页面首屏共用同一缓存；对 `workspace` 类读请求用 `stale-while-revalidate`。

### P2-3 超大组件

- 统计（node 行数，含空行）：`StudentView.vue` 1719 行 / 111KB；`GradesView.vue` 1195 行 / 43.5KB；`ConversationView.vue` 987 行 / 77KB；`PublishedTools.vue` 767 行；`PortalClassicView.vue` 589 行；`ScheduleView.vue` 34KB；`StructuredReview.vue` 34.6KB；`LiveDirectionCompare.vue` 30KB。
- 影响：单文件承载模板+状态+格式化+请求，改动冲突概率高；阅读与测试成本高（这些文件目前均无组件级测试）。
- 建议：StudentView 按"画像事实/学籍核验/来源面板"拆子组件并把请求/派生逻辑抽到 `composables/useProfile*`；GradesView 把查询与表格拆开；给拆出的组件补最小渲染测试。

### P2-4 `index.html` 内联逻辑与源码双实现

- 证据：`index.html` 共 145 行，其中：
  - `index.html:9-13` 启动占位样式（写死 `#f7f8fa/#5a6472/#1f6feb/#151517/#cfd3d6`）；
  - `index.html:20-56` 主题防闪脚本（读 `zhiyin-demo-skin`，逻辑与 `src/lib/theme.ts` 平行）；
  - `index.html:70-143` 白屏兜底脚本（资源加载失败/Promise/超时检查，`ResizeObserver` 过滤逻辑与 `src/main.ts:36-39` 重复；底部弹层色 `#96000e/#ffffff` 写死）；`main.ts:41-75` 另有 `showFatal` 一套。
- 影响：两套逻辑需同步修改（例如主题键名、错误过滤正则），易漂移；内联颜色绕过 token 体系（注释已声明为例外，但例外点在两处）。
- 建议：保留 HTML 内联"最小启动占位"，其余抽为构建期注入（Vite `transformIndexHtml` 或独立 `boot.js` 手写最小实现）；用单测锁定主题键名/默认主题与 `theme.ts` 一致；内联色集中到一个常量段并注释指向 tokens。
