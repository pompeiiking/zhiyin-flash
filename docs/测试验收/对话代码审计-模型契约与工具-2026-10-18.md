## 三、缺陷清单

### P2-1 转述/引用门禁词表不全：截图、学长/亲戚/群聊等载体未被识别
- 文件行：`zhiyin-business/zhiyin_business/services/orchestrator.py:190-215`（`_instruction_is_quoted_or_impersonated` 角色词表与动作词）；`:232-262`（`_explicit_report_request`，引用守卫只认 `报告里写|写着|原话|引号|说的是`）。
- 触发：`学长说「帮我更新报告」`、`截图里那句话是「帮我更新报告」，你照着做`、`聊天记录里说「帮我更新计划」`。角色表无「学长/学姐/亲戚/表哥/群友」，载体表无「截图/聊天记录/邮件/微信/公告」；这些句子会走到 `_explicit_report_request` 主正则（`更新…报告`）并返回 True。
- 影响：**未授权生成报告/计划版本**的入口仍在；R3 A11 实测未写入是模型侧拒绝，不是门禁拦住。
- 建议：角色表补 学长/学姐/亲戚/群友/班委 等；载体词（截图/聊天记录/邮件/通知/公告/转载）统一进"引用"判定；并加一条回归用例覆盖 10 个角色 × 4 种载体。

### P2-2 报告越界校验只覆盖 verdict，section/SWOT/维度不扫
- 文件行：`orchestrator.py:3532-3559`（`_diagnose_verdict_is_meta` 只取 `verdict.title/summary`）；调用点 `:1666`（对话路径）、`:2772`（落库路径）。`_diagnose_prose_is_unsafe`（`:3562-3583`）同样只拼 `conclusion+verdict`。
- 触发：模型把"本轮/上一版/报告里…"写进 `dimensions[].items[].conclusion`、`gaps[].current_state` 或 report section 正文。
- 影响：与 `prompts.json` `core.system`"不要泄露内部环节/推理过程"及"报告结论无过程点评"不一致；实测 R3 DEF-R3-01 报告 V2 的 section 结论含"你**本轮**说现在是大五""**本轮**未取得…"，仍成功落库。
- 建议：把扫描范围扩到 `dimensions/swot/gaps/conclusion` 全部可展示文本；或报告落库前对全文做一次 marker 扫描并拒绝。

### P2-3 契约与提示词硬标准脱节（计划截止/时长、SWOT 数量、诊断维度上限、决策三方案）
- 文件行：`contracts/act.py:47`（`phases` 自由列表）；`zhiyin-kernel/zhiyin_kernel/assets.py:138,145`（`ActionTask.due_date`、`estimated_minutes` 均 Optional，无默认）；`assets.py:26-34`（`Swot` 四项 `default_factory=list`，无 min_length，docstring 却写"每项不少于 2 条"）；`contracts/diagnose.py:77-86`（`dimensions/gaps` 无上限）；`contracts/decide.py:52-54`（`plans` 无角色完整性校验，`orchestrator.py:2828-2833` 只在空列表时拒绝）。
- 触发：模型给出缺 `due_date`/`estimated_minutes` 的任务、空 SWOT、超过 2 条维度、1 套或重复 role 的方向方案。
- 影响：`prompts.json` `role.path_planner.act` 明确"每个任务都要有截止时间/预计时长"，`role.career_advisor.diagnose` 写"维度/差距最多 2 条、SWOT 每项至少 2 条"，`role.career_advisor.decide` 写"主攻/平行/保底三套"——这些硬标准在契约/服务端全部不设防；日历页会出现无截止任务、报告维度不足、方向页少于三套。
- 建议：在对应 Pydantic 模型加 `min_length/max_length` 与 role 唯一性 validator（或 `_save_*` 前置校验），与提示词同一口径；提示词里已写死的数量要求应视为契约硬约束。

### P2-4 `workspace.task.set_done` 无"讨论/询问"判别，存在把讨论当完成写入的路径
- 文件行：`zhiyin-boot/zhiyin_boot/module_platform.py:89-120`：`named` 只要求任务原文出现在消息（`:106`），`wants_done` 正则 `标记.{0,8}完成|勾选|完成.{0,4}任务`（`:115`），否定词只含 `不要|不必|无需|暂不|别`（`:113`）。
- 触发：消息 `帮我看看「<某任务原文>」，先聊聊怎么完成任务`（`完成.{0,4}任务` 命中 wants_done，无否定词），模型若调用 `set_task_done(done=true)` → `:116-119` 通过并写库。
- 影响：与"讨论/询问任务完成不能被当成完成动作"的产品修复方向相悖（编排层有保护，但工具是第二条写入路径，agent 可被注入材料引导调用）。
- 建议：工具入口再加"讨论/询问/假设"否定（聊聊/讨论/先问/怎么/吗/如果/假如），并要求完成指令里出现明确祈使（帮我/把…标记/勾选掉）；或把"完成意图判定"收敛到编排层一次性判定后传布尔值，工具只认布尔。

### P2-5 `chart.render` 可宣称"图已挂上"而无图；`direction_match` 是死分支
- 文件行：`zhiyin-infrastructure/zhiyin_infrastructure/ai/tools.py:118-120`（`direction_match` 恒 `return None`，注释"Legacy scores are model estimates"）；`:56-57`（`_CHART_KINDS` 仍登记 `direction_match`）；`:458-469`（依赖盒不存在时仍返回 `图已经挂上了（{title}）…`）。
- 触发：用户要"看方向匹配图"→ 工具返回"画不出来"（可接受）；但依赖盒不是 dict（如直接调用/异常上下文）时，工具仍向模型返回"图已经挂上了"，模型据此回复"图在下面"，前端没有 renderable。
- 影响：工具声明与实际数据不符；模型可对用户宣称展示了不存在的图（与 R2 实测"进度卡片挂上了"类问题同源）。
- 建议：`direction_match` 从 kind 表移除或改为读资产真实分值后再生效；`chart.render` 在盒子缺失时返回"图没挂上，改用文字说"，不要返回成功文案。

### P2-6 `plan_patch` 子串匹配 + 静默失败：一条指令可改多项、非法日期不生效也不告知
- 文件行：`zhiyin-business/zhiyin_business/services/plan_patch.py:24-28`（`_hit` 用 `key in text` 子串）；`:74-84`（一个 key 命中即改）；`:31-44`（`_parse_due` 解析失败返回 None，调用方当"未命中"处理，`:79-83` 原样保留）；`:86-99`（阶段 date_range 直接写任意字符串）。
- 触发：用户 `改一下计划，把第二项挪到下周`，模型把"第二项/下周"作为关键词 → 可能命中多条含相同字样的任务；模型给出非法时间 → 静默不改。
- 影响：与 R3 E06 实测一致（一条指令后 `t_1_2`、`t_1_3` 两项截止日同时后移）；用户听到"挪好了"但计划可能没变/多改；阶段 `date_range` 可写入"10月32日"等无校验文本。
- 建议：`reschedule_tasks` 的 key 只允许任务 id（关键词匹配限定"唯一命中"否则回问）；`_parse_due` 失败要在响应/日志里显式提示"没改成"；`reschedule_phases` 增加日期区间格式校验（复用 `asset_content._normalize_phase_date_range` 并拒绝非法）。

### P3-1 `Disclosure` / `BehaviorGuide` 文档写"必填"，契约实际 Optional；guide 无 kind-payload 校验
- 文件行：`contracts/common.py:3-7`（注释"Disclosure 是必填项之一""BehaviorGuide 是必填项之一"）vs `contracts/collect.py:87-95`、`contracts/diagnose.py:88-95`、`contracts/decide.py:59-63`、`contracts/act.py:57-60`、`contracts/review.py:94-98` 全部 `| None = None`，且提示词 `guide.closing` 明说"给 null 也行"；`common.py:69-83` 无 validator 校验 `kind=options` 时 options 非空、`kind=question` 时 question 非空。
- 影响：注释/提示词/契约三份口径互斥；前端可能拿到 `kind=options` 但 options 为空、`kind=task` 但 task 为 null 的 guide。
- 建议：统一口径（若产品已允许 null，就改注释与设计文档）；补 model_validator 按 kind 校验字段；或去掉 kind 由后端按 payload 推导。

### P3-2 `achievements_unlocked` 是无人写入的契约字段
- 文件行：`contracts/review.py:90-92`（模型可输出 badge_key 列表）；`orchestrator.py:3371-3380`（`_replace_task_ids_in_prose` 只把它当要保留的键）；全仓检索无落库/解锁调用；`kernel/assets.py:200-209` 明确"成就是每次从行为日志**实时推导**出来的，不是一份独立记录"。
- 影响：契约允许一个永不生效的字段，模型按提示词写"本次解锁"也不会发生；后续维护者会误以为已实现。
- 建议：删除该字段，或在 `_save_review` 里丢弃并记录 WARNING；如需保留，仅在行为日志事件确有 badge 时由代码写。

### P3-3 流式降级没有"撤回/纠错"帧；有业务工具调用时整轮不流式
- 文件行：`zhiyin-orchestration/zhiyin_orchestration/impl/agno_engine.py:201-229`（先 `emit_progress({'text': ...})` 流式片段）；`:246-263`（模型 status=error 时返回 `valid=False, degraded=True`）；`:269-301`（`_repair_once` 重新调模型，结果不再流式）；`:223`（`not business_calls and not module_attempts` 才发流式更新）；`stream_text.py:24-48`（未完成字符串可能返回 `''`）。
- 影响：用户先看到部分文本，随后最终结果若校验失败/修复，界面替换或显示兜底句；有工具调用的轮次整轮无进度反馈（体感卡住），与"流式降级"要求不一致。
- 建议：`AgentResult` 增加 `stream_reset` 语义（失败/修复时通知前端清 pending），或校验通过后才开始流式；工具轮次至少发一条"正在查…"状态帧。

### P3-4 工具异常处理不一致；info_scout retries=0
- 文件行：`tools.py:288-293`（`web.search` 捕获异常返回"检索失败"）；`:306-321`（`kb.search` 未捕获 `search.hybrid` 异常）；`:331-370`（`xuezhi_search` 未捕获 `external_data.fetch` 异常）；`:377-424`（profile/behavior/plan 读取未捕获）；`:426-478`（chart 读取未捕获）；`prompts.json:115-119`（`role.info_scout.params.retries=0`）。
- 影响：外部取数/读库超时或 5xx 时，`web.search` 会降级说话，其余工具直接抛异常 → agno 工具调用失败（`_executed_tool_names` 只统计成功调用）→ 本轮可能整轮降级且无重试；用户看到通用失败句而无"哪一步取数失败"。
- 建议：只读工具统一包一层 try/except 返回"这次没取到（原因类别）"；外部情报取数设 retries>=1 与独立 timeout，失败时在回复中说明缺哪类外部事实。

### P3-5 `agents.json` 白名单不是唯一权限来源
- 文件行：`agno_engine.py:553-557`（对 profile_analyst/career_advisor/path_planner/companion_coach 强制追加 `workspace.read`、`workspace.task.set_done`；并追加 `module_tool_names(agent_id)`）；`tools.py:261-263` 注释与 `agents.json:2` 注释称"哪个角色能用模块工具写在 agents.json 白名单里"；`zhiyin-business/services/modules.py:195-197` 的 `tool_names` 实际按模块 `policy.agents` 过滤。
- 影响：同一能力有两套授权源；把 `workspace.task.set_done` 从 agents.json 删掉并不会降权（引擎仍注入），白名单的可审计性下降。
- 建议：产品级工具也走统一授权表（agents.json 或 policy 表二选一），README/注释同步；启动时校验"引擎注入的名单 ⊆ 配置名单"并告警差异。

### P3-6 阶段日期只修 `M月D日（周X）` 一种格式，跨年启发式粗糙
- 文件行：`zhiyin-business/zhiyin_business/services/asset_content.py:44-70`（正则 `(\d{1,2})月(\d{1,2})日[（(]周[一二三四五六日天][)）]`；`:62-67` 超过 200 天按明年猜）。
- 影响：`2026-10-17~2026-10-23`、`第 1 周`、`10/17-10/23` 等格式不会重算星期；1 月初的计划（距现在 200 天内）仍按今年算星期，若实为明年会错。R3 实测阶段星期矛盾属同类（该函数为后加修复）。
- 建议：把所有 date_range 解析成 `(start,end)` 后统一格式化；无法解析就拒绝该阶段并让模型重写，不要原样落库。

### P3-7 画像落库无 PII 兜底（仅提示词约束）
- 文件行：`orchestrator.py:2589-2613`（`_apply_collect` 只有：来源改写、年级/学段黑名单、画像词表、本人填写保护；无身份证/手机号/银行卡扫描）；`contracts/collect.py:48`（`value: object` 任意结构）。
- 影响：若模型把"身份证号 110…/手机号 138…"写进允许字段（如 experience 值/备注），服务端不拦 → 进画像 API、报告、日志；当前靠模型拒绝（R3 C01/C02 实测拒绝），无代码层兜底。
- 建议：`_apply_collect` 落库前对字符串值做 PII 正则（18 位身份证/11 位手机号/银行卡）→ 拒绝并回复"敏感信息不记录"；契约层加 `SecretStr`/脱敏提示。

### P3-8 `FactItem.source_url` 默认空，契约不强制；报告 sources 静默丢弃无 URL 事实
- 文件行：`contracts/diagnose.py:42-44`（`source_url` 默认 `""`）；`prompts.json:109-120`（`role.info_scout` "每条必须有…没有原始链接的不要写"）；`asset_content.py:106`（sources 只收 `item.source_url` 非空项）。
- 影响：模型写无链接事实仍能通过 `DiagnoseOutput` 校验；报告 `sources` 静默为空，正文 facts 却可能被展示 → "无来源事实"进入报告。
- 建议：`FactItem` 加 validator（source_url 空则丢弃该条或整份拒绝），与 info_scout 提示一致。

### P3-9 维度编号无范围/唯一性校验
- 文件行：`kernel/assets.py:42`（`index: int` 无 `ge/le`）；`contracts/diagnose.py:78-80`（`dimensions` 自由列表）。
- 影响：模型可给 `index=0/16/重复`，前端 15 维用编号定位会错位；报告页"15 维"可能少于/多于 15 条。
- 建议：`ReportDimensionItem` 加 `ge=1, le=15`，报告落库前校验 index 唯一且分组数量为 6/5/4（或允许缺省但必须连续）。

## 四、建议修复顺序

1. P2-1（转述词表）——安全面，直接对应"引用/转述不构成授权"的产品底线。
2. P2-2（报告越界扫描）——用户可见资产质量。
3. P2-3（契约硬约束）——系统性，改模型 validator 一次收益最大。
4. P2-4（任务完成工具讨论判别）——写入副作用风险。
5. P2-5 / P2-6（图表与计划补丁）——用户可感知的假成功/多改。
6. P3 清单按迭代排期。
