## 二、复现明细（按严重度排序，均 P2）

### F-01（P2）1024 宽度：报告页章节导航浮轨压住卡片并遮住状态徽标

**复现步骤**
1. 视口设为 1024×768，登录后打开 `#/report`（本账号报告 V1 为“待重新核对”状态）。
2. 观察报告卡片右侧与“待重新核对”徽标。

**预期**：固定章节导航位于正文卡片外侧留白，不覆盖卡片内容与状态徽标；1024 与 1440 表现一致。

**实际（稳定复现）**
- 章节导航浮轨 `.report-toc-rail`：`left=938, right=982, width=44, position=fixed, z-index=38`。
- 报告卡片 `.report-masthead`：`left=241, right=989` → **浮轨与卡片右缘重叠 44px**（浮轨整个落在卡片上）。
- 状态徽标“待重新核对”：`left=891, right=951` → **被浮轨遮住右侧 13px**（截图中徽标显示为“待重新核…”）。
- `document.elementFromPoint` 命中 `report-toc__handle`，浮轨盖在卡片之上。

**涉及文件/行**
- `zhiyin-src/template/zhiyin-web/src/components/FullReportBody.vue:314`：`.report-toc-rail{position:fixed;top:50%;right:max(42px,calc((100vw - 1074px)/2));z-index:38;width:44px;…}`
- 同文件 `:321`：`@media(min-width:1240px)` 才重新计算 right —— **768–1239px 区间沿用 42px 视口固定值，与内容列宽脱钩**
- 同文件 `:320`：`@media(max-width:767px)` 才切到移动端底部位置

**证据**：`desktop1024-06-report.png`、`probe-1024-report-rail.png`、`probe-visual.json`（`report1024`）

**建议**：对 768–1239px 增加中间断点，让浮轨跟随内容列（例如 `right: max(12px, calc((100vw - min(860px,100vw - 48px))/2 - 60px))`），或在该区间改为可收起的贴边按钮。

### F-02（P2）移动端报告页：章节导航浮球与提醒铃铛重叠

**复现步骤**
1. 视口 390×844（或 320×844），打开 `#/report`。
2. 看右下角两个圆形/胶囊控件；点击铃铛位置。

**预期**：两个固定控件互不遮挡，均可点击。

**实际（390 与 320 均复现）**
- 390：`.report-toc-rail` = `left 334 / right 378 / top 704 / bottom 748`，`z-index 40`；`.floating-reminders__trigger` = `left 336 / right 380 / top 712 / bottom 756`，`z-index 39`。**重叠 42×36px（1512px²）**。
- 在重叠区中心 `(357,730)` 调用 `elementFromPoint` 命中的是导航浮球内的 SVG（`report-toc__handle`）→ **想点铃铛会点到章节导航**；铃铛未读红点也压住导航球。
- 320 同样：导航 264–308×704–748、铃铛 266–310×712–756。

**涉及文件/行**
- `FullReportBody.vue:320`：移动端 `.report-toc-rail{right:calc(12px + env(safe-area-inset-right,0px));bottom:calc(96px + env(safe-area-inset-bottom,0px));…}`
- `FloatingReminders.vue:166`：移动端 `.floating-reminders__trigger{right:calc(10px + env(safe-area-inset-right,0px));width:44px;height:44px;…}`（两者距右 12/10px、垂直位置接近）
- `FloatingReminders.vue:142`：铃铛 `z-index:calc(var(--z-drawer) - 1)`，低于导航轨的 38–40

**证据**：`mobile390-06-report.png`、`mobile320-06-report.png`、`probe-390-report-rail-bell.png`、`probe-320-report-rail-bell.png`、`probe-visual.json`（`report390`/`report320`）

**建议**：移动端把章节导航与铃铛排到不同位置（如导航贴左下、铃铛右下），或导航收起为更小的把手并让出 56px 安全区。

### F-06（P2）报告页首屏同一“待核对”状态重复 3 次、措辞三种

**复现步骤**
1. 打开 `#/report`（报告处于 `needs_recompute` 状态）。
2. 看首屏：顶部横幅、封面右上角、封面底部“报告状态”。

**预期**：同一事实在一个页面只出现一次主要提示，其余位置用统一短语或省略。

**实际（同一屏三处）**
1. 顶部横幅：`资料或方向已变化，报告、方向方案待核对`（可选“确认无需重算/核对版本”）。
2. 封面右上：`待重新核对`（红色）。
3. 封面底部：`报告状态：资料或方向已有变化，本版结论尚未随之更新。`
三种措辞（“资料或方向已变化/待重新核对/资料或方向已有变化”）表达同一件事，且第 2、3 处无操作入口；首屏被这三处占去较多注意力。

**涉及文件/行**
- `views/AssessmentView.vue:54-55`：`reportState`/`reportStateDetail`（`needs_recompute` → “待重新核对”“资料或方向已有变化…”）
- 同文件 `:148`（`report-masthead--attention` 红色左边框）、`:156`（“报告状态”字段）
- `components/AssetNotice.vue:35-46`：横幅 `资料已变化，${label}待核对`

**证据**：`desktop1440-06-report.png`、`dark1440-06-report.png`、`mobile390-06-report.png`

**建议**：保留顶部一条可操作横幅 + 封面一处小标签即可；底部“报告状态”改成版本号/生成时间等不重复的信息。
