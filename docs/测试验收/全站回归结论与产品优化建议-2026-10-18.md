# 职引全站回归结论与产品优化建议（2026-10-18）

依据：本轮全站功能清单与真实页面回归（`.tmp-shots/fix3/`）、修复记录、`docs/前端/需求与规范/用户需求基线.md`。
说明：建议按"学生价值 / 风险 / 成本"排序；与需求基线冲突的方案不列入。

## 一、回归结论（摘要）

- 覆盖：门户/登录注册、外壳导航、对话、画像、成绩、课表、报告、方向、阶段计划、今日行动、复盘、完成记录、待办、职业探索、工具、提醒、设置、指南、404、开发者页；桌面 1440/1024 + 移动 390/320；浅/深主题、键盘、axe、减少动效。
- 结果：**无 P0/P1 功能缺陷**；发现并修复 1 个 P2（双击发送撤回消息）、若干 P3（会话/展示/无障碍），以及能力缺口（对话内联网搜索未配置、任务/阶段删除缺失、经历追加覆盖、看报告不生成等）。
- 仍存限制：真实定时提醒触发、学信网正向核验、真机/读屏器、200% 缩放、部分长尾数据态未覆盖；这些已记录，不算"已通过"。

## 二、产品层建议（优先做"闭环与可信"）

### P0-1 把"一个建议 → 一件可执行的事 → 一次复盘"做成可见闭环
现状：报告/方向/计划/今日/复盘各自可用，但页面之间仍靠"去对话/去计划"的文字引导；计划生成曾出现 >90 秒才可见。
建议：
- 每个资产页固定一个"下一步"动作条：报告→选方向、方向→排计划、计划→今日、今日→复盘、复盘→调整计划；动作写成具体对象（"把「投递 8 份」放到本周"），不是泛化"继续咨询"。
- 长生成任务（报告/计划）改为**异步任务 + 可见进度 + 完成后通知**，页面显示"生成中/预计/失败重试"，不在对话里干等。
- 验收：任一环节完成后 1 次点击可到下一环节；生成中刷新不丢；失败可重试且不重复生成。

### P0-2 统一"可信度语言"：来源、核验、覆盖度、范围排除
现状：画像完整度曾出现 1/1 与 4 项待补充矛盾；资料范围关闭后分析说"专业未填"；报告/画像对同一事实表述不一致。
建议：
- 建立全站统一口径：**已记录 / 待补充 / 待核对 / 已核验（record）/ 按你的资料范围未使用** 五类状态，每类有固定文案与颜色；任何页面不得把"未使用"写成"未填"。
- 报告/方向/计划页显示"本结论依据了哪些资料、哪些被排除、哪些待核验"，与画像页同源。
- 数据版本变化后：先标"待重新核对"，重算完成再替换；横幅只到重算完成时消失（本轮发现 V2 后横幅残留）。
- 验收：同一事实在画像/报告/计划三页文案一致；自动测试覆盖"关闭范围/缺字段/待核对"三种状态。

### P1-1 补齐"管理自己数据"的基本动作
现状：任务/阶段本轮才补删除；会话无法重命名/删除/搜索；计划无撤销。
建议：任务/阶段/待办/会话支持删除/撤销/恢复；危险操作二次确认；删除后关联（今日/提醒/成就）同步并提示影响范围；会话支持搜索、重命名、删除。
验收：删除后刷新不复活；关联页不残留；有撤销入口。

### P1-2 对话能力"可发现、可解释、可替代"
现状：对话内联网搜索未配置时用户只能得到"没有工具"；工具提议何时出现不稳定；理论卡/图表触发条件不透明。
建议：
- 对话能力面板（或"能做什么"浮层）：列出当前环境真实可用的能力（读画像/计划、学职平台、知识库、图表、进度卡），不可用的明确写"未接入"及原因/替代。
- 工具提议由服务端确定"何时值得提议"，并在回复里说明"为什么建议用这个"；用户拒绝后短期内不再重复。
- 验收：用户明确要求某能力时，要么执行，要么给出原因+替代；不得静默无反应或编造来源。

### P1-3 新用户第一公里
现状：注册→年级→主题→采集，路径清楚；但新账号大量空态，价值感慢。
建议：注册后给"3 分钟得到第一版画像/第一件事"的引导（可跳过）；空态统一包含"为什么空/下一步/示例"；完成后给一次"第一份报告/第一件事"的成就反馈。
验收：新账号 3 分钟内完成一次有产出的对话；空态点击率/完成率可观测。

### P2-1 提醒与节奏
现状：提醒中心可用，但真实定时触发/铃铛入口/去重仍有缺口。
建议：定时任务 worker + 时区/安静时段/频率上限；同一事件合并；未读铃铛常驻；提醒→对应页面锚点；逾期升级策略（温和）。
验收：到点必达（含刷新/离线后补发）；不重复轰炸；可一键延后/处理。

## 三、前端建议（结合需求基线 7/8/9/10/11/12/17/19/20）

### P0（体验硬伤，建议本轮后立即排）
1. **触控热区统一**：全站 36–42px 文本按钮、40px 输入/下拉、底部导航 39×48、行内链接 21px 高；按需求基线"手机端触控区域"要求，统一到 ≥44×44（视觉可不变，用 padding/伪元素扩大热区）。优先设置/指南/待办/职业探索。
2. **日期与数字口径统一**：`2026-10-18` / `2026年10月18日 04:11` / `10/18` / `10月18日` 混用；把握度 1.00 小数。建立 `formatDate/formatPercent` 单一实现，全站替换；相对时间（今天/昨天/3 天前）只用于近期。
3. **错误与加载状态统一**：错误文案去"后端/服务地址"等内部词（本轮已改主文案，需全量替换）；壳层与页面错误横幅去重；首屏白屏加骨架（本轮已加 index.html 提示，继续做应用内骨架）；所有异步区域 `aria-busy` + live 播报。
4. **标题/焦点/landmark**：路由标题已修；继续修 heading 层级（探索 h1→h3、报告 h1→h3）、SPA 路由切换焦点、重复 main/aside（本轮修 4 页，需全站复查）。

### P1（结构与一致性）
5. **状态可见性**：待核对/待重新核对/资料范围排除/失败/空态用同一套徽标+说明；已保存/已生成只在真实成功后出现；冲突提示保留"最新值 vs 你的输入"对照。
6. **页面"活"而不模板化**：按需求基线 8/12，减少"标题—说明—卡片—按钮"平铺；画像用关系/缺口组织、计划用时间/依赖组织、报告用阅读面；避免把对话卡片模板复制到全站。
7. **报告阅读与输出**：目录/锚点/打印样式/长文断点；图表提供文字替代与数据表；移动端单列阅读；导出文件名含时间与账号（本轮已做部分）。
8. **移动端浮层与遮挡**：铃铛/悬浮元素不得遮关键按钮（本轮修 390/320 指定页）；统一底部安全区、键盘弹起输入框可见、浮层最大高度与滚动。
9. **对话页**：历史会话搜索/重命名/删除；长会话摘要；消息失败/停止/中断三态统一；复制/导出会话；工具提议与确认条不重复出现；移动端输入区与阶段条密度。
10. **无障碍深化**：深色主题对比度全站扫描（本轮修 2 处，建议 CI 化）；focus-visible 全站；aria-prohibited/landmark/heading 规则纳入 CI；减少动效已达标，保持。

### P2（打磨）
11. 主题令牌化：颜色不要散落页面 CSS，统一 semantic token；深色/红色主题逐页回归。
12. 空态/错误态组件化：`EmptyState`/`StatusBanner` 覆盖所有页，文案由服务端/配置提供，避免各页自写。
13. 性能：路由懒加载已做；继续做图片/图标按需、长列表虚拟化/分页、请求去重与缓存（画像/计划/报告共用快照）、慢网骨架与超时提示。
14. 可观测前端：错误上报带 trace_id、页面/操作维度；关键漏斗（注册→首次对话→首份报告→首件完成）埋点（注意隐私与资料范围）。

## 四、后端/架构建议

### P0（可靠性与能力闭环）
1. **能力配置即健康检查**：工具/搜索/学信/模型 provider 未配置时，启动自检 + 管理端可见 + 对话明确降级；本轮"联网未接"应显示为"未启用"而不是模型才说没有。建议 `capabilities` 接口返回真实可用能力，前端对话能力面板同源。
2. **长任务异步化**：报告/计划生成改任务队列（带 job id、进度、超时、重试、幂等键），SSE/轮询只读进度；避免 >90s 对话阻塞与重复生成。验收：生成中刷新可恢复、失败可重试、并发不重复。
3. **单一事实源与版本图**：画像字段（source/version/updated_at）、报告/方向/计划版本、重算依赖图统一服务；任一上游变化 → 下游标"待重新核对"，重算后清标记（本轮 V2 横幅残留说明需要服务端状态机）。
4. **提醒调度器**：真实定时任务（时区、安静时段、频率、去重、补发、已读/稍后/已处理），与计划/情报/资料变化事件解耦；提供投递日志。
5. **删除/撤销语义**：任务/阶段/待办/会话删除要有软删/恢复窗口、关联清理（提醒/成就/今日）、审计；前端二次确认与结果一致。

### P1（数据与安全）
6. **并发与幂等**：所有写接口 expected_version/updated_at + 冲突 409/1003 中文对照；创建接口 client_request_id 幂等；排序加稳定 tie-break（id）避免 Windows 15ms 时间戳抖动。
7. **上传与内容安全**：2MB/文本类型限制之外，做 MIME sniffing、编码检测、恶意文本/提示注入隔离（材料内容作为数据，不作为指令）；PDF/Word 若不解析就明确不支持。
8. **权限与租户**：学生/开发者/管理员三档最小权限；服务间凭证不下发前端；越权返回 403 + 中文；开发者页与 API 分离（本轮学生 403 正常）。
9. **PII 与日志**：日志/trace 不落密码、token、完整材料正文；导出/删除数据可审计；隐私说明与资料范围一致。
10. **可观测性**：指标（对话首字/完成耗时、生成失败率、工具成功率、提醒投递率、报告重算时长）、告警、trace_id 贯穿；给运营一个"学生卡在哪"的漏斗。

### P2（AI 质量与成本）
11. **证据与引用约束**：报告/画像/方向每条判断可追溯到字段/材料/公开来源；无来源写"待核对"；禁止虚构学信/岗位/薪资；已有 evidence_constraints 继续加强并用评测集守。
12. **评测集与回归**：建立 50–100 条真实学生问题集（含边界：假设、否定、冲突、资料范围、无工具），每次 prompt/模型变更跑评测（事实一致率、引用率、幻觉率、时长/成本）。
13. **Prompt/模型路由版本化**：prompt 与模型路由可回滚；按任务复杂度选模型，控制成本；生成失败降级到"可读的兜底"而非空回复。
14. **契约与测试**：OpenAPI 快照 + 前端 operations 清单已守；新增 DELETE/批量接口同步；补 E2E（注册→报告→计划→复盘）与 API 集成测试；CI 加 axe/对比度/触控检查。

## 六、验收与度量

- 功能：全站清单逐项 PASS（本轮台账）；新增能力必须有真实页面证据，不以构建/单测代替。
- 质量：axe serious=0（浅/深）；触控 <44 占比 <5%；日期/数字格式 100% 统一；错误文案 0 内部词；首屏 LCP/可交互在慢网有骨架。
- 业务：新用户 3 分钟首个产出率、报告→方向→计划转化率、任务完成率、复盘率、提醒到达率/处理率、生成失败率与重试成功率。
- 可靠性：写接口冲突可感知、重试幂等、删除可恢复、长任务可恢复；告警覆盖生成/工具/提醒。

## 七、不建议做的事

- 不要为了"看起来智能"编造联网结果、匹配分、来源或核验状态（需求基线 15/17/18 明确禁止）。
- 不要把对话卡片模板复制到全站（基线 12），也不要把所有页做成文章阅读器（基线 8）。
- 不要在没有配置搜索/学信服务时对用户宣称已具备该能力；应显示"未启用+替代"。
- 不要用演示数据填补空态/失败态（基线 18）；不要以构建成功代替真实页面验收（基线 20）。
