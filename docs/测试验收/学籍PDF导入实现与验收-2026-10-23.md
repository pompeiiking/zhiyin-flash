# 学籍 PDF 导入：实现与验收

实现位置：在 `zhiyin-profile` 工作目录基于 `个人画像重构` 的 `6b7fb6b` 实施，现整理到独立分支 `学籍信息pdf导入`。本地 Docker 已部署，正式服务器未部署本功能。原 `zhiyin-flash` 工作目录的分支和未提交修改保留。

## 已实现的行为

- 个人画像“学籍信息”卡片提供“核验或导入学籍”，弹层并列保留在线验证码与 PDF 导入。
- PDF 路径为选择文件、解析预览、逐项选择、本人归属确认（缺少可比对身份时）、确认导入、刷新画像。刷新失败保留成功回执，可单独重试读取。
- HTML 与 PDF 共用 `EnrollmentReportService` 的身份检查、动态字段白名单、年级推算及画像写入参数。在线请求和 HTML 错误页处理仍由原网关负责。
- PDF 由 pypdf 在可终止子进程读取，文件上限 2,000,000 字节、3 页、50,000 字符、10 秒；Linux 另限子进程内存与 CPU。拒绝损坏、加密、无文字层、错误报告类型和关键字段缺失。
- 仅支持中文版《教育部学籍在线验证报告》文字 PDF。标题、姓名、学校、专业必须可识别；不调用模型补字段。PDF 标签识别增加边界约束，避免将“测试职业学校”名称中的“学校”截为标签。
- 姓名或学号明显冲突阻止整份导入。过期报告仍可查看解析预览，但不能确认；无法识别有效期则明确提示，允许作为未核验材料导入。
- 缺失项默认选中；不同值默认保留，用户逐项选择；相同值跳过。已有 verified 字段不可由 PDF 覆盖，本人填写年级不被推算覆盖。
- PDF 直接字段使用 source=record、verification=record，推算年级使用 pending。兼容 confidence 沿用既有材料记录规则，前端已核验标记必须同时满足 verified 与学信网在线来源，分数不代表在线核验。
- 在线获取报告的 HTTP 403 改为具体的拒绝访问提示，并提示 PDF 导入；错误消息不含验证码。

## 接口和持久化

`POST /api/v1/app/chsi/pdf/preview` 接收 multipart 的 `file`，鉴权后返回 `preview_id`、`expires_at`、报告日期、有效期、警告、可导入状态和字段新旧值。每项包含 selectable、selected 和 reason。

`POST /api/v1/app/chsi/pdf/confirm` 接收：

```json
{
  "preview_id": "chsi-pdf-…",
  "selected_keys": ["school", "major"],
  "ownership_confirmed": true
}
```

确认接口拒绝额外字段和客户端提供的报告值，只使用服务端保存的解析结果。返回导入标识、时间、导入/保留/跳过的字段键及回执。重复确认返回同一回执。

新增 `biz_chsi_pdf_import` 表，进入现有 `SCHEMA_SQL` 路径；同时提供内存仓储。预览绑定用户、30 分钟有效；确认时使用账号锁、记录行锁和画像版本检查，同一事务写入全部所选字段与回执。跨实例使用同一 PostgreSQL 锁，证据评估在提交后安排。

`chsi_import_cleanup` Worker 按既有 Worker 驱动周期删除过期 pending 预览；成功记录保留摘要和幂等回执。部署时必须运行后台 Worker，不能仅启动禁用后台任务的 API。

原 PDF 和完整提取文本不持久化，UploadFile 临时文件关闭；身份证号、照片、验证码不进入预览存储。预览仅保留规范字段与版本快照；确认成功即清空 payload，回执只保留字段键，避免保留被删除字段的值副本。来源引用使用导入 ID。

已同步 OpenAPI、前端生成类型、接口调用注册、装配及归属登记。现有 nginx 4m 上传限制足够容纳该接口的 2MB 文件，无需放宽。

## 验证结果

- 学籍、API 鉴权、画像写入、证据评估、装配、接口契约及骨架登记回归：110 项通过；随后新增了表格标签边界及 HTTP 403 专项用例，PDF 专项最新 17 项通过。
- 扩展回归覆盖分层依赖、画像历史与更正、教务导入、读缓存：通过。普通材料上传 22 项全部通过，确认普通 PDF 上传仍按原规则拒绝，没有被学籍入口全局放开。
- 使用本机一次性 pgvector/pgvector:pg16 容器、两个独立数据库连接池，实测同一预览并发确认只写入一次；第二项写入失败时整批字段与回执回滚。测试数据库与正式服务器完全独立，两个实例先完成 schema 初始化再接受请求。
- `npm test`：127 项通过；`npm run check:backend`：通过，93 个调用与契约匹配；`npm run build`：通过。保留既有 system-data 静态/动态导入提示，无构建失败。
- 真实 Edge 无头浏览器、1440×1000 桌面和 390×844 手机视口：在生产使用的 InfoSheet 弹层中挂载生产组件，走真实上传接口、子进程解析、导入服务和画像刷新；上传、预览、本人确认、导入、刷新及无效文件提示通过。无横向溢出、无页面脚本异常。身份与工作台聚合使用明确的本机隔离验收实现，未连接生产。
- 本地浏览器证据：`.runtime/browser-results.json`、`.runtime/desktop-preview.png`、`.runtime/mobile-preview.png`，均为合成报告。
- `git diff --check`：通过。

测试环境使用 Python 3.12。系统 Python 3.10 低于项目要求，不用于最终回归；Windows 普通上传测试使用专用短路径临时目录，避开现有路径长度限制。
