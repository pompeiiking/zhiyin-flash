# 后端专项审查与修复（2026-10-20）

## 结论与范围

人工智能专业职业检索问题暴露的不只是一个检索词问题：后端还存在上游失败被吞掉、状态读取不一致、缓存边界、导入部分提交及后台并发问题。本轮对这些已确认问题实施修复，并增加可复现的回归测试。

此前将局部代码阅读和测试通过表述成“完整看过后端”，不准确。本报告明确区分四种证据：

1. **全包清点和静态检查**：8 个后端 Python 包、273 个源码文件、125 个控制器路由；建立 AST/编译与入口清单。清单不是逐行审查证明，也不是所有路由的线上验证。
2. **关键调用链审查**：认证和当前账号解析、会话运行与审批、画像/材料归属、数据源与检索、学业导入、资产/工作台读写、开发者/模块权限、缓存、事件总线与调度、PostgreSQL 事务。重点读实际读写和异常分支，未逐行覆盖全部源码。
3. **确定性回归**：运行整个后端 pytest 测试集及 Ruff，新增故障、并发、账号边界与迁移测试。既有用例可能使用内存仓库和模拟上游，不能代替真实部署验收。
4. **真实 PostgreSQL 验证**：使用隔离的合成标识，验证事务回滚、outbox 一致性、导入并发和两个调度器抢占。仅清理精确生成的测试 ID，不读写真实学生材料，不执行真实到期任务。

完整文件和路由清点见同目录 `后端审查清单-2026-10-20.json`；验证结果见 `后端审查证据-2026-10-20.json`。

## 兼容与部署约束

旧材料不会直接按有碰撞风险的旧路径返回。新路径不存在时，用原材料 ID 中绑定账号、文件名及原始字节的 SHA-256 验证归属；验证成功才迁移到新命名空间。支持常见 UTF-8、GBK/GB18030、UTF-16 文本编码重建。无法验证的历史格式保留原文件，需要重新上传，不能为了兼容绕过归属检查。

历史导出通过当前账号状态中记录的确切对象键下载，不盲目猜测旧目录。此次无数据表重置、无真实学生记录批量迁移。

内存仓库的锁保证同账号串行，不提供多个仓库之间的持久事务回滚；生产 PostgreSQL 装配才具有本轮验证的快照、画像、outbox 原子性。

## 尚未关闭的风险与优化项

这些是边界或后续优化，不伪装成已复现并修复的缺陷：

1. 上游外层总超时仍可能取消整次学职取数；同一阶段中某条详情失败仍会结束该阶段剩余条目。后续可按条目隔离并设置时间预算。
2. 失败的情报结果仍按现有 TTL 缓存；重试可强制 refresh，后续应给失败设置更短 TTL，同时限制请求风暴。
3. 画像变化与正在执行的情报请求交错，仍应增加缓存代际校验，避免失效后被旧请求重新填充。此次解决键边界，不宣称解决全部缓存一致性。
4. 依赖未完全锁版本，Docker 源码变更触发重新下载全部依赖，构建慢且可重复性不足。建议锁依赖、分层缓存依赖与业务源码。
5. 尚未对全部 125 个路由进行真实账号矩阵、恶意输入、跨实例故障注入与压力测试；现有权限回归与关键调用链审查不等于完整渗透测试。
6. 当前没有为真实模型多轮对话质量建立足够规模的持续评测。关键词回退清理、资料真实性、拒绝多问、简短回答、自然追问，需要持续样本回归，单次模型验收不能保证长期稳定。
7. 本轮调度验证针对 PostgreSQL outbox 同事务装配；替换为外部非事务 broker 后，需要重新设计投递幂等与失败恢复。进程内去重账本也不能覆盖外层事务回滚和跨实例永久去重。
8. 没有使用真实学籍验证码、真实学生附件和外部写入服务做破坏性验收；这些接口的真实生产联调仍需专用测试数据。
