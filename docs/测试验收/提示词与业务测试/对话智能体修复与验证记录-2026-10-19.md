# 对话智能体修复与验证记录

日期：2026-10-19。工作分支：`前端重构版`。依据：[63 项审计清单](智能体对话机制与问题审计-2026-10-19.md)。用户已授权修复并推送；本轮保留并整合了工作区原有的相关修改，没有改动选定页面布局，也没有重启或部署现有服务。

## 本轮结果

正常咨询使用独立的 `ConversationOutput` 契约，不再强制填诊断 SWOT 或整份计划；五阶段继续服务于业务状态和明确的成果生成。最近最多 24 条完整消息按 24000 字符总预算进入模型，使用原生 user/assistant 消息角色。用户明确的持续约束可经原话核验保存到当前会话，超出近期历史后仍可取回；跨话题累计摘要不再直接注入模型。

核心已复现故障已增加回归并修复：敏感信息先存后拒、否定专业更正、否定年级倒置、system 消息导致后续回答丢失、同请求并发执行、分句任务状态错误、多项任务部分失败反馈错误、任务操作吞掉追问、旧提议/旧按钮触发写入、提醒文案覆盖真实生成结果。

## 具体变更

### 对话与上下文

- 保留段落、解释、列表与用户指定的回答长度；普通回复可以没有追问。
- 取消普通咨询的阶段角色禁令和阶段成果契约；报告/计划/方向生成保留专用契约和真实保存回执。
- 近期历史使用原生消息角色，避免把历史都塞成一条用户 JSON。上下文中去掉重复画像和全部会话摘要。
- 记录当前时间及用户时区；纠正已有阶段日期星期换算中的年份选择问题。
- 本轮新事实在成果生成前进行证据绑定的提取；普通阶段均可返回字段更新，不再依赖少量“我喜欢/我做过”关键词才记录。
- 会话约束记忆必须逐字引用本轮用户消息，并且值包含在证据原文中；模型不能凭空增加用户偏好。
- 材料 ID 绑定到轮次，新增 `material.read` 片段读取工具，可在续问时读取当前会话已上传材料，并复查资料偏好。

### 授权、真实操作与恢复

- 敏感信息在模型调用和原文存储前拦截；材料正文、文件名同样检查。旧历史和工具资料在模型边界脱敏，保留用户原始档案。
- 正常的“直接生成”“先生成”不再等同于注入或否定；生成授权从剔除引用/第三方转述后的用户指令读取。
- 画像更正检查否定与假设；项目经历允许较长文本，普通字段保留短值限制。
- 历史契约支持 system 消息；持久化完整 `TurnResult`，重试恢复引导、告知、来源和资产状态。
- 没带客户端请求 ID 时分配服务端 ID，避免相同文字的连续新消息被静默去重。
- 每账号在进程内串行，PostgreSQL advisory lock 进一步串行跨进程对话；重复 ID 同时校验会话和请求摘要。
- 任务操作按分句分别定位与执行；明确报告已成功、原本无需修改和保存失败的项目，保留部分成功状态。
- 任务状态已处理后，带回执继续回答“下一步怎么做”，不吞掉问题。
- 提议与当前轮次绑定；切换话题后旧提议不再复活。新按钮携带提议标识，旧按钮不能确认新提议。为已有客户端保留字符串选项值的兼容路径。
- 读取报告/计划不再自动等同于确认创建；空计划的进度提议可通过口头“可以”继续。
- PostgreSQL 内容、版本/快照、outbox 事件采用同一事务；计划和日历节点也在同一原子写入范围。嵌套事务使用同一连接，工具并行查询在固定连接上串行执行。
- 关闭 SSE 仅停止接收，本轮已授权操作继续在时限内完成并保存，避免在写入和回执之间被取消。
- 展示快照保存失败不再把已成功的业务请求报告为失败；完整历史回包支持重放。

### 工具、事实与运行边界

- 联网能力提示依据实际挂载工具，不再根据已移除的只读确认提议判断。
- 工具只读与业务保存不再整轮互斥；字段仍须经过本轮原话证据校验。
- 模块卡片可以附带有效回答；没有真实回执的写入宣称及不存在的任务卡仍被拦截。
- 检索工具保留条目 ID、来源、时间和评分，并把真实来源回传到回复来源卡。
- 外部来源采用实际取回的片段，不再让后置模型用“URL 存在”冒充对具体断言的核验。
- 知识库向量检索异常时保留关键词结果；本地占位嵌入不参与语义检索。
- 格式修复禁用工具，避免重新执行副作用；修复保留原始任务上下文。
- 每次运行复制 Agent 原型，隔离 Agno 的可变运行状态；模型路由变化后更新运行时及缓存。
- 输入和材料合计受长度限制；模型输出和工具调用次数设上限，本轮执行设统一 150 秒时限。
- 修复生成前端类型的脚本漏掉能力清单类型的问题；类型来源于真实 OpenAPI，不再依靠手工追加。

## 明确保留的优化与验证边界

63 项清单包含架构建议及条件风险，不等于 63 个独立缺陷全部被证明消除。本轮重点是恢复可用交流和修正可复现的一致性故障，以下仍保留：

1. **语义路由与动作规划**：关键词和部分阶段推进规则仍在。普通回答已与阶段脱钩，但尚未整体替换成模型规划的统一动作状态机。对应审计 11–13、15、25、31。
2. **更复杂的指代与更正**：“第 N 项”仍主要指现有计划顺序；复杂跨列表指代、多人引述和多层否定需继续扩充语义验收，不能声称任意自然语言都能正确执行。
3. **完整执行日志与并发冲突**：跨进程串行及完整回包重放已实现；进程崩溃或原文保存失败后的逐动作恢复、与其他页面并发重排的版本校验仍需更细粒度执行日志。事务保护不等于所有故障模式下严格 exactly-once。
4. **流式体验**：当前对话正文先完成校验和真实操作，再发布结果；SSE 保留进度及心跳。这样避免先展示未经确认的写入宣称，但逐字正文的首字延迟需要后续拆分独立文本通道来改善。对应审计 42、58。
5. **证据语义与检索质量**：逐字证据绑定、来源回传、去除全局词语替换已落地；断言是否被证据真正蕴含、实时招聘覆盖、语义检索召回质量还需专门评测。对应审计 24、43、47、50–52。
6. **容量与界面联调**：没有做多人高并发压测、真实手机软键盘测试或更新后的部署页面全站验收；缓存仍有部分 namespace 级失效。当前运行容器未更新，不把本机隔离验证冒充部署验收。

上线时由正常启动迁移为逐轮消息增加 `metadata` JSONB 列；无需清空数据库或重导用户资料。代码推送后需更新部署，现有运行服务不会自动读取工作区代码。
