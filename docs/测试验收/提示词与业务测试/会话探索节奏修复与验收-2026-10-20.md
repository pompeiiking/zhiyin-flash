# 会话探索节奏修复与验收

日期：2026-10-20。问题样本：用户回答“调bug”“搞清楚为什么错”后，助手过早推断岗位，再布置积累经历的任务，当前对话难以继续。

## 修改

1. 在既有账号/会话运行记录中增加有界探索工作快照，记录目标、模式、用户原话、假设、已谈主题、开放问题和下一个重点。`workspace.exploration` 复用主模型原生工具循环，不新增独立分类模型；探索中可能增加一次工具往返。原有补充记忆提取仍存在。
2. 用户陈述携带消息 ID 与逐字原话，校验本会话、当前账号、有效历史及长度。助手判断不能充当用户来源。假设与原话分开，探索工作快照不直接写长期画像或资产，也不授予权限。
3. 更新先暂存，仅成功且未取消的回复提交；重置记忆、遗忘范围、临时会话设置变化时旧快照失效，新会话不继承旧快照。
4. 当前用户原文单独置于模型输入末尾，避免埋在大型上下文 JSON 中。历史和工作线索保持低可信资料，不变成系统指令。
5. 重写主对话及职业顾问、画像分析师的探索职责，补充规划师接手条件，替换旧的“小尝试也算推进”默认收尾口径。依据当前模式返回短回应节奏约束，不强制固定问句、问号或追问轮数。
6. 修复原有补充记忆只看最近四条消息的问题：传入更多近期原文、有来源的会话工作线索和记忆控制；禁止因为换题、更正而忘掉本会话“不保存长期画像”的限制。主记忆提示词同步更新。测试脚本对拒绝保存却仍产生画像/计划的样本明确报失败。

设计同步见《对话系统重构设计》第2.1、2.2节。本次仅改后端、资源和验证文档，没有改前端页面。

## 确定性验证

新增15项回归，覆盖短回答跨轮承接、重复请求不重复更新、助手/其他会话/其他账号/编造来源拒绝、无效或取消回复不提交、三种隐私变化失效、新会话隔离、普通回答无强制记录、大小限制、真实工具参数 schema、用户消息优先级及记忆提取上下文传递。

全量后端测试 **1097 passed**，1项既有 Starlette TestClient/httpx 弃用提醒；Ruff 和差异空白检查通过。脚本模型只验证状态和边界，不用于证明自然交流质量。

## 真实模型验证

使用本机已配置模型 `deepseek-chat`，真实调用、合成内存用户和会话，只读取模型配置，不操作真实学生记录。运行 `scripts/accept_dialogue_continuity.py --suite exploration`，保留每轮回复、工具事件、状态快照和资产/画像检查。

最终样本为7个独立会话、13轮回复：两组“调bug→想弄清原因→具体经历→感受”各3轮；想不起例子和明确不再追问2轮；转向社团选择2轮；暂停、单句事实、否定与转述更正各1轮。

- 两组调试体验交流没有把单个偏好匹配到岗位，也没有要求先完成练习再来；顺着具体经历继续了解其他兴趣场景。
- “想不起例子”改用具体场景；用户明确不再追问后，本轮只反馈与解释，没有追加问题或任务前置条件。
- 换题后转向社团目标和社交偏好，没有继续追代码；暂停、单句事实和更正场景遵循当前诉求。
- 10轮探索产生工作快照；3轮直接回答/暂停/更正未强制调用记录工具。13轮均未写长期画像或计划。

中间测试发现工具 `text/quote` 参数不一致，改为明确的 Pydantic 来源结构并补 schema 测试；另发现补充记忆忽略较早的禁止保存要求，修正上下文和记忆提示后重跑。中间失败不能计入最终通过样本。

本轮人工审阅仍看到个别多余评价、二选一问法及未经用户证实的技术细节推测。当前解决了本样本中的任务式收尾、过早岗位归因、工作上下文缺失及记忆限制丢失；不宣称模型的全部语言质量已稳定。后续应持续加入真实匿名多轮样本，不能只检查句尾有没有问号。
