# 个人画像设计实施与检查记录

日期：2026-10-20。依据：[个人画像设计（2026-10-20）](../../产品与架构/个人画像设计-2026-10-20.md)（下称“设计”）。

本文记录**实际改了哪些代码、验证到什么程度、哪些还没完成**。它不是设计通过记录：真实模型、真实 PostgreSQL 迁移与正式前端浏览器验收仍未完成。本轮**未推送、未部署**。

## 1. 实施范围（两轮）

### 1.1 记录结构与消费契约（设计第 2、4、8 节）

- `zhiyin-kernel/zhiyin_kernel/enums.py`：新增 `ProfileEntryType`（学习背景/兴趣/经历/能力/职业关注/价值取向/现实条件/补充信息）、`ProfileEntryStatus`、`ProfileVerification`、`ProfilePurpose`、`ProfileClueStatus`。
- `zhiyin-kernel/zhiyin_kernel/blackboard.py`：`ProfileField` 增加类别、类型属性、核实状态、状态、原话引用、有效范围、事件时间、条目版本、替代关系；`Profile` 增加 `clues`；新增 `ProfileClue`（系统理解，与事实分开）。
- `zhiyin-kernel/zhiyin_kernel/profile_taxonomy.py`：受控词表 —— 键 → 类别、来源 → 默认核实状态、各类型长度/条数、类型专属属性、五种用途 → 可读类别。
- 画像写入服务：按类型校验取值与属性，不再统一 40 字（经历 12000、兴趣最多 8 条、短事实 40）；写入时固化类别/核实状态/原话引用/版本；更正后清掉旧属性并使相关线索失效。
- 数据层：`biz_profile_field` 新增列（幂等补丁），新增 `biz_profile_clue` 表；PostgreSQL 与内存仓储同步；旧库缺列/缺表按默认值降级，不因迁移未跑而 500。
- 返回契约：`ProfileFieldView` 下发类别/核实状态/属性/来源引用/时间/版本；`ProfilePanelView` 下发 `clues`；OpenAPI 快照与前端类型已重新生成。

### 1.2 取数与用途读取（设计第 8 节、第 10 节第 1 步）

- 学职网关：专业检索独立；职业检索只认明确职业关注，普通兴趣/价值取向/补充描述一律不进入；职业优先官方专业映射，没有才名称检索；返回 `details`（专业词/职业词、专业/职业/案例各自计数、官方映射与名称检索分别计数）。
- 情报主题只从专业或明确职业关注推出；取数状态按专业/职业/案例分别报数，职业 0 条时明确“不代表平台没有收录”。
- 用途视图接入消费方：
  - AI 任务提示词按任务用途过滤（`portrait.analysis` / `report.summary` / `match.careers` → 方向推荐；`day.advice` / `plan.todos` / `plan.timetable` → 制定计划；`gap` / `academic.analysis` → 普通交流），不再整份画像塞提示词，也不再输出内部 confidence。
  - `profile.read` 工具按普通交流用途过滤，去掉“把握 0.xx”，显示类别/核实状态/来源。
  - 分析访问先过滤冲突/过期/撤回，再按方向推荐用途过滤，再走原有来源权限。

### 1.3 写入链路（设计第 3.1、4、5.1、10 节）

- 对话 `workspace.action` 的 `profile.update` 现在接收并校验：`attributes`（类型专属受控属性）、`assertion_type`、`valid_from` / `valid_to` / `event_at`（带时区 ISO，未知不补当前时间）、`save_scope=single`。
- 服务端生成 `origin_ref`（`conversation:{会话}:{本轮消息}`），不再只依赖一段可被改写的文字证据。
- 引述/假设/不确定（非肯定自述、非明确更正）不能通过自动记忆写成本人事实；类型属性取值受控，未知属性直接拒绝。
- 长度口径统一到词表：对话预检不再另设 2000 字上限，长经历可以写入。

### 1.4 待验证线索与用户控制（设计第 3.2、7、9 节）

- 新增 `biz_profile_clue`：`id/user_id/session_id/text/evidence/field_keys/source/status/invalidated_reason/created_at/updated_at`。
- 对话探索的 `hypotheses` 在保存探索快照时落为线索（同一会话整体替换，不重复累加），依据取本会话用户原话；隐私重置/删除记忆时清理本会话线索。
- 用户更正或删除画像字段时，`field_keys` 命中的线索自动失效并写原因；用户可在画像页“不是这样”否认一条系统理解。
- 画像页新增“删除这条”入口（服务端版本校验、缓存失效、资产影响传播）；新增两条 REST：`DELETE /app/profile/fields/{key}`、`DELETE /app/profile/clues/{clue_id}`。

### 1.5 记忆策略（设计第 5.2 节）

- 新增 `MemoryPolicyService`：在 `biz_student_state.payload` 持久化 `record_policies`（scope=account/session/content/single、target、value、source、note、session_id、created_at），并同步既有三档兼容字段。
- 账号级关闭、会话级临时、按键/按内容拒绝、只保存一条：都有服务端读取入口 `check_auto_write`，对话运行时在自动写入前统一调用；不依赖提示词或最近几条消息。
- “只保存这一条”：`authorization=explicit` + `save_scope=single` 记录一次性授权；其他自动记录继续关闭，不会恢复全局自动记忆。
- 偏好保存与临时会话设置现在同时写一条带来源与时间的策略记录。

### 1.6 补充信息与旧数据迁移（设计第 6、10 节、P28）

- `copies.json` 增加 `profile.field.supplement`（补充信息）与 `profile.field.supplement_info`（补充说明），两键进入允许写入的画像词表；无法归类的信息有合法落点。
- 新增 `scripts/migrate_profile_entries.py`：默认 dry-run，`--apply` 回填老数据的类别/核实状态/状态；按词表推导、已有合法值不覆盖、可重复执行；输出分类计数与样例。

### 1.7 展示（设计第 9 节）

- 画像页按三种内容组织：**你提供的信息 / 系统基于证据的理解 / 近期补充与变化**；线索块单独展示、可“不是这样”。
- 每条显示内容类别与核实状态；不再展示“整体可信度”百分比与内部置信度条；资料概览改为“已记录资料”，待补充文案改为“可以补充，不影响继续交流”。
- 新增删除入口，沿用原有更正、来源与判断关联展示；对话右侧摘要与导航未改。

### 1.8 历史版本、冲突并存与旧读接口投影（设计第 4、7 节、P12、P29）

- 新增 `biz_profile_field_revision`（只追加）：每次当前值被替代时，旧值进历史（`superseded`）；删除时留一条 `withdrawn` 历史；每条带来源、核实状态、原话引用、有效范围、版本、替代时刻与原因。
- **当前值仍由 `biz_profile_field` 一行一键承载**：`GET /app/workspace`、画像更正/删除等旧读接口的返回结构不变，历史表只是旁路（旧 API 兼容投影）。
- 自动记忆遇到与当前值不一致、且不是明确更正的新说法时，不再拒写或覆盖：记为 `conflict` 提案，当前值保持不变，冲突单独出现在 `profile_panel.conflicts` 中等待裁定。
- 新增 `GET /app/profile/fields/{key}/history`（历史回读）与 `POST /app/profile/conflicts/{revision_id}`（`choice=revision` 以新说法为准 / `current` 保留当前记录）；裁定为新说法时走统一写入服务、失效缓存并标记上下游资产待核对。
- 画像页新增“有两种说法待核对”块：并列展示当前记录与新说法，两个按钮完成裁定。

### 1.9 线索依据字段与自动记录范围（设计第 3.2、5.2 节）

- 线索的 `field_keys` 不再为空：保存探索快照时，取本会话真实写入画像的字段（按服务端固化的 `origin_ref` 前缀识别）作为依据字段，不靠关键词猜。
- 图片画像页“系统基于证据的理解”可展示 3 条真实线索；桌面与手机截图见文末证据。
- `conversation.memory` 提取增加 `policy` 输出：用户本轮明确提出的记录范围（账号关闭/恢复、临时会话、内容拒绝、字段拒绝、只保存一条）由模型按语义识别，服务端落入 `record_policies`；没有要求时 `scope=none`。
- 自动事实提取在“自动记忆关闭/临时会话”时仍会运行策略识别，但不写事实。

## 4. 仍未完成的部分与原因

1. **并发、事务与导入（P23–P26）**：真实库迁移已执行，但跨账号并发写、事务冲突、导入与后台入口仍未针对新字段逐项复验。
2. **结构化真实模型评测（P31）**：真实模型多轮中已观察到反馈与探索交替、未强制盘问，但没有固定样本与评分表，不能算评测通过。
3. **删除入口的浏览器点击（P32）**：线索、冲突、删除接口与页面入口都已接入；冲突裁定已在桌面/手机点击验证，删除按钮还没有专项点击验证。
4. **旧兴趣/职业关注别名逐项拆分（P28）**：真实库回填与历史基线已做，别名值本身（例如旧 `career_interest`）没有按“了解/考虑/已选”拆分迁移。
5. **线索重新分析触发（P21）**：依据字段失效已有测试；线索失效后何时重新分析、如何避免用重复次数把推测变成结论，仍没有自动触发流程。
6. **账号级关闭/恢复、回复失败与重启后的策略行为（P13–P18）**：真实模型已验证会话拒绝、内容拒绝与只保存一条；账号级开关与失败/重启场景仍待专项复测。
7. **回滚演练**：已保留 `zhiyin-flash:before-profile-20261020` / `zhiyin-flash-web:before-profile-20261020` 镜像和迁移前 profile 表备份，但没有实际执行回滚。

## 5. 结论

两轮改造（含历史/冲突、真实环境补齐）已经把设计的“记录结构 + 消费契约 + 用户控制”主干落地：写入有类别/核实状态/原话引用/版本，读取按用途取词，专业与职业分离，兴趣不冒充职业；线索与事实分开、可否认、带依据字段；记忆策略持久化并由服务端执行；补充信息有落点；旧数据已真实库回填并建历史基线；旧值进历史、冲突并存并由用户裁定；桌面与手机浏览器及真实模型的关键路径已验证。32 项中本地可判定为 **10 项已通过、17 项部分完成、4 项需真实环境、1 项未改**。**并发/事务/导入、结构化真实模型评测、删除按钮专项、别名拆分和回滚演练仍是明确缺口，不能把本文当作全量验收通过记录。**
