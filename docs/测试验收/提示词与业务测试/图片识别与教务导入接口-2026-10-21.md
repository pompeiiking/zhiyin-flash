# 图片识别与课表、成绩共享导入接口

日期：2026-10-21。分支：`个人画像重构`。

状态：代码、自动化接口测试、真实 DeepSeek 图片识别、当前 Docker 部署及桌面/手机基础流程已验证。复杂学校版式和手机真机触控不属于本次全部覆盖的范围。

## 根因与处理

原链路将材料统一视为文字：前端拒绝图片，HTTP 上传再次拒绝，材料服务仅调用文字提取，主对话最后一条消息也只包含字符串。因此，单改提示词或增加 OCR 无法提供视觉理解。

本次增加真实 `image_url` 输入：图片经格式与尺寸验证、方向归一和 EXIF 清除后，保存在用户命名空间的材料信封中。给前端和会话历史的仍然只有材料编号、名字等信息；图片字节不进入会话正文、提示词变量、长期画像或操作账本。主模型当前轮可以直接分析图片及表格布局。

DeepSeek 官方视觉能力文档明确使用 `deepseek-flash`：[Vision](https://api-docs.deepseek.com/guides/vision/)。本机环境文件仍保留旧的文字模型名称 `deepseek-chat`；不能将该名称直接当作图片能力配置。本次将图片选型独立处理：

- 默认情况下，DeepSeek 官方地址的图片请求使用 `deepseek-flash`，文字请求继续使用原有文字模型。
- `ZHIYIN_LLM_VISION_MODEL` 可显式指定图片模型；兼容服务未指定时沿用当前模型。
- 图片对话和教务识别共用上述配置及当前路由的地址、密钥。不会发送给另一家未配置的供应商。
- 不支持视觉、超时或返回格式不完整时，明确报识别失败，不降级伪装成识别成功，不写入数据。

## 页面、对话共用的流程

1. 上传材料；图片最大 2MB，支持 PNG、JPEG、静态 GIF、WebP。实际内容必须可解码；最大 1600 万像素、单边不超过 8192 像素。动图不悄悄只读第一帧。
2. 提交识别/解析请求，返回逐条预览、警告、学校、学期、当前将替换的记录数和有效期。此阶段只读，不改变课表、成绩或画像摘要。
3. 用户核对完整列表，可打开普通表单逐条修改课程、时间、地点或成绩，不向学生展示识别结果 JSON。修改会清空旧预览编号，必须重新核对生成新预览后才能确认保存。最多 200 条，不再只展示前 20 条而隐藏其余待保存记录。
4. 确认时仅提交真实 `preview_id`，不接受客户端重写预览正文。保存复用既有学业导入服务，更新对应画像摘要并使相关缓存失效。
5. 课表只替换课表，成绩只替换成绩，另一类保留。新增或局部修改时，AI 必须先读取现有课表，构造包含保留课程的完整目标预览。

当前接口是“替换当前该类记录”，不是自动跨学期合并。UI 和审批卡明确展示替换范围；不自动猜测用户想保留哪些旧记录。

## 接口

所有接口沿用现有身份认证，服务端从令牌解析用户，不接受请求体自报账号。

| 接口 | 用途 | 是否修改正式数据 |
| --- | --- | --- |
| `POST /api/v1/app/conversation/material` | 上传文字或图片，返回材料编号 | 仅存材料，不改课表、成绩 |
| `POST /api/v1/app/academic/preview` | 图片识别或文字解析，返回完整替换预览 | 否 |
| `POST /api/v1/app/academic/preview/commit` | 保存已核对预览 | 是，用户确认后调用 |

预览请求示例：

```json
{
  "kind": "courses",
  "material_id": "上传接口返回的真实编号",
  "school": "学校名称",
  "term": "2026-2027-1"
}
```

`kind` 为 `courses` 或 `grades`。`material_id` 和 `text` 二选一；文字入口支持原有导出格式。学校、学期无法确定时先询问，不能编造。

提交确认示例：

```json
{"preview_id": "预览接口返回的真实编号"}
```

旧文字导入接口保留兼容；本次正式导入浮层改用上述共享预览、确认链路。

## 智能体工具与授权

- `academic.preview`（原生函数名 `preview_academic`）识别当前轮已上传材料或解析目标表格，无需审批。图片必须属于当前用户，且在本轮材料清单中；遵守材料/学业资料使用范围。
- `workspace.action(operation="academic.import", payload={preview_id: ...})` 创建具体审批。即使模型使用 `automatic` 或 `explicit`，也只能生成提案，不会直接保存。
- 正式执行仍走已有持久化审批账本，用户确认真实 `action_id` 后执行已保存的具体内容。图片、历史记录及工具返回的指令不能充当用户授权。
- 审批卡展示学校、学期、完整课程或成绩列表、替换数量和警告。工具状态展示“正在识别课表或成绩”，保存时展示实际操作状态。
- 重复确认由原审批账本处理。单独重复提交同一已应用预览会因版本变化被拒绝，不重复覆盖数据；响应丢失时应先重新读取当前记录核对。

## 一致性与安全边界

- 预览保存在用户隔离的对象存储命名空间，编号随机生成，有效期 30 分钟。
- 预览绑定完整学业快照版本；保存前复查，并在学业写锁内再次检查。预览后任一类学业数据变化都会使旧预览失效。
- 课程日期/节次异常、空课程名、嵌套字段及缺失成绩在写入前拒绝。成绩 `0`、绩点 `0`、等级制原文保留；不换算分数。
- 未识别出的上课时间保持未知，并提示不会出现在课表网格，不能编造。周次、地点、学期分别保留。
- 预览先使用既有去重规则，确认保存与预览列表一致。另一类学业记录和每条成绩所属学期不被覆盖。
- 图片中可能存在提示词攻击：主对话和识别器均将图片视为不可信资料；识别器没有工具，实际写入权限由服务端审批规则约束。
- 不自动访问图片内链接，不收集教务系统密码。图片字节不写入业务日志；视觉模型失败日志只记录异常类型。
- 30 分钟为使用有效期；当前对象存储不具备自动过期清理，过期预览仍可能占用存储，后续需纳入对象生命周期清理。此项不影响过期后的拒绝执行。
