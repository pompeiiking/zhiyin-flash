# 个人画像真实验收问题修复与复查

日期：2026-10-21。工作目录 `D:/zhiyin-flash-profile-review`，分支 `个人画像重构`。

复查入口：前端 `http://127.0.0.1:5276/#/profile`，后端 `8000`。

本次按[新账号真实验收记录](个人画像新账号真实验收-2026-10-21.md)修复代码、更新本地运行后端和相关动态配置，并重新进行真实模型、浏览器及 PostgreSQL 核对。没有切换原 `D:/zhiyin-flash` 的 `前端重构版` 分支，没有清空数据库或修改其他用户资料。

## 根因与最终改动

### 运行版本与动态配置没有一起更新

此前前端已更新，`8000` 容器却仍在运行旧后端；数据库优先的动态提示词、字段词表也不会被镜像重建自动覆盖。这使此前记忆预检、删除保护、线索否认修复没有在实测环境生效。

本次已重建并替换本地 `zhiyin-flash` 服务。新增 `scripts/update_profile_dialogue_registry.py`：默认只读预览，`--apply` 必须提供旧值备份路径；只更新两条对话提示词和四条画像字段词表，不重同步其他运营配置。旧镜像保留为 `zhiyin-flash:before-profile-20261021`，配置旧值备份保存在本地 `output/`，未提交凭证或连接串。

### 类型契约没有贯穿真实采集链路

画像服务支持类别、属性和有效期，但主对话提示词与兜底提取仍使用旧的短字符串契约。职业关注、补充说明和临时条件因此经常漏采或放错位置；词表中也缺少可直接使用的 `career_focus`、`time`。

现在主对话与语义采集共用 kernel 中的字段类型、取值形状、属性 schema 和长度契约：

- 专业、年级、学历与学籍属于学习背景。
- 兴趣保存活动对象及 `like/dislike/unsure`；同一字段可用 `attributes.items` 保留逐项属性。
- 职业关注保存岗位对象和 `exploring/considering/selected`，不会把“了解中”当成专业或已选方向。
- 笔记习惯等补充说明使用 `supplement_info`，不再默认塞进技能或项目经历。
- 临时条件带范围与含时区的 `valid_from/valid_to`，可从过期业务读取中退出。
- 只完成一次与熟练能力分开；单次能力证据使用 `completed_once`，不是已核验或熟练结论。

属性的枚举、布尔值、文本与逐项列表分别校验；不再把数组、对象强行转换成标题或其他标量字段的 Python 文本表示。价值取向的文本列表可规范化为可读文本。

### 两条采集路径互相漏项、重复写入

原逻辑只要主模型成功写入任意一个画像字段，就跳过本轮全部兜底采集；反过来分别运行两个链路，又会把同一句话的不同概括追加成多个兴趣。

现已移除全轮跳过逻辑和回复后的重复提取：先核对记忆范围，再用同一次语义结果逐项保存本轮事实，之后交给主对话自然交流。主对话收到更新后的画像和本轮已采集键；重复提交已成功采集的键返回真实回执，避免再写一份同义概括。尚未采集的键仍可由受控工具补充。

所有写入仍经统一授权、证据、版本及幂等边界；没有恢复关键词路由，也没有让 Kev 或模型绕过权限检查。账号禁用、临时会话、字段删除及内容拒绝仍由服务端持久化策略约束。

### 有效期在 PostgreSQL 操作账本中序列化失败

真实复查发现，时间经解析后以 `datetime` 放入操作账本；内存仓储接受它，PostgreSQL 的 `json.dumps` 拒绝，后续事实采集也随之中断。

现在账本保存带时区 ISO 字符串，实际写画像时再解析为时间对象；显式更正路径保留类型属性、原话、来源引用和时间范围，不再只传 `key/value`。新增严格 JSON 状态仓储回归用例，覆盖时间条件及其后续字段仍可保存。明确的本人更正使用本人确认写路径。

### 集合追加被误判成冲突，冲突裁定又丢其他条目

原逻辑用同键新旧值不等判断冲突，没有区分“新增独立偏好”和“同一对象的矛盾说法”。

现独立兴趣与职业关注按对象合并，逐项保留极性/状态；同一对象相反说法才形成冲突。候选携带完整集合，因此采用新说法也不会删除未涉及的其他兴趣。冲突界面展示两侧属性，让同名活动的“喜欢／不喜欢”可直接比较。

用户明确要求“先保留另一种说法，不覆盖原值”时，新增受控的 `conflict_candidate` 类型，只创建待核对候选，不写当前事实。回执明确说明“当前记录没有覆盖”，不冒充普通画像更新。

### 裁定后的旧待核对状态留在会话中

真实测试进一步发现，画像裁定成功后，相关线索和会话探索快照仍可能说“等待核对”，主模型继续引用历史状态。

现在两种裁定都会失效相关会话理解、清除该会话旧探索快照；候选操作涉及的字段也进入失效关联。每轮主对话取得当前未决冲突的权威快照，空列表明确表示没有待裁定项，历史回复不能覆盖它。

### 页面只更新事实行，没有更新衍生状态

更正、删除成功后，前端原来只替换/过滤 `fields`，后台已失效的线索仍留在页面。现操作成功后刷新完整 workspace，先移除受影响的旧理解；刷新失败时保留已保存结果，提示“修改已保存，但最新判断暂未读取”，不诱导重复写入。补充更正提交忙碌保护。

### 待补充、待核验及计数混在一起

采集登记表对学历等字段要求权威来源，导致已有自述仍被当成“没提供”，页面又引导用户重复聊天。

现画像事实已存在的字段退出待补充清单；核验状态仍在学籍区单独表达。顶部已记录数与实际资料条数一致；可核验的缺口进入核验入口，并保留先自述的选择。已有经历或偏好时，主卡不会再要求先提供同类内容才可开始探索。

### 浮层、依据及导出

- 浮层启用持续定位、优先避让和可用高度约束，正文可滚动；桌面及390宽度实测均在视口内。
- 线索依据允许展开全部用户原话，不再固定显示前两段并截断为180字。当前存储仍是会话级证据集合，不宣称已经有逐句语义相关度排序。
- 导出改为版本化的当前画像快照，保留原始字段、属性、核实状态、有效期、来源引用、线索、冲突及采集清单。明确 `history_included=false`，不能当成含全部历史版本的无损备份。

### 重新登录时退出后的旧请求重复清除会话

实测一次登录接口成功后，又被退出期间旧页面的401结果重置到空登录表单。传输层此前在没有请求令牌时也派发全局 `unauthorized`，可重复触发清会话、重建登录浮层。

现学生、流式及开发者传输仅对携带当前令牌的认证失败发送失效通知；无令牌请求仍被后端拒绝、仍向调用者抛错，不重复清除已经退出的前端会话。没有关闭认证或忽略有效会话的401。新增匿名401、业务错误和流式错误回归，原有有效令牌失效及跨账号隔离用例继续通过。修复后连续两次快速退出并重新登录，均第一次提交成功，刷新后仍保持登录。

## 验证边界

本次覆盖已复现问题和上述核心链路，不代表穷尽模型所有措辞、全部提示词攻击或生产压力测试。语义采集仍可能遗漏长复合消息中的某个细节，不能把代码不再整轮跳过解释成模型永远一次抽全；本例首轮复合背景未单独抽出学籍状态，后续明确后记录。新增契约已要求复合背景分别采集，仍需积累真实对话样本持续评估。

真实学信核验、外部核验撤销因没有本人在线验证码未执行，没有伪造结果。实体手机软键盘、生产多实例高并发和完整历史画像迁移未在本轮验证。导出范围为当前快照，历史版本需走专用历史接口。兴趣逐项属性已保存，但当前存储仍以字段为当前记录单位；细粒度来源和历史的进一步演进应按既有画像设计另行实施，不能冒称本轮已完成多实体存储迁移。
