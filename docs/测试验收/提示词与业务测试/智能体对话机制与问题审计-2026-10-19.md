## 结论

目前的核心问题不是单一模型“智商低”，而是**对话被业务流程、极短历史、关键词写入规则和事后文本覆盖共同控制**。模型可能已经理解了部分请求，最终回复仍可能被替换；模型没有拿到完整上下文时，也不可能可靠承接用户。

最值得优先处理的是：否定句触发真实修改、敏感信息先保存和发送再声称未处理、更正后回答不落历史、30 字历史截断、任务操作错误、并发重复执行。继续增加同义词和兜底文案会扩大分支冲突，难以从根本上改善交流。

本清单共 **63 项**，包括已复现缺陷、代码确认的机制问题、待联调风险及架构优化；不是 63 项都已在当前部署中实测失败。静态审计不能证明不存在其他问题，也不能据此断言当前服务正在使用哪一个模型、哪一版数据库提示词。

## 实际工作机制

1. **前端发送**：创建或续接 `task_id`，发送文字、`client_msg_id`、选项身份、最多五个材料 ID。前端通过 POST SSE 接收完整替换式的 `text` 更新，最终用 `result` 替换等待气泡。
2. **Facade 取材料**：检查分析同意和资料偏好，从对象存储取出本轮附件全文，然后交给编排器。附件并不是由 Agent 持续可访问的会话文件列表。
3. **先处理部分动作**：找会话、查已完成答复以尝试去重，计算安全标志，先保存用户原文；用正则直接修改画像。能定位的任务完成/恢复也可在这里直接执行并提前返回。
4. **识别确认与阶段**：从上一条 Agent 文本末尾或账号状态找提议；关键词优先，未命中时可让 Kev 分类。再根据阶段规则、账号资产/行为、采集门槛、轮次上限决定五阶段之一。
5. **选择主理与组装上下文**：采集主要由建档分析师，诊断/决策由职业顾问，行动由路径规划师，复盘由陪伴教练负责。角色主要按阶段映射，`assistant_agents` 默认为空，并非多名 Agent 在每轮共同讨论。
6. **模型实际看到的内容**：系统总纲＋角色指令，以及一条含收尾规范、当前输入、最近历史短行、画像、计划、全账号会话摘要、最近行为、来源与证据约束的 JSON 文本。最近历史最多六条消息，每条最多 30 字；用户摘要每次最多 60 字、回复摘要最多 120 字，并累加保存。
7. **调用与产出**：Agno/OpenAI 兼容模型，按角色挂工具；普通咨询也按当前阶段输出 JSON。启用业务工具时为兼容函数调用，把 Schema 拼进输入，最终再解析校验。部分轮次流式展示 `conclusion`。失败时可能再次调用模型修复格式。部分阶段还会额外调用信息侦查员或采集模型。
8. **执行、修补与展示**：编排器做业务证据检查、保存报告/方案/计划、补采画像、消费工具回执，再经过大量正则改写或整体覆盖回复，最后写记忆、历史、行为、会话快照并返回。

因此，用户看到的不是模型的直接回答，而是：**阶段模型输出 → 校验/修补 → 业务执行 → 多个条件覆盖 → 最终气泡**。定位问题时必须同时看这五层。

## 推荐的改造顺序

### 第一批：先堵住错误执行与错误承诺

优先处理 19、20、21、28、29、39、40、53。把动作授权、写入和回执统一起来；所有输出以真实提交结果为准。特别是敏感信息处理必须发生在存储和模型请求之前。为这批具体复现补回归测试，而不是继续往正则里堆词。

验收示例：

- “不要把专业改为法学”不修改；“我不是大二”追问真实年级。
- 更正成功后刷新仍有完整问答，重试不再次执行。
- 一句话里第一项完成、第二项未完成，分别正确处理。
- 两项中一项保存失败，明确说哪项成功、哪项失败，与回读一致。
- 并发同一请求只执行一次，返回同一完整结果。
- 合成手机号不会进入拒绝处理后的模型输入或原文存储；若选择允许保存脱敏内容，说明必须与之相符。

### 第二批：恢复正常交流能力

优先处理 01–10、11–18、30、33、46、49。近期对话保留原文，早期历史按预算总结；把用户偏好、否定要求和当前任务保存为可修订约束。普通聊天不强制生产报告结构，工具只作为回答所需的手段。

建议的运行链路：

```text
用户消息＋完整近期历史＋相关长期事实
  → 理解本轮问题、约束与待执行动作
  → 权限/对象/版本校验
  → 必要查询和已授权操作
  → 真实回执
  → 回答用户本轮问题
  → 选择性更新记忆与任务状态
```

阶段保留为业务任务状态；成果生成作为明确动作，使用独立契约。一个统一对话入口可按需调用职业分析、计划生成等专业能力，不要求用户每句自然话都先进入某个固定角色。

### 第三批：提高知识质量与恢复能力

处理来源结构化、附件回查、读写混合流程、事务/补偿、请求状态回查、总预算与分阶段观测。模型选择应在记录实际模型、上下文长度、工具成功率和失败原因后再比较，不能先把所有问题归因于模型供应商。

最小观测字段：turn/request ID、实际模型、prompt/schema 版本、上下文 token 估算、各阶段耗时、工具调用及回执、资产版本、失败类别；用户正文和敏感内容按数据策略处理，不为了排障直接全量打日志。

## 下一轮真实模型验收矩阵

1. 纯咨询：解释概念、要三条建议、要求长答/短答、情绪表达、转话题。
2. 长历史：第 1 轮设置限制，第 5/10 轮继续，确认不遗忘、不重复问；更正过的事实不回滚。
3. 引用与否定：引述老师建议、引用任务标题、先生成/先别生成、只是讨论/明确执行。
4. 混合请求：提供经历＋查计划＋问下一步；生成计划＋提醒时间；两项不同状态动作。
5. 查询与来源：已配置/未配置搜索、查询失败、空数据、用户本轮换职业；引用卡与实际结果一致。
6. 写入与确认：口头同意、按钮同意、旧提议、已换话题、跨会话、多标签页和参数变更。
7. 附件：本轮读取、下一轮引用、刷新后续问、总量过大、材料含类似指令的内容。
8. 失败恢复：超时、停止、断流、第二步写入失败、快照失败、同请求并发重试；核对实际业务值而非口头宣称。

本轮没有执行上述真实模型/当前部署全矩阵，不将本报告中的建议当作已完成修复。产品源码和审计开始前已有修改均已保留。
