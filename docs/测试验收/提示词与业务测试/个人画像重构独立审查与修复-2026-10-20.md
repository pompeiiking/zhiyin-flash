# 个人画像重构独立审查与修复

日期：2026-10-20。分支：`个人画像重构`。

## 范围与结论

审查起点为 `048c4d9..ec89cca` 的四次画像重构提交，并检查原工作目录中尚未提交的 `migrate_profile_aliases.py` 及其测试。本分支在 `ec89cca` 上补修，保留原目录和原分支。

分类记录、独立线索、修订历史和用途读取的方向合理；原有测试全通过不能证明记忆策略和真实交互已经闭环。独立检查复现了以下缺陷，已针对性修复。这里的结论覆盖本次改动及关键调用链，不代表逐行审查了整个后端或重新完成了全部产品验收。

## 已确认与修复的问题

| 编号 | 优先级 | 触发与影响 | 修复 |
|---|---|---|---|
| R01 | P1 | 用户同轮说明不保存，但范围识别在主模型工具之后执行；主模型一旦写成功，范围提取还会被跳过 | 工具执行前先识别并持久化记忆范围，同轮复用语义结果；范围识别或保存失败时阻止自动写入，仍允许交流 |
| R02 | P1 | 临时会话或关闭自动记忆时，探索假设与原话仍被发布到长期画像线索 | 会话工作上下文与长期线索发布分开；后者检查账号、会话、内容与单条范围，历史被拒绝内容也不能通过下一轮线索发布 |
| R03 | P1 | 否认线索后，下一次分析传空 ID 整体替换，原否认记录消失，同一句话以新 ID 恢复有效 | 按既有 ID 或相同文本延续线索，保留失效记录；提示模型不得把否认内容改写后重新提出 |
| R04 | P1 | 从画像页删除字段没有写拒绝记忆状态；下一轮可再次自动保存 | 删除服务统一登记字段拒绝记忆并使旧探索上下文失效，页面删除与对话删除遵守同一限制；版本冲突不执行删除后续处理 |
| R05 | P1 | 兴趣的 dislike、情境等保存在 attributes，但推荐、分析与画像描述只输出 value，丢失语义 | 批量分析、单项解读和画像描述携带类型属性；画像列表与详情显示中文属性 |
| R06 | P2 | valid_to 已过或 valid_from 尚未来到，但状态仍 active 时，记录仍参与计划与分析 | 公共可用性判断同时检查状态和实际有效时间；字典时间与对象时间均处理 |
| R07 | P2 | 职业取数构造字段上下文时丢弃 status，过期等状态被读取端默认成有效 | 取数前过滤不可用记录，并传递状态和时间范围 |
| R08 | P1 | 两个旧别名指向尚不存在的同一规范键，迁移计划生成两次 create，后一次 upsert 覆盖前一次 | 后续别名读取计划中的目标值，异值进入冲突提案；备份保留迁移前真实目标状态，支持回退 |
| R09 | P2 | 后端允许长经历，但更正框和前端预检仍限制 40 字 | 去除统一的前端截断与拦截，按服务器类型规则校验，错误保留输入 |
| R10 | P2 | 长文本已写入真实后端，前端随后又写演示 store，触发旧 40 字提示，表现为成功保存却报错 | 真实档案保存后不再调用演示数据写入；新增前端行为测试覆盖该链路 |

## 后续优化与验证边界

1. 当前仍以每个字段键一个当前值兼容旧接口；兴趣、经历等多条内容应继续演进为独立条目，逐项管理情境、证据、时间与增删，避免把新增兴趣误判为覆盖冲突。
2. 当前服务端能阻止相同文本的否认线索恢复，并向模型传递否认约束；改写后的同义假设尚无确定性的概念身份判定，不能宣称完全解决所有语义复现。后续宜使用稳定线索身份与明确的重新核对事件。
3. 记忆范围继续依赖 AI 语义识别，未恢复关键词路由；识别失败时已有保护，但模型误解授权语义仍需要真实模型对抗和长会话测试。
4. 删除沿用现有的账号级上下文重置口径。后续应按原话／条目依赖做更细粒度排除，减少删除一项信息对其他会话上下文的影响。
5. 本轮未向真实数据库应用别名迁移，也未重新运行真实模型、生产 PostgreSQL 的多进程并发与跨账号验收。不能用内存仓储通过替代这些证据。
