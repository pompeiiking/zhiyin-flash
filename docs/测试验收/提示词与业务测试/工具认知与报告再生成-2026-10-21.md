# AI 工具认知与报告重新生成检查（2026-10-21）

工作目录 D:/zhiyin-flash-profile-review，分支「个人画像重构」，基线 ebdf24b。用户要求检查 AI 是否清楚可用工具，并补上报告页重新生成入口。

## 根因与修复

1. 主对话 native 工具池漏挂 workspace.memory：注册表有它，提示词要求用它，但实际模型不能调用。现已挂入实际对话，并让能力检查复用同一个工具池；缺失工具、未授权模块与被替代的旧入口不对模型宣称可用。
2. workspace.action 的 operation 原为任意字符串，说明未覆盖实际操作。现在与执行器共用 DialogueOperation 的16项枚举。测试校验 Agno 实际接收的包装后函数 schema，用户身份和会话上下文不作为模型参数暴露。
3. schemas 读口只返回三个资产模型，directions.save 却实际要求 plans 列表，报告模型还要求模型填入由服务器产生的身份/版本信息。现提供全部操作的用途、授权规则和精确 payload_schema，可用 operation 按需读取；方向列表外壳、条数、计划局部修改字段及草稿启用流程均与执行路径对应。
4. 真实重生成复测暴露复杂报告参数拼错后仅返回泛化失败，模型重复尝试直到工具次数耗尽。新增 save_report_draft 强类型入口（规范名 workspace.report_draft），直接展示 verdict/swot/dimensions 等正文结构，隐藏服务器负责的 ID、用户、版本、时间。保留统一操作边界和草稿审批。ValidationError 反馈具体字段路径/类型/信息，不回显输入原文，不把校验失败伪装成成功。
5. 草稿回执原为“已保存报告”，容易与正式报告混淆；现明确“已保存报告草稿，正式版本尚未替换”。写入回执的实时状态也只表示已核对回执，不在结果未确认时宣称保存成功。
6. 报告页之前仅有“重新读取”，空态才有生成入口。有报告时现在显示“重新生成报告”；无报告显示“生成报告”。入口进入现有流式对话：读取最新资料、生成新版、展示确认、确认后启用，历史版本保留。“重新读取”继续只读，不冒充重新生成。页面与自动发送文本使用面向用户的简短表达，不展示内部字段契约。

## 工具边界

- workspace.read / material.read 读取资料；kb.search / xuezhi.search / web.search 等查询按安装与角色配置提供。
- workspace.action 提供画像、任务、草稿、启用、日历、选择方向、删除、撤销和审批操作；未知操作不会被当作已实现能力。
- workspace.memory 保存明确拒绝记忆要求；workspace.exploration 只维护会话工作快照；workspace.classify 仅作 Kev 辅助，不能授权写入。
- save_report_draft 只保存草稿。report.activate 必须审批，不能因为模型称“用户明确要求生成”就自动替换。
- 运行容器中的函数 schema 已核对：operation 共16项；报告正文必填 verdict/swot，不要求用户身份；本轮7个产品工具均真实注册。专业角色与理论辅助入口保留。
