## 常用入口

命令默认从仓库根目录执行，只有明确说明时才切换目录。

| 工作 | 入口 |
| --- | --- |
| 系统部署 | `docker compose up -d --build`，环境配置见[部署说明](../部署运维/部署说明.md) |
| 前端开发 | 进入 `zhiyin-src/template/zhiyin-web`，执行 `npm run dev`；本机端口 5275 |
| 前端验证 | 在前端目录执行 `npm test`、`npm run check:backend`、`npm run build` |
| 后端测试 | 在 `zhiyin-src/template` 执行 `python -m pytest -q` |
| 接口清单维护 | `python scripts/contracts/frontend-capabilities.py` |
| 前端基础联调 | `python scripts/acceptance/frontend/frontend-smoke.py --base http://127.0.0.1:5275` |
| 隔离接口验收 | `scripts/acceptance/frontend/frontend-remaining-acceptance.py`，按[验收说明](../前端/后端接入/系统接入与验收说明.md)在独立容器内运行 |
| Kev 配置及联调 | `scripts/integrations/kev/kev_config.py`、`scripts/integrations/kev/kev_smoke.py` |
| 模块平台验收 | `scripts/acceptance/platform/accept_*.py`，具体前置条件见各脚本说明和[平台验收记录](../测试验收/模块平台验收记录.md) |
| 构建发布包 | `python deploy/package_release.py`，先按部署说明准备环境及迁移文件 |

## 分类原则

- `deploy` 放部署过程及持续运行依赖；用于验收结果的独立脚本放 `scripts/acceptance`，避免误把验收程序当生产启动程序。
- 工程内部脚本靠近后端契约、迁移和模块代码，保留在 `zhiyin-src/template/scripts`；跨工程维护工具放根目录 scripts。
- 文档按用途归入 docs。当前需求、实际验收和历史方案分别存放；历史资料不覆盖最新需求。
- 代码、模块及工具约定文件保留稳定的技术名称；面向阅读的文档、文件夹和配图使用中文名称。
- 根目录保留 Docker 与 Compose 常规入口，使原有启动方式继续有效；正式前端保留用户指定的原路径。
- `node_modules`、`dist`、Python 缓存、`.platform` 中的运行状态和本机凭证属于生成或私有文件，不进入版本控制。不要把它们复制进 docs 或发布包。

## 本轮迁移

部署说明归入部署运维，模块开发说明归入开发指南，平台和提示词测试记录归入测试验收；产品截图与问题截图集中到资源目录。原 deploy 下的 13 个独立验收程序归入平台验收，前端联调、契约和 Kev 工具分别分类。

迁移同步调整了脚本定位仓库根目录的逻辑、部署工具导入、发布包白名单、说明链接和对齐测试。后端包名、前端运行代码、数据库以及已验收的接口行为不因目录整理而改变。
