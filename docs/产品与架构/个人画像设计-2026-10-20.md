# 个人画像设计

日期：2026-10-20。状态：已根据本轮讨论与评估整理的目标设计，尚未完整实施或验收。本文不表示数据迁移、权限策略或页面已经上线。本轮已落地的记录结构、取数分离与展示改动见[个人画像设计实施与检查记录](../测试验收/提示词与业务测试/个人画像设计实施与检查记录-2026-10-20.md)；该记录同样不是全量验收通过证明。

适用范围：个人画像的数据组织、对话采集、长期记忆、来源、更正与删除、派生分析、业务读取及必要的展示调整。与《完整设计文档》《对话系统重构设计》涉及画像的旧口径冲突时，以本文为本轮画像设计依据；其他业务审批、账号隔离和资产生效规则继续沿用原设计。

## 1. 设计目标与现状

画像通过持续交流和真实资料逐步形成，支持用户查看、更正、撤回和删除。普通咨询不要求画像完整，不以完整度或字段数量作为继续交流的门槛。

采用“分类信息＋来源证据＋待验证线索＋按用途读取”。AI 理解信息含义与当前意图，服务端落实结构、来源、权限、版本和用途边界；不恢复关键词路由或用词命中即写入的规则。

现有实现已有 `major`、`interest` 等字段，但仍主要使用 `key/value` 平铺结构，值的语义约束不足，部分职业关注别名被归入普通兴趣。学职取数把 `interest` 纳入职业查询词，在专业无官方职业映射时，兴趣描述会覆盖专业检索。

本轮已复现：专业“人工智能”能够查询到人工智能工程技术人员；加入兴趣“把东西真正跑起来的过程”后，实际职业与案例查询改用了兴趣描述，得到 0 个职业及“老白校园”“好玩工厂”两条案例。该问题不是通过新增一个显示字段就能解决，需同时调整记录结构和消费契约。此根因已确认，本文提出的完整改造仍待实施。

## 2. 内容分类

| 类别 | 内容与示例 | 边界 |
| --- | --- | --- |
| 学习背景 | 学校、专业、年级、学历及相应时间；关联课程、成绩资料 | 专业不等于兴趣或职业目标。不同阶段的教育记录可以并存，不把所有经历压成一个当前值。 |
| 兴趣与偏好 | 喜欢或不喜欢的活动、关注领域、偏好的做事方式及情境 | 多条记录，允许不确定和变化；不能直接充当职业名称、能力证明或人格标签。 |
| 经历 | 项目、课程实践、实习、活动中的行动、困难、结果和感受 | 保存具体事件；同一经历被多处引用，不重复复制成多份事实。 |
| 能力与技能 | 接触过什么、能独立完成什么、本人自评、作品与成果 | 区分接触、自评和成果支持；喜欢不等于擅长，单次完成不等于稳定能力。 |
| 职业关注 | 想了解、正在考虑、已明确选择的职业或方向 | 关注状态分开；查询、点击或 AI 推荐不能自动成为已选目标。 |
| 价值取向 | 对收入、稳定、成长、自主性等方面的偏好与取舍 | 可因情境变化，不能从一次选择推断固定人格或永久价值排序。 |
| 现实条件 | 时间、地点、经济条件、家庭责任等与当前目标有关的条件 | 标明适用范围和时间；本周没空不是长期没有时间。只收集当前服务所需内容。 |
| 补充信息 | 明确来自用户、有持续价值、暂时无法归类的信息 | 多条、有来源、可待归类；不作为业务检索或职业判断的通用入口。 |

类别是组织视角，不要求一条信息只能有一个展示位置。一份经历可以支持兴趣和能力分析，通过引用关联；原始经历及其更正仍只有一个出处。

“人工智能”本身不能决定类别：上文问专业而用户回答人工智能，可记录专业；用户明确说对人工智能感兴趣，可记录关注领域；“想了解人工智能工程师”属于职业关注。由 AI 结合上下文理解，写入后使用明确类型，消费方不再猜字符串含义。

## 3. 三层内容分开管理

### 3.1 用户信息与经历

保存用户明确提供或实际资料中存在的信息，注明是本人自述、手动确认、资料记录还是外部核验。来源证明“信息来自哪里”，不自动证明能力或职业判断成立。

本人对兴趣、感受的明确陈述可以作为本人偏好使用，不要求外部验证；“用户说自己擅长编程”仍是能力自评，不能直接展示为已验证能力。

### 3.2 待验证线索

AI 对信息的有限理解单独保存，必须关联依据并标明适用范围，不进入事实字段。不为每句话制造推测；没有后续用途的理解无需持久化。

例如，“喜欢弄清 bug 的原因”是兴趣体验；“可能关注机制与原因”是待验证线索；“适合算法工程师”不能由此成立。不能通过反复引用同一推测，把它变成稳定能力或人格结论。

依据被更正、撤回或删除后，相关线索失效或等待重新分析。重新检查的时机来自证据变化、用户反馈和实际用途，不以简单重复次数自动确认。

### 3.3 会话工作上下文

本次诉求、已谈主题、待承接的问题、记录限制和临时状态属于会话工作上下文。当前探索目标不默认转成长期目标；日常闲聊保留正常会话记录，不等于额外生成画像条目。

会话探索快照与长期画像分开，沿用既有会话隔离、来源校验及取消处理。当前用户意图优先，不能因为上次处于探索模式就持续盘问。

## 4. 记录结构与语义契约

以下是概念结构，不是已经发布的接口或数据库字段承诺。实施时以业务契约定义正式 schema。

| 记录内容 | 作用 |
| --- | --- |
| 条目标识、账号、类型、规范属性 | 稳定定位与隔离；关键属性来自受控词表，模型不能自由生成权限相关字段。 |
| 整理后的内容及结构化值 | 不同类型使用不同 schema；兴趣是多条偏好，经历是事件，职业关注含状态。 |
| 原话或资料来源引用 | 指向实际会话、材料片段或导入记录，保留必要语境；不能编造引用。 |
| 来源方式、核实状态 | 分别表达自述、本人确认、资料记录、核验及待核实，不用一个分数混合这些含义。 |
| 记录时间、事件时间、有效范围 | 区分何时知道、何时发生、何时仍适用；未知时间不自动补成当前时间。 |
| 当前状态、版本及替代关系 | 支持有效、被更正、存在冲突、过期、撤回等状态及并发更新。 |
| 证据与派生关联 | 说明哪些分析依赖此条信息，便于失效和重新计算。 |

兴趣条目至少区分活动或领域、喜欢/不喜欢/不确定、情境及来源。职业关注至少区分关注对象、了解/考虑/已选状态；官方职业标识只有实际解析成功时才关联，不猜 ID。

例如：

```text
类型：活动偏好
活动：调试程序
原话：我想查清原因，查明白挺开心。
情境：一次文件读取后数字成为字符串的调试经历
来源：本会话对应用户消息与所关联经历
来源方式：本人自述
核实状态：有原文支持；是否适用于其他活动尚不清楚
```

该条不携带“算法岗适合度”或“根因分析能力分数”。“不喜欢调 bug”可以记录为对具体活动的否定偏好，不概括为“没有技术兴趣”。身份否定也不能制造一个新身份值。

不继续用统一的40字短字符串承载所有记录。各类型分别限制条数、文本长度、结构深度和来源大小，经历正文与短标签分开；超限明确反馈，不静默截断。

现有 `confidence` 可在兼容阶段保留，但不作为真实性、熟练度、展示分数或写权限的共同开关，不用未经校准的百分比装饰画像。

## 5. 自动采集与记录权限

### 5.1 一条统一写入链路

对话工具、补充记忆提取、手动编辑、资料导入、批处理及后续后台任务，都通过统一画像写入服务处理。不同来源有各自的可信范围，不允许补充提取直接绕过权限、版本或归属检查写表。

AI 提出分类、整理内容、来源和更新意图；服务端验证类型 schema、真实来源、当前账号、有效记录策略、幂等键、预期版本及允许用途。模型填写“已授权”不能代替实际授权依据，工具或附件内的指令也不构成用户授权。

明确、相关、有持续价值且允许记录的信息可按既定自动记忆策略保存，不逐条弹审批。含糊信息保留未知；不能为了补齐画像反复追问，只有澄清会影响当前回答或操作时才提问。

### 5.2 记录策略必须持久化并由服务端执行

默认自动记忆的既定选择保留，但下列范围必须区分：

| 用户要求 | 生效范围 |
| --- | --- |
| 本次只聊，不保存长期画像 | 当前会话禁止自动写长期画像，仍按会话策略保存交流内容。 |
| 以后不自动记录 | 账号级自动记忆偏好；后续会话继承。 |
| 这条不要记录 | 对应内容与其派生提取，不扩大为所有内容都不能记录。 |
| 只保存这一条 | 对明确对象的一次授权，不恢复全局自动记忆。 |
| 临时会话 | 按临时会话策略处理，不把工作快照转成长期画像。 |

AI 结合用户原文识别要求和范围；形成有来源、可回读的策略记录。服务端在每个写入入口读取有效策略，不能仅靠提示词或最近几条消息维持限制。会话摘要压缩、换题、重启或更正信息都不能使拒绝记录要求失效。

限制应在后续自动写入前生效，不随回复生成失败而撤回。扩大记录范围需要明确的用户设置或范围唯一的新指令；含糊时维持原限制。用户手动保存某条内容只授权该条，不代表允许恢复其他自动记录。记录策略的更新与普通探索快照分开，探索模式或角色切换不能授予写权限。

系统应准确说明保存范围。“不保存长期画像”不能泛称为“不存任何东西”；现有会话原文、工作上下文的保留方式与长期画像分别说明，不在每轮反复宣读。

## 6. 补充信息的进入与归类

先判断是否值得长期保存，再判断类别。满足明确来源、业务相关、持续价值及记录许可后，仍无法归类的内容才进入补充信息。AI 推测进入线索，临时状态进入会话或限时条件，无关内容不额外入画像。

补充信息保存简短标题、内容、原话与来源、情境、时间或有效期及待归类状态。允许少量特殊信息长期留在这里，不要求所有条目最终归类。

AI 可以提出归类建议；真实迁移保留原始出处和替代关系，去除重复展示，不复制成第二份事实。不能自动补出原话没有的含义，例如“照顾家人，晚上才有时间学习”不能改成“家庭经济困难”。同类需求持续出现时再调整正式 schema，不为每个个例新增字段。

## 7. 更新、冲突与删除

区分新增、修正、随时间变化、冲突、撤回和删除，不统一执行“最新值覆盖旧值”。来源不能排成无条件的全局优先级：旧核验资料可能准确描述过去，用户当前自述可能描述转专业后的新情况。

- 内容相同且情境一致时合并来源，不制造重复条目；语义合并可由 AI 提议，提交仍绑定真实条目、版本和差异。
- 新情况有不同适用时间时保留时间关系；只将满足当前范围的记录投影为当前画像。
- 不能明确区分修正与冲突时并存标记，只有影响当前服务时才澄清；重要身份冲突不擅自标成“已核验”。
- 用户更正优先处理其明确修改的对象，不顺便重写其他信息。相关线索、报告或推荐标记待核对，完成实际重新分析后才更新结论。
- 删除内容不能继续通过摘要、经历关联、旧报告、缓存或补充信息被恢复使用。可保留必要的删除标识与审计状态，不能以审计为名继续向模型提供已删除正文。

多个标签页和后台写入使用条目版本校验，重复消息不重复新增。画像变更与必要事件保持一致提交，缓存按相关画像版本失效，不依靠前端刷新碰运气。

## 8. 按用途读取

各业务读取服务端生成的用途视图，不能自行扫描整份画像，把任意字符串拼成查询词。字段类别、状态、来源和适用范围共同决定可用内容；允许用途由服务端规则计算，不能由模型设置一个 `allowed=true` 绕过。

| 用途 | 允许的输入与约束 |
| --- | --- |
| 专业相关职业检索 | 明确专业信息独立检索；普通兴趣、价值偏好或补充描述不能替代专业查询。 |
| 职业/方向检索 | 用户明确关注的职业、方向或主动查询；关注不等于已选，职业目录未匹配时保留原关注内容。 |
| 方向推荐与比较 | 相关兴趣、经历、能力证据、价值取向和有效条件；事实、假设和推荐分开，不能自动写为已选目标。 |
| 制定计划 | 已确认目标、当前能力依据及有效现实条件；临时限制不固化为长期属性。 |
| 普通交流 | 与当前问题有关的少量信息；不把整份背景和全部推测反复塞进提示词。 |

兴趣可以帮助 AI 提出候选方向；如需查证，应形成明确、带推荐依据的职业查询。查询结果不自动证明用户适合，也不反向证明兴趣就是职业目标。

检索结果保留查询依据、取数方式、真实来源及相关性说明。区分官方专业映射、名称检索和一般案例；“本次未取到职业”不能解释成“平台没有收录”。专业、职业、案例分别报告数量与状态，不能仅因返回了专业介绍就把整个职业查询宣布成功。

## 9. 展示与用户控制

沿用现有正式前端结构，围绕三种内容组织：用户提供的信息、系统基于证据的理解、近期补充与变化。分类可按当前任务呈现，不把全部后台类型铺成必填表格。

用户可以查看来源、修改、删除、否认系统理解，看到具体变更结果。后台属性名、内部置信度、迁移状态和推理过程不直接堆到页面。待验证线索与明确资料有清楚区别，不显示无依据的能力分数，不以完成度催促补档。

对话右侧保留简洁画像摘要；完整经历和来源在个人画像页按需查看。当前页面结构、导航及其他页面不随本方案一起重做。涉及正式前端修改时仍需桌面与手机真实验证。

## 10. 迁移与实施顺序

1. **先止住取数混用。** 专业检索独立，普通兴趣退出职业名称输入；核对来源与相关性，修改“未取到即未收录”的文案，补完整画像组合回归。
2. **落实统一记忆策略。** 账号/会话/单条范围可持久化，所有写入入口共用；拒绝记录不能依靠模型短期上下文维持。
3. **升级记录与证据结构。** 优先迁移明确学习背景、用户原话和经历，再处理兴趣、关注方向及派生关联；先做事实和经历，不急于做能力评分。
4. **切换用途视图与展示。** 业务消费者逐一迁移到新契约，页面逐步接入，最后撤除旧写入口和混用逻辑。

迁移先预览具体差异，再按确定的规则分批执行；保留回退条件、幂等和版本检查，不清空现有数据库。旧条目缺少原始消息时保留“历史字段来源”，不伪造原话或确认状态。

旧 `interest` 中明确的偏好可迁为偏好条目；含义不清的原文进入待整理，不批量猜成职业目标。`career_interest → interest` 等别名要逐项拆分，历史含糊值不能仅凭旧键名自动归到已选职业。

以新写入服务作为唯一入口；旧 API 如需兼容，提供有明确范围的只读投影，不维护两套各自独立写入、互相覆盖的事实。迁移期间不得让旧提取器或批处理绕开新策略。

## 11. 验收要求

以下为待执行验收，不能把本清单当成通过记录。每例保存输入、当前策略、工具轨迹、数据库前后差异和结果；语义场景另保留真实模型输出及人工审阅。

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| P01 | 只提供人工智能专业 | 作为专业保存和检索，不自动生成兴趣或职业目标。 |
| P02 | 专业＋“把东西真正跑起来的过程” | 专业检索保留；兴趣不成为职业名称，不再返回截图中的无关案例冒充相关结果。 |
| P03 | 专业＋“调bug” | 不按“调”模糊查出调香师或旅行社计调作为专业相关职业。 |
| P04 | 明确说对人工智能感兴趣但未说明专业 | 保存领域兴趣，不推断专业。 |
| P05 | 想了解算法工程师 | 职业关注为了解状态，不成为已选方向。 |
| P06 | 兴趣、明确职业关注和方向方案同时存在 | 各自用途与状态正确，专业结果和方向结果不互相冒充。 |
| P07 | 一次调试经历及开心感受 | 原始经历一份，偏好关联来源，不直接生成能力或岗位适合度结论。 |
| P08 | 用户说自己擅长编程 | 标为自评，不伪称作品或外部核验支持。 |
| P09 | 不喜欢某活动 | 保存具体否定偏好，不变成“没有兴趣”或另一个肯定身份。 |
| P10 | 引用同学的想法、假设、例子 | 不记录为本人事实；来源文本相同也不代表语义成立。 |
| P11 | 上周没时间、本周有时间 | 按有效范围使用，不固化或覆盖成永久属性。 |
| P12 | 学籍记录与转专业自述 | 处理时间与冲突，不用简单来源优先级覆盖全部历史。 |
| P13 | 本会话不保存，之后多轮、换题或更正 | 所有自动提取入口持续禁止长期写入，不能等拒绝原文离开上下文后恢复写入。 |
| P14 | 不保存要求所在回复失败、断流或服务重启 | 已生效的限制保持有效；重试不重复写入。 |
| P15 | 账号级关闭自动记忆 | 新旧会话、主工具、补充提取和后台入口均遵守。 |
| P16 | 只保存一条 | 只写明确对象，不恢复其他自动记录。 |
| P17 | 单条禁止记录 | 对应内容及派生提取不保存，其他合法记录不受无关扩大限制。 |
| P18 | 临时会话 | 工作内容不自动转成长期画像，保存口径与实际行为一致。 |
| P19 | 补充信息、闲聊和临时状态 | 正确决定是否值得长期保存，不能全部进入“其他”。 |
| P20 | 补充信息重新归类 | 保留真实出处、无重复事实，不添加经济或人格等未提供推断。 |
| P21 | 更正经历中的关键事实 | 相关理解与推荐失效或待核对，未经重新计算不显示新结论。 |
| P22 | 删除一条信息 | 从模型上下文、摘要、关联读取和缓存中排除，不能通过旧资产恢复使用。 |
| P23 | 同账号多个会话、多个账号 | 来源、策略和修改范围不串用，其他账号的真实消息 ID 也不能作为证据。 |
| P24 | 两个标签页并发编辑、重复请求 | 版本冲突可见，幂等有效，不静默覆盖或重复新增。 |
| P25 | 无效来源、删除来源、助手生成来源 | 不写成有证据的用户事实，不伪造引用补齐。 |
| P26 | 资料导入与后台补充任务 | 走同一权限与版本边界，事务失败无部分事实或孤立派生结果。 |
| P27 | 检索空结果、部分失败、模糊匹配 | 状态和相关性准确，不推断平台未收录，不把任意案例当对口职业。 |
| P28 | 迁移旧兴趣与职业关注别名 | 保留原文及来源，不自动提升关注状态；预览、重跑和回退可验证。 |
| P29 | 兼容旧读接口及撤除旧写路径 | 当前值投影一致，旧提取器不能绕开新策略重新写入。 |
| P30 | 无画像、只做普通咨询 | 能直接回答，不强制建档、补齐分类或写画像。 |
| P31 | 真实多轮对话采集 | 有用反馈与了解交替，不无限盘问、重复索取、过早归因或布置任务结束交流。 |
| P32 | 用户查看与控制，桌面和手机 | 来源可理解，确认/更正/删除可实际完成；无虚构分数、成功提示或不可用入口。 |

## 12. 实施时仍需定稿的事项

正式类型 schema、每类容量和有效期、历史记录保留与实际删除流程、旧 API 兼容期限，需要在实现评审中明确。自然语言记忆策略识别要有真实多轮评测，不能只验证模型能输出策略字段。上述待定事项不影响已确认的原则：专业、兴趣与职业目标分开，统一写入，限制由服务端执行，来源和推测分开，按用途读取。
