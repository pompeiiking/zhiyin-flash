# 职引 · 学生端重设计演示

> 大学生生涯规划与就业指导智能支撑平台 —— **前端重设计的第一版演示**
>
> 这是一个**独立工程**：不依赖后端、不碰 `zhiyin-src/template/zhiyin-web` 的现有代码，
> `npm run dev` 就能跑。数据是预置的，交互是真的。

---

## 一、这一版在回答什么

按评审要求做三件事，改动都落在这个工程里：

| 评审要求（原文） | 这一版怎么做 |
| --- | --- |
| 配色体系要求：禁止自定义乱配颜色，参考 DeepSeek、Codex、河大门户的红蓝+深灰配色体系，主色不超过 3 种 | 只留 **蓝（主）/ 红（辅）/ 深灰（骨架）** 三支。全部色值在 `src/styles/tokens.css`，组件里不出现任何颜色字面量。`/spec` 页把三支主色、12 级灰阶、对比度硬线全列出来，色值直接从 `:root` 读回，所以它永远等于界面真实用色 |
| 交互设计要求：界面需简洁清晰，加入明确的操作引导与状态导航，抛弃现有手写类不符合简洁要求的设计元素 | ① 顶栏下面一条**状态导航**：认识你 → 你的报告 → 选一个方向 → 今天要做的事 → 回头看看（内部五环节的名字一律不上界面）；② 每处功能顶部一条**可收起引导**，写清"这里做什么、下一步去哪"；③ 手写体（站酷快乐体）、roughjs 手绘框、手绘光标、手绘地图**全部移除**，换成系统字体栈 + 1px 描边 + 灰阶分层 |
| 场景化设计：按一年级到四年级的不同使用场景设计内容，每个操作步骤配对应界面截图 | 顶栏有**年级切换器**（大一 / 大二 / 大三 / 大四），切一次换掉**一整套内容**：任务清单、画像进度、里程碑、报告重点、复盘关注点。四套任务是真的重写过（大一是"弄清专业能干什么 / 找个学长聊 15 分钟"，大三才是"改简历 / 投 3 家"）—— 只换标题不换事，界面上一眼就能看穿。`#/path` 页给出四个年级的完整场景 + 一条**七步操作路径**，每一步嵌一张**真实界面截图**（`scripts/shots.mjs` 用无头 Chrome 生成，不是设计稿） |
| 产品逻辑优化：仅区分学生端、系统管理员端两个层级；核心定位调整 | 这一版只做**学生端全流程**（评审选择的范围）。管理员端是独立的一块，不在本次演示内 |

另外移除了第四种及以上的色相、彩色阴影、玻璃拟态、大渐变、emoji 图标 —— 理由逐条写在 `/spec` 的「明确不做的」一节，防止下一版又加回来。

**门户为什么只有一个入口**：评审原话「门户页尽量简洁（操作层面），最好只有一个入口」。
上一版门口摆着 9 张任务卡 + 五步旅程图 + 4 张年级卡 + 3 张信任卡 + 2 个按钮 ——
每一件单独看都有道理，合起来是让用户**站在门口先做一道选择题**（"你现在最想解决的是哪件事？"），
而这恰恰是产品承诺要替他省掉的成本。现在门户只做三件事：一句主张、一句成本 + 隐私、**一个「开始」**。

**但"只有一个入口"不等于"一片空白"**（评审下一轮原话：「整体太空了，没有任何特色」）。
入口保持一个，把空的部分填成**信息节奏**与**质感**，而不是填成更多按钮。
节奏照 DeepSeek 官网首页（`deepseek.com`）：

| DeepSeek 入口页 | 这里 |
| --- | --- |
| `# 探索未至之境`（标题 4 字） | `知道下一步`（5 字，字号 clamp 44–76px） |
| `深度思考智能搜索`（副标题说品类） | `大学生生涯规划与就业指导智能支撑平台` |
| 3 个入口 | **1 个入口** |
| 分组页脚 + 备案信息 | 一行页脚（演示环境说明 + 一个 meta 链接） |

原来的长主张（"说不清自己适合什么？从一个答得上来的问题开始"）**从标题降级成了正文里的宣传语位置**，
最后由一句更短、更具体的替换掉 —— 见下。

**第三轮按评审意见又重排了一次**（原话：入口居中、重点突出、字太多、职引存在感低、背景能不能动）：

| 意见 | 处理 |
| --- | --- |
| 大一到大四「不是重点」 | **整段删掉**（它是解释，已经在 `#/path` 那一页里）。同时删掉三栏页脚与信任那一段 |
| 职引存在感低 | 品牌从顶栏挪进 hero：`职引` clamp 26–34px + **0.3em 字距** + 一个红方块标记，读起来是一个标志而不是一行字 |
| 重点不突出 | `知道下一步` 放到 **clamp 48–92px**，是全页最大的东西；层级变成 主张 > 品牌 > 其他 |
| 文字太多 | 门户可见文字压到五行：品牌 / 主张 / 一句宣传词 / 一个按钮 / 一行成本。可点元素**只有 2 个**（1 个真实动作 ＋ 登录态入口）—— 曾经还有第 3 个 11px 的「设计规范」meta 链接，按"门户只有一个入口"已移除（见文末【当前状态】） |
| 入口居中 | hero 全部 `align-items: center; text-align: center` |
| 背景能不能动 | 能，见下 |

**宣传词是自己写的**：「每天只推一件事，并且说清为什么是现在」。
它一句话交代了三件事 —— 频率（一天一件）、量（就一件）、依据（为什么是现在），
而且没有一个"智能 / 赋能 / 一站式"这类空词。

背景三件，全部代码还原、**不引任何外部图片**（引位图会带进第四种颜色，也多一个网络请求）：

| 层 | 做法 | 出处 |
| --- | --- | --- |
| 品牌色光晕 ×2 | 两片径向渐变，**34s / 46s 各自漂移**，只动 `transform` | DeepSeek 官网首页的做法（+ 让它动起来） |
| 颗粒 | `feTurbulence` 内联成 data URI，给近白底"纸"的质感 | designeer 清单里的 [Fffuel](https://www.fffuel.co/) · `nnnoise` |
| 版面竖线格 | 280px 一道 1px 竖线，径向 mask 从中心淡出，当"刻度" | designeer 清单里的 [Fffuel](https://www.fffuel.co/) · `ooorganize` |

动态的三条口径：① 两片光晕周期**故意不同**，同步的循环一眼就看得出"在放动画"；
② 只动 `transform`，不触发布局与重绘；③ **颗粒刻意不动** —— 它压在文字底下，动起来字会发飘。
系统 `prefers-reduced-motion` 下整个装饰层不渲染（见文末【白屏的真凶】—— 只停动画会触发 Chrome 的绘制缺陷）。

页底色换成 `#f9f8f8`（DeepSeek 的 `--ds-color-bg-page`）：比纯白有纸感，是让大片留白"不空"最省的一步。

---

**导航为什么不做成"五步流程"**：上一版那条横条有编号、有连线、有"你在这儿"。
评审一句话点破了它的问题：「这种呈现方式会让用户认为必须一点一点做，按顺序才行」——
对，编号 + 连线 + 进度点就是**向导（wizard）**的视觉语法，而产品的价值恰恰相反
（一次只推一件事，随时可以从任意一处进）。

所以这一版把**导航**和**进度**彻底分开：

| | 放在哪 | 语法 |
| --- | --- | --- |
| 导航（能去哪） | 顶栏下面一条 Tab，**无编号、无连线、无"你在这儿"** | Tab 的语法是"去哪里"，不规定顺序 |
| 进度（走到哪了） | 各页自己身上 —— 画像"还差 3 条"、报告"第 3 版"、我的事"现在要做的 3 件" | 状态属于内容，不属于常驻外框 |
| 五步模型（怎么走） | 「大一到大四」那一页里讲，配七步操作路径与截图 | 它是**解释**，不是每天要看的导航 |

多出来的入口（大一到大四、设计规范、以及以后会加的）走 `⌘K` 命令面板，不往导航条里塞 ——
顶栏只放 5 个并列的地方，超过就该分组或收进搜索。

**为什么不用 Element Plus / Naive UI / shadcn-vue**：这一版要验的是**一套新的视觉语言**，引入组件库等于先接受它的观感再往回改，成本比手写高。图表同理 —— ECharts 自带的调色板会出现三支主色之外的颜色，所以四张图表都是手写 SVG，颜色只能取令牌。
（如果后续要正式落地，`vue-pure-admin + Element Plus + Element-plus-X` 那条组合更适合做管理端与流式对话，这一点在调研里有记录。）

## 四、演示建议动线（约 5 分钟）

1. **门户**（`#/`）——一句主张 + 成本先说清（5 分钟 / 0 张表 / 随时停）+ 隐私说明在首屏。右侧旅程图回答"你在哪、能去哪、先做什么"。
2. **切一次年级**——顶栏点「大一」，任务卡组、里程碑、画像进度整套换掉；这就是场景化设计。
3. **对话**（`#/chat?as=mid`）——点一个选项（能用点就不打字）；看**交接卡**：谁接手、为什么、凭什么。
4. **对你的了解**（`#/profile`）——点开任意一条，看它从哪来、有多大把握、什么时候记的。缺口 2 条也写在明面上。
5. **你的报告**（`#/report`）——L1 只有"结论一句 + 把握 + 门槛解释"；点"看分值、走势与来源"才展开 L2。红框那句是重点：**"差 4 分，是补起来最快的一个"**。
6. **选方向**（同页下半）——选主攻，看右侧「跟着改的地方」列出 4 处；改选另一条，看变更说明。系统不替你选。
7. **计划与行动**（`#/plan`）——勾掉一条，回「我的事」看三组计数与"因为做了什么，所以哪里变了"。
8. **回头看看**（`#/review`）——归因只三选一：任务太大 / 方法不对 / 方向要重估。点"看一次主动干预长什么样"。

想演"客户十幕主线"就照 `docs/职引-完整设计文档.md` 的 14.2 一节走，这一版的界面落点与那十幕是对得上的。

## 五、这一版**没有**做的（说清楚，别当成做了）

- **系统管理员端**：评审选定的首版范围是学生端全流程，管理端（数据看板、学生管理、内容与模型配置）还没做。
- **真实接口**：所有数据是预置的（`src/data/student.ts`）。没有接 `zhiyin-src/template` 的后端，也没有流式输出 —— 对话里那 520ms 的"正在看你的情况…"是模拟，不是真调用。
- **两个已知的简化**：聊天的关键词话术表只实现到能演示交接的程度；报告导出走浏览器 `window.print()`，不是服务端导出。
- **PPT**：评审意见里还有「PPT 内容整改」一整块（标题改为"大学生生涯规划与就业指导智能支撑平台"、删冗余汇报类表述、按年级配界面截图），那是另一件事 —— 不过这一版生成的 `public/shots/` 截图可以直接拿去做 PPT 的配图。

## 七、皮肤：三条轴，18 种组合

顶栏右侧「皮肤」按钮，或按 <kbd>⌘K</kbd> 搜"皮肤"。选择存在本地（`localStorage`），
也可以写进地址栏发给别人（`?query` 不落盘，不会覆盖对方的偏好）：

| 轴 | 属性 | 档位 | 换什么 |
| --- | --- | --- | --- |
| 主题 | `data-theme` | 浅色 / 深色 / 跟随系统 | 全部颜色 + `color-scheme` + 阴影 + 描边强度 |
| 主色 | `data-accent` | 河大蓝 / 河大红 | `--c-primary` 一族 + 图表主序列 + 焦点环 |
| 风格 | `data-style` | 极简 / 柔和 / 紧凑 | 圆角、阴影、**间距阶梯 + 行高 + 字号**（真正决定"一屏几条"）、入场位移 |

**风格轴的密度是 2026-10-11 改造过的**：原先两档只改 `--card-pad`（24 → 32 / 16）与圆角，
1600×1100 全屏像素比对下来，与默认档**平均只差 2.3–3.0 灰阶**、明显差异像素 6–8% ——
用户的原话是"变化不明显"。原因很直接：页面里绝大多数间隙走 `--sp-*` 阶梯，
卡片内距只管卡片自己那一圈，"一屏多看几条"当然不成立。

现在把 `--sp-3..--sp-7`、`--lh-normal`、圆角与卡片内距一起算进密度（**字号不参与**，理由见下），改完后同一组比对：

| 对比 | 改造前（明显差异 / 平均差） | 改造后 |
| --- | --- | --- |

**【第四条轴「动效」（完整 / 克制）已于 2026-10-11 删除】** 三个理由：

1. 它和 `prefers-reduced-motion` 是同一件事的两种说法，而后者是无障碍刚需 ——

2. 它带来的差别只有一组时长令牌，用户在界面上几乎看不出变化，属于"一条看起来像坏了"的轴；
3. 它还把门户整页搞白过（见文末【白屏的真凶】）—— 一个既看不出用、又会出致命 bug 的开关，

## 八、动效：只动"状态真的变了"的地方

判据是**频率**，不是"哪里能加就加"：

| 场景 | 数值 |
| --- | --- |
| 路由切换 | `opacity` + `translateY 6px`，160ms ease-out（只做入场，不做退场） |
| 列表逐条入场 | 间隔 40ms、位移 8px、单条 240ms（上限 8 条，且只在这一屏第一次出现时） |
| 数字滚动 | 420ms ease-out（分值、条数、百分比；`prefers-reduced-motion` 直接给终值） |
| 进度 / 分值条 | `transform: scaleX`，250ms（用 transform 而非 width，避免触发布局） |
| 步骤推进 | 圆圈填色 180ms、连线 240ms、对勾 `0.9→1` 淡入 |
| 悬停（颜色） | 150ms `ease`，且位移类一律包在 `@media (hover: hover)` 里 |
| 按下反馈 | `scale(0.98)`，150ms |
| 浮层 / 下拉 | 180ms ease-out，`scale(0.97) → 1`，`transform-origin` 在触发点 |
| 对话 | 主理回答**逐字出来**（按字数夹 320–900ms）+ 生成中三点脉冲 |
| 换肤 | 切换瞬间**禁用一切过渡** → 整页 160ms 淡入 |
| 键盘发起的动作 | **不做动画** —— 命令面板（⌘K）刻意没有开合动画 |

曲线只有三条，都取自生产 CSS 实测：`--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`
（= Linear 的 `--ease-out-quint`）、`--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)`、
`--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1)`。UI 动效一律 < 300ms，
数字滚动属"数据揭示"单独放宽到 420ms。

1. **表头/小标签不加 `letter-spacing`、不用 `uppercase`** —— 中文没有大小写，加字距只会把汉字拆松（原来侧栏的"学生端"就是这么写的，已改）。
2. **正文行高给到 1.7** —— 汉字是满框字，上下没有西文升降部的缓冲；按西文的 1.5–1.6 排出来会挤。

4. **当前步用"半填充圆"而不是实心圆，已走过的连线改主色** —— 实心圆是"已完成"的语法（照 Carbon 步骤条改的）。
5. **层次用同色相的不同透明度表达，不引入第四色相** —— 圆点、门槛线、侧栏选中态全部如此。
6. **输入框自动增高（上限 240px）、Enter 发送 / Shift+Enter 换行** —— 生涯规划的追问经常要写两三句，单行框会把话截断。

### "链接有时候打不开"：两个具体原因，都已修

这不是服务器不稳，是两个可复现的原因：

1. **登录态只存在内存里，而内页需要登录**。`router.ts` 的门禁对未登录访问内页一律弹回门户
   （`/?signin=1`），而 `store.ts` 里没有任何持久化 —— 所以**点着走进去能看，一刷新、新标签页、
   或把裸 URL 粘给别人就打不开**。这正是"有时候"的来源。
   修法：登录态落 `localStorage`（登一次，之后所有标签页与刷新都算已登录，「退出登录」清掉它）；
   并且**未登录直接打开内页时静默落到演示账号 `mid`**，不再弹白墙 ——
   演示里链接就是评审的主要入口，一个"请先登录"等于链接坏了。门户上的登录/退出流程照旧。
   **回归证据**：`link-bare-chat.png` 与 `link-bare-report.png` 就是**不带 `?as=`** 拍的裸链接截图。
2. **只绑 IPv4，而且端口宽松**。`vite.config.ts` 里 `host: '127.0.0.1'`（实测 `[::1]` 连不上，
   `localhost` 与 `127.0.0.1` 都可以），并且原先是 `strictPort: false` ——
   **5273 被占用时 Vite 会悄悄换到 5274**，而评审手上的链接写死 5273，于是又是"有时候打不开"。
   已改成 `strictPort: true`：端口被占**直接起不来并报错**，宁可失败得看得见，也不要悄悄换端口。
   （这条改动要**重启 dev server** 才生效；当前实例仍在 5273 上正常服务。）
3. **"刷新后闪一下正常界面、然后变白"**的第三个原因：**懒加载的路由组件那一刻没拉到**。
   壳mount上了、页面先正常渲染，随后 `() => import('./views/XxxView.vue')` 失败
   （dev server 正在被写文件时，Vite 会返回 500；日志里能看到 `EBUSY` / `ENOENT` /
   `Pre-transform error` 这一类的记录），vue-router 拿不到组件，`<RouterView>` 就渲染成空的 ——
   而**白屏不报错、不提示**，看起来就是"坏了"。
   已加两层兜底，不再靠"多刷几次"：
   - `router.onError` → **自动整页重载一次**（`sessionStorage` 记一次防死循环，下次导航成功即清掉，所以偶发失败始终能自愈）；
   - `main.ts` 里兜住 Vue 渲染期异常与全局未捕获异常 / 未处理的 Promise → 画成底部一条**看得见的说明**（含"刷新一次"的指引），而不是留一个白页。
     这块提示的颜色是**故意写死的字面量**：它必须在样式表本身没加载成功时也能看见，是全工程唯一允许出现颜色字面量的地方。
   **验证方式**：临时加了一个 `?boom=1` 触发点、确认提示真的画出来（截图存证），随后把触发点删掉并核对 `main.ts` 已无残留。
4. **"完全空白、连提示都没有"**：说明异常发生在 `main.ts` 注册兜底**之前** ——
   `import` 语句先于模块体执行，一旦入口模块或它 import 的某个模块在求值时就抛，
   `main.ts` 里那两行兜底根本没机会跑。
   所以兜底必须前移到 `index.html` 的**内联脚本**（它一定能执行），并加一个**看门狗**：
   几秒后 `#app` 仍是空的就把原因与当前 URL 写出来。它能抓到三类情况：
   资源加载失败（入口模块拉不到 / 解析失败，只有捕获阶段收得到）、未处理的 Promise 拒绝、
   以及"入口没挂载"。
   **两个方向都验证过**：
   - 正常加载、9 秒虚拟时间 → **不误报**（截图确认页面干净）；
   - 临时把入口指到不存在的模块 → **立刻报出**「资源加载失败：…/src/\_\_missing\_entry\_\_.ts」（截图存证），
     随后把入口改回并核对无残留。
5. **"完全空白、无红字"**的第二个（也是更常见的）原因：**地址匹配不到任何路由**。
   原先没有兜底路由，`#/` 后面一旦匹配不上，`<RouterView>` 就什么都不渲染 ——
   **外壳（顶栏）在、中间全空、控制台一点报错都没有**，所以看门狗也不会触发。
   截图 `_nope.png`（当时的状态）与 `not-found.png`（现在）对比就是这件事。
   已加 `/:pathMatch(.*)*` 兜底路由（**必须放最后**，标 `public`：坏地址不该再触发登录），
   渲染一个说明页：这是什么情况、**现在有效的地址有哪些**、以及一条退路。
   **验证方式**：`node scripts/shots.mjs` 里的 `not-found.png` 就是访问 `#/nope-does-not-exist` 拍的。

   **这条排查值得记一笔**：前四种原因我都做了兜底，但真正命中你那次的是第五种 ——
   一个**不抛任何异常**的空白。所以"加了错误兜底"不等于"不会白屏"：
   还要问"有没有一条路径是**正常地**什么都不渲染"。路由兜底补的就是这一条。

### 白屏的真凶：那条「动效」轴（已修，随后整条轴删除）

前面四种原因都不是你遇到的那个。真凶是**皮肤第四条轴（动效=克制）**：

- **症状**：`data-motion="calm"` 时门户**整页白**。DOM 完好（81185 字符，与正常时逐字相同）、
  控制台**零报错**、暗色主题下**连页面底色都不画**（全图 960000 像素全是 `#ffffff`）；
  其它页（对话 / 规范）都正常，所以只在门户上出现。
- **触发**：皮肤存在 localStorage 里。**无痕窗口没有这份存储 → 一切正常**，
  普通窗口里有 `motion: calm` → 门户白屏。这就是"有时打得开有时打不开""无痕能开"的全部原因。
- **机制**：门户原来的 calm 规则是"**只停这几层的动画**"，但保留了底色、`filter: blur(60px)`、
  `mask-image` 与 SMIL —— 这个组合在 Chrome 里会让**整个文档的绘制失效**。
  二分定位：把整段 calm 规则停掉，页面立刻恢复（4 KB → 476 KB）。
- **同一处还有第二个受害者**：`@media (prefers-reduced-motion: reduce)` 写的是同一套规则 ——
  **开了系统"减少动态"的用户本该看到更安静的界面，实际看到的是一片白**。
  这一条比上面那条严重得多（无障碍刚需），修法同样是**整层不渲染**。
- **处置**：先修（`prefers-reduced-motion` 保留，走"装饰层整层不渲染"）；
  然后**把这条轴整个删掉** —— 见第七节的三个理由。
  减少动效从此只有一个来源：系统的 `prefers-reduced-motion`。
- **验证**：`--force-prefers-reduced-motion` 与正常加载两种路径，
  由 `portal-reduced.png` 与其余 24 张截图守着。

### 文案语气：三档，按场合分工（2026-10-11 立）

评审反馈"系统的文字几乎全是口语化的"。核对下来要分清一件事：
**内页口语化是设计文档 7.4 的明确要求**（为用户省理解成本：不上环节名、不上黑话、
"答不上来可以跳过"这种话就是产品的一部分），所以不能一刀切改正式。
真正错的是**该正式的地方也用了口语**。现在按场合分三档，改文案前先认准自己属于哪一档：

| 档 | 适用范围 | 口径 |
| --- | --- | --- |
| **一 · 说人话** | 操作引导（`GUIDES`）、空态正文（`EMPTY_COPY`）、按钮与状态标签、把握程度标签（"还不好说"） | 亲切、短句、可跳过。这一档的口气**不要**改成正式 |
| **二 · 正式** | 平台自述、数据与隐私、故障与降级（`FALLBACK_COPY`）、演示声明、费用与责任 | 中性、精确、可追责；不用"好像／随便／接着来"，**也不出现任何工程词** |
| **三 · 随意** | 代码注释、规范页 `#/spec` | 读者是开发与评审，不必收敛 |

这一轮按第二档实际改的（都是用户可见的）：

- `FALLBACK_COPY` 五条全部正式化，例如"网络好像断了…恢复后接着来" →
  "网络连接已中断。你已填写的内容不会丢失，连接恢复后可继续。"
- `AUTH_COPY`（登录屏讲的是"你的数据去哪了"）："登录一下，免得换设备就丢了" →
  "登录后，已答内容会保存到你的账号，换设备也能接着答。你的回答仅用于生成你自己的报告与计划。"
- **两处内部工程词跑到界面上**（这比口语严重 —— 用户看不懂）：
  "报告不**渲染**空壳" → "报告不会预填内容"（`EMPTY_COPY.reportBody` 与 `ReportView` 空态各一处）
- "点开可以**盘问**" → "点开可以看到它的依据"（`GUIDES.profile` 与 `PathView` 各一处）——
  "盘问"带对抗语气，而它出现在平台的信任说明里
- `AuthLayer` 的"密码随便填一个就行" → "演示环境：密码可任意填写"

**同时删掉两块死文案**（`HOME_COPY` / `TRUST`，全仓库零引用）：没人读的文案只会与真实口径悄悄分叉。

**没有加"文案风格开关"**：口语↔正式不是皮肤 —— 它改的是**意思与长度**（会撑坏版面），
而且每一句都要维护两份、必然随真实口径分叉；更重要的是，"说人话"是这个产品的立场，
把它做成可选项等于承认它只是个口味。**该正式的地方写正式，其余地方保持说人话。**

### 结构名换成正式用词（导航 + 页面标题，2026-10-11）

评审要求"导航栏换成正式的"。**导航栏与页面 H1 共用同一套名字**，所以要一起改
（否则同一处会有两个名字）。改动如下：

| 原来 | 现在 | 为什么 |
| --- | --- | --- |
| 我的事 | **任务与计划** | 口语；这一节装的正是"今日任务 + 计划与行动"，用内容命名更准 |
| 今天要做的（子项） | **今日任务** | 结构名用名词短语 |
| 对你的了解 | **学生档案** | 2026-10-11 客户定名（备选是"情况了解"）。"档案"对上的是这一页的事实口径：条目 / 来源 / 把握度，也与方案 B 的"索引式档案页"同构 |
| 你的报告 | **评估报告** | 指代不明；"评估"点明这是对专业与岗位适配的评估 |

| 对话 / 计划与行动 / 报告 / 设计规范 | **不变** | 本来就是中性名词，不必改 |

同步的地方：路由 `meta.title`、命令面板的页面项、对话页右栏标题、首页画像卡标题、
各页之间的跳转链接文案、规范页上的状态导航示意。

**【这一改与设计文档 7.3「用户词对照表」冲突，是有意为之】**
7.3 之所以把这些结构名写成大白话，是为了**让学生不必学企业词汇**。
按评审要求把导航改成"学生档案 / 复盘记录"，方向正好相反。现在的处理是**分开两档**：

- **结构名（导航 + 页面 H1 + 跳转链接）→ 正式**：读者是学校与评审，这是平台的官方索引；
- **说明语（引导 `GUIDES`、空态 `EMPTY_COPY`、反馈与故障 `FALLBACK_COPY`）→ 保持亲切**：
  读者是学生，这里正是 7.4 要保护的语气。例如标题已经是「学生档案」，
  而页内引导仍是"这里是我们对你的了解。每一条都标了来源与把握程度"。

代码注释（档三）里保留旧称，因为那是工程视角的历史陈述，不是界面文案。

**为什么一直没被发现**：截图清单里有 4 种皮肤组合（浅/深 × 蓝/红），
**唯独没有覆盖"减少动效"这条路径**。现在 `portal-reduced.png` 是常驻回归截图
（`shots.mjs` 也支持了每张自带的 Chrome 开关）。**教训：一条路径没有被截图覆盖，
就等于没被验证过 —— 哪怕它有 CSS 在"看着像对的"。**

**排查方法上的教训**：我先连续试了五个假设（服务器、登录态、模块拉取失败、缺失路由、
`filter: blur`），全是错的方向；**最后是"二分"一击命中** ——
不猜机制，而是把可疑的那段规则整段停掉，看现象是否消失。

### 清晰度收敛：字号、版心、线、焦点（2026-10-11 第二轮）

客户原话：「别的导航界面我看着还是不美观，简洁大气」「每个界面的不够清晰，乱糟糟的」。
**先去测，不先改** —— 把"乱"拆成六个可数的量（`.tmp-research/lead-clarity.mjs`），
再把外部一手规范（NN/g、GOV.UK、IBM Carbon、USWDS、NHS）当判据（完整提案见 `.tmp-research/clarity-brief.md`）。

**改前 → 改后（实测，1600×1100）**

| 页 | 字号档 | 分隔线 | 最长段落（汉字/行） |
| --- | --- | --- | --- |
| 对话 | 5 → **3** | 15 → **4** | 46 |
| 任务与计划 | 7 → **4** | 7 → **4** | **58 → 29** |
| 学生档案 | 6 → **4** | **17 → 2** | 45 → **23** |
| 评估报告 | **9 → 4** | 8（真表格，保留） | 36 |
| 计划与行动 | 7 → **4** | 8（真表格） | 49 → **25** |
| 复盘记录 | 7 → **4** | 4 → **2** | 52 → **30** |

**四处改动**

1. **字号由 12 档收敛到 5 档**（`--fs-38 / 30 / 20 / 14 / 12`，相邻档差 ≥6px）。
   原来 11/12/13/14/15/16 六档全挤在 6px 之内、相邻只差 1px —— 读者分辨不出"这是另一层"，
   一屏数出 7–9 个字号，正是"大大小小、乱"的机械来源。
   层级改由**字重 + 留白 + 位置**承担（NHS 仪表盘规范："用不同的字重建立层级，在字号、粗细、颜色上保持一致"）。
   `check-contrast.mjs` 的 `FONT_SIZE_USES` 同步收敛；规范页 `#/spec` 里"字号只留八档"的旧表述也改成了五档。
2. **密度轴不再改字号**（原来 soft/dense 各推 `--fs-13/14/16` 一档）。
   缩字号是拿可读性换密度，而且会重新造出"12 与 13 只差 1px"。复测：**8.3 灰阶 / 12.4% 像素**仍明显。
3. **版心收到 40em**：`.page__sub` 原来是 `max-width: 60em`（≈**58 汉字/行**），
   而中文舒适区是 30–45 —— 改后 23–30 汉字/行（外部口径：GOV.UK 一行不超过 75 字符 ≈ 37–50 汉字）。
4. **非表格列表不再逐行画线**，改用留白分组（学生档案 17 → **2** 条、对话 15 → **4** 条）；
   **真正的 `<table>` 保留行线**（USWDS："表格就该像表格"）。
   另外 **`.focal` 那道 3px 主色左规退役** —— 焦点改由栏宽（主块 8 栏）+ 更大留白承担，
   不再"用装饰表达层级"（GOV.UK：分隔线是 opt-in；NN/g：加容器要克制，否则 create visual clutter）。

**顺带堵掉两个"绕过令牌"的口子**（都是这轮实测才发现的）：
- `CommandPalette.vue` 有一处硬编码 `font-size: 10px`，比最小的登记档还小，门禁却看不见；
- 报告页图表用了 **SVG 的 `font-size="10" / "11"` 属性**（7 处）—— 既不是 CSS、也不是令牌。
两种写法现在都会让 `check-contrast.mjs` 直接失败。

**没做的（如实记）**：`.tmp-research/clarity-brief.md` 里的 **P2-11**（把数据页的解释性文字重排成"标签—值"）
与 **P0-4** 的两条新尺子（文字墨迹起始线、Squint test）本轮未做。

### 四页版面重做：三种页面语法（2026-10-11 晚）

客户原话：「我说的是这四个界面**大改一下**，我感觉**里面的布局不好看，不清晰，对用户不友好**。」
并且明确：上一轮"只改字号 / 留白 / 分隔线"**没什么变化** —— **病在结构，不在皮肤**。

**根因（可命名）**：四页共用同一套"两个列 × 若干等重方块"的语法。
只调那套语法的参数，观感不会变。所以这一轮改的是**页面语法的种类**。

| 页面 | 语法 | 结构 | 出处 |
| --- | --- | --- | --- |
| 任务与计划 | **队列页**（账页） | 今天这一件 → 队列（三组）→ 学生档案 → 变化与支持 | [Every Layout Switcher](https://every-layout.dev/layouts/switcher/)：一宽一窄会被读成"故意不同、更重要"，这个读法是错的 |
| 学生档案 | **档案页** | `<dl>` 属性条（学校事实）→ 证据流（你说的 / 行为记录）→ 还差 3 条 → 采集动线 → 核验 | [Geist Table](https://vercel.com/geist/table)：键值元数据用 Description，**不是两列表格** |
| 评估报告 | **文章页** | 结论（通栏引文）→ 画像 → 三个分区 → 门槛 → 三条取舍 → 影响面 | [GOV.UK Inset text](https://design-system.service.gov.uk/components/inset-text/)：引文一页只用一次 |
| 复盘记录 | **文章页 · blameless** | 你动过 X% 的手 → 归因 → 时间线 → 两种说法 → 收起参数 | [Google SRE](https://sre.google/sre-book/postmortem-culture/)：先看"做到了什么"；"你不能修人，但能修系统" |

**版面基元只写在 `base.css` 一处**：`.ledger*`（账页 = 左侧 152px 标签格 + 内容 + 行尾动作，行尾动作与内容**同一行**）
与 `.article` / `.sec`（文章页 = 节标题 + 发丝线分节 + 原生 `<details>` 折叠）。

**实测（`lead-clarity.mjs`，1600×1100）**

| 页 | 语法 | 可见框 | 分隔线 | 左边缘种类 | 最长段落（汉字/行） |
| --- | --- | --- | --- | --- | --- |
| 任务与计划 | ledger | 7 → **3** | 4 → 3 | 7 → **4** | 58 → **29** |
| 学生档案 | article | 6 → **1** | 2 → 3 | 7 → **2** | 45 → **26** |
| 评估报告 | article | 6 → **4** | 8 → **5** | 8 → **5** | 36 |
| 复盘记录 | article | 14 → **6** | 4 → **2** | 9 → **4** | 52 → **30** |

**顺带修掉**：`评估报告` 里 `GuideNote` **渲染了两次**（顶部一次、旧 `.rail` 里又一次），评审会看到两条一样的引导条。

**判据也跟着换了一轮**：`lead-gate.mjs` / `lead-click.mjs`（按"索引栏条目"判的）**已经失效** ——
索引栏被拆掉之后它们会把这四页报成"未改造"。
现在由 `lead-clarity.mjs` 一份同时报 **语法 / 残留 `.rail` 数 / 节数 / 可见框 / 分隔线 / 字号档 / 左边缘 / 最长段落**，
`checks.py` 改问"旧的 `.rail` 还在不在、换成了哪种语法"。**换版式就要同时换尺子，否则等于没有尺子。**
