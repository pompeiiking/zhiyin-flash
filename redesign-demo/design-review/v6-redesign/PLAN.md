# 职引 · 全站重构契约（v6）

对象：`redesign-demo`（Vue 3 + Vite），基线 `新前端2@fa8edc9`，工作分支 `新前端4`。
本文件是**施工契约**，不是展示稿。任何页面改动都要能在这里找到依据；验收按第 8 节逐页过。

---

## 1. 目标与验收口径

一次能明显看出变化的全站整改：结构、视觉、体验三层同时提升。

- **不是**换颜色 / 改圆角 / 加阴影 / 塞图标。
- **是**重新组织页面与功能、给每类内容合适的视觉表达、把"要用户自己点开才知道"改成"一眼看见"。
- 验收看**实际页面**（1280 / 390 两档截图 + 真机手感），构建通过和测试数量只证明技术质量。

## 2. 信息架构：一份导航模型

现状：`lib/nav.ts`（旧 5 并列入口）与 `lib/workspace-nav.ts`（新 4 组）并存，17 条路由、5 个入口面、`/spec` 桌面无常驻入口、`/tools` 无分组归属、`/chat` 有 4 个入口、搜索有 2 个入口。

决定：

1. **收敛为唯一模型** `lib/workspace-nav.ts`。`lib/nav.ts` 及其消费方（`AppTopBar`/`CommandPalette` 死组件、`NotFoundView`）全部删除或改写。
2. **导航按"我现在要做什么"分组，不按产品循环分组**：

| 组 | 项 | 说明 |
|---|---|---|
| 对话 | 咨询对话（置顶，唯一主入口） | 产品主循环；门户 CTA 直达此处 |
| 了解自己 | 个人画像 · 诊断报告 | 我的情况与判断依据 |
| 做决定 | 方向方案 · 岗位资讯 | 比较与外部信息 |
| 去做 | 今日行动 · 阶段计划 · 日历课表 · 待办目标 | 执行与安排 |
| 回头看 | 复盘记录 · 成长记录 | 复盘与完成记录 |

   学籍与资料归入「了解自己」下方（它是画像的来源之一，不是并列业务）。

3. **门户 → 对话**：`/` 上所有主 CTA（开始第一个问题 / 登录后进入）一律落到 `/chat`，不得落到 `/home`。
4. **移出学生导航**（改为账号菜单或帮助入口，不再占导航位）：
   - `/spec` 设计规范 —— 内部文档，不该出现在学生导航
   - `/path` 大一到大四 —— 改挂「使用指南」
   - `/tools` 应用工具 —— 后端无数据时是空页，降级为「更多」里的次级入口
   - `/` 产品门户 —— 已登录用户不该被导航带出应用
5. **移动端**：底栏 5 项 = 对话 / 行动 / 画像 / 方向 / 更多，**「更多」必须有文字标签**（现状被 CSS 永久隐藏）。「更多」里是完整的分组目录，不允许把 7 个页面压成无标签图标。
6. **入口去重**：搜索只保留顶栏一处（桌面侧栏那个去掉）；版本记录只保留报告页内的能力，不在 4 处重复。
7. **断点统一**：只保留 3 档 —— `mobile < 768`、`tablet 768–1119`、`desktop ≥ 1120`。现有 11 个阈值全部对齐到这三档（`lib/layout.ts` 与 CSS 同步）。
8. **页内视图切换统一**为 Reka `PanelTabs` 或路由，禁止第三种本地 `ref` 实现。

## 4. 设计语言：动态、丰富、高级、不堆字

### 4.1 视觉语法

- **分层表面**，不是"卡片套卡片"：页面底 / 工作面 / 局部关注区三层，用底色、1px 描边、留白和极轻阴影区分。
- **每类内容有专属表达**，不再一律套同一种卡片：
  | 内容 | 表达 |
  |---|---|
  | 结论 / 判断 | 大字号主张 + 一行依据摘要 + 可展开证据 |
  | 依据 / 来源 | 编号证据行 + 来源徽标 + 时间 |
  | 行动建议 | 行动卡（做什么 / 多久 / 加入按钮） |
  | 进度 / 完成度 | 进度环 / 刻度条 + 分母文案 |
  | 时间 / 日程 | 时间网格或时间轴，不塞进卡片 |
  | 对比 / 选择 | 同刻度对照行 + 选中态 |
  | 存量数据（画像/成绩/资讯） | 结构化表格/列表 + 就地筛选 |
- **禁止**：大量文字罗列当作内容表达；无意义填空；装饰堆砌；所有内容同一张卡片。

### 4.2 小组件库（本次新建）

`MeterRow`（同刻度对照）、`Sparkline`、`ProgressRing`、`StepRail`（阶段）、`Timeline`、`StatTile`、`SourceChip`、`EvidenceRow`、`ActionCard`、`DecisionRow`（方向选择）、`CalendarGrid`、`DayColumn`、`FilterBar`、`SegmentedControl`、`Sheet`（统一抽屉）、`Toast`（统一反馈）、`SkeletonBlock`、`EmptyState`（升级版，带下一步）、`StatusBanner`。

全部基于 Reka UI 原语 + 自有 CSS 令牌；不引入第二套 UI 框架皮肤。

### 4.3 动效：界面本身要是"活"的

**完整口径见 [`DESIGN-LANGUAGE.md`](DESIGN-LANGUAGE.md)（含判定清单与反例表），以那份为准。**

摘要：**"活"不是"动得多"，是界面里存在只有"看一段时间"才能获得的信息。**
判定用**截屏测试**——静图不丢信息的就是死的。
对话页的活 = **过程可见**；数据页的活 = **组织可见**。
数据不动时，活来自**把组织权交还用户**（视角、粒度、顺序可重组）+ 结构/状态/溯源显形。

约束：动效必须**承载意义**；禁止装饰堆砌、无意义持续背景运动、粒子、发光边框、自动轮播；
`prefers-reduced-motion` 必须降级到可用形态；动效库已选 `motion-v` 2.7.0。
**需求方给的对白示例只是感觉参照，不是功能清单。**

#### 技术备注：`motion-v` 的 `layout` 在 2.7.0 实测不工作（2026-10-14）

画像页做"多视角重排"时逐帧采样验证（40 帧 × `getAnimations()` × computed transform）：
`<motion.div layout>` / `layoutDependency` / `LayoutGroup` 三种用法都**只写了 `transform-origin`，
全程 0 个动画、transform 恒为 `none`**。

→ **需要 FLIP 重排动画时不要依赖 `layout` prop**，改用自实现 FLIP：
pre-flush watch 量旧矩形（注意：此 Vue 版本里 `onBeforeUpdate` 触发时 DOM 已打补丁，不可用）→
`onUpdated` 后一帧量新矩形 → 按**稳定 key** 匹配（重渲染会替换 DOM 节点，按节点匹配会全部落空）→
反向 transform 再归零。`prefers-reduced-motion` 下整段跳过。

motion-v 仍可用作依赖（其余能力未否定），但**不要在没有逐帧验证前声称它做了重排动画**。

### 4.4 减少"点击才展开"

现状 51 处 + 6 处异步取数式展开。原则：

- **主信息默认可见**：结论、当前任务、关键字段、当天的课与事，不折叠。
- 折叠只留给**次要**内容（完整历史、原始证据全文、高级设置）。
- 一页最多 1 层折叠；现状报告页 5 层折叠必须压到 1 层。
- 需要用户先点才去取数的，改为进页自动取 + 骨架屏。

## 4.5 视觉方向已选定：C2「陪伴感 × 河大配色」（2026-10-14）

**背景**：前三轮直接在对话页上改，产出始终被评为"劣质、像十几年前的造物"。
根因不是细节不够，是**没有靶子**——六个杠杆（配色/字体/材质/深度/密度/动效）全在默认位置。
于是先做了三个真正不同的方向样张供选择：

| 方向 | 立场 | 自认风险 |
|---|---|---|
| A 工作台 | 密度 + 刻度 + 数字纪律 | 变成没人味的控制台 |
| B 编辑物 | 排印（46→11px 跨度、41 字版心、零阴影） | 变成挂在网页上的 PDF；密集交互不够用 |
| C 陪伴感 | 材质 + 温度 + 在场感 | 滑向通用 AI 应用模板 |

**需求方选定 C**，并要求按既定配色要求重做 → **C2**（`directions/c2-hbu/`）。

### C2 的定案

- **配色严格执行**：白灰为底与结构色（页面底 `--gray-50`，面为白玻璃，线 `--gray-200/300`，导航白灰、无大面积深蓝）；
  默认强调 **校徽蓝 `#0058A7`**，可切换 **官网红 `#96000E`**；两套都补齐梯度。
- **主题切换覆盖**（脚本逐项 diff 验证，浅/深各 24 项）：按钮、选中态、焦点环、图表、进度、徽标、头像。
- **对比度**（读**渲染出来的**底色，非算 token）：蓝浅 4.95 / 红浅 4.95 / 蓝深 5.52 / 红深 5.31 : 1，**无一走"大字放宽"**。
- **"温度"的迁移**（本方向的关键）：C 原本靠色相（暖沙 + 陶土）；色相被锁死后搬到四处——
  材质（真半透明分层 + 内高光/内描边）、光影（统一照明模型，大模糊 + 大负扩散）、
  头像在场感（腮红换成下巴背光/顶部镜面高光，**色相温度 → 明度温度**）、动效与排印节奏。
- **头像改为卡通**（需求方意见）：材质层从 4 层砍到 2 层，眼睛占脸宽 32%→34%，
  靠**轮廓与比例**而非明暗；守住"不低龄化"（不正圆、无腮红/符号、幅度 ≤1.12 倍）。
- **用户气泡改纯色**（需求方意见）：`background-image: none`，四组实测最低 4.74:1。

### 两处已知限制（不假装解决）

1. **深色主题下红蓝两套的气泡填充完全相同**（`#1b1b1d`），色相只在 1px 边上——
   深色里用"主色浅档"会掉到 3.3:1 或让气泡比页面底更暗。要解决需新造**深色专用低饱和色阶**。
2. 40px 下"思考/待命"的眉几乎不可见，两态差别主要靠六点轨道。

### 下一步（尚未开始）

1. 把 C2 固化成**能落到 `tokens.css` 的令牌与组件原语**（还掉审计指出的"§4.2 列 19 个组件、只落地 1 个"这笔账）
2. 用这套组件**重做对话页**，之后才是其余 16 个已审未改的区块

## 6. 样板页（先做这三块，确认后再铺开）

1. **应用外壳**：唯一导航模型 + 顶栏 + 桌面侧栏 + 移动底栏 + ⌘K；入口去重；断点三档。
2. **咨询对话 `/chat`**：顶部动作 → 稳定阅读列 → 固定输入区。必须区分：用户发言 / 顾问回复 / 重点 / 顾问交接及原因 / 行动建议 / 后续问题 / 来源与证据。右侧画像不常驻、保留入口。
3. **诊断报告 `/report`**：短结论 + 最关键差距 → 章节导航 → 维度解释 →（按需）分值与证据；同刻度表达「自身值 / 要求值 / 差距」；版本视图讲清变更。

## 7. 后端能力覆盖

后端 91 个接口（`/api/v1/app/*` 51 + `/developer/*` 39 + `/healthz`）。前端 `api/operations.json` 已登记 50 条，但**大量登记无调用点**。

要求：学生端可见的后端能力必须有对应页面或入口。待补的关键落点（据后端盘点）：

- `pipeline_cards` / `disclosure` / `renderables`（含 `bars_chart`）/ `intel_refs` / `theory_refs` —— 对话内管线卡、告知行、可视件、来源链，目前**无可视件分发组件**；
- `menus` / `routes` / `task_entries` / `copy_bundle` / `feature_flags` —— 全未消费，导航与文案仍写死在前端；
- `collection_panel`（还缺什么 / 去哪取 / 为什么 / 可直接执行的 `ask`）、`report_panel` / `plan_panel` / `action_panel` / `review_panel`、`layout_panel` / `coach_messages` / `dependencies`、画像 `coverage` / `overall_confidence`。

已知量纲风险：后端分值为 **0–1 浮点**，前端演示数据用 **0–100 整数**，`validate-ai.ts` 只校验 `number`，切换数据模式后同一组件会用两种量纲渲染而不报错。所有图表必须统一到 0–1 并在展示层格式化。

范围待定：`/developer/*` 39 条（管理/开发端）——当前无页面，且不属于学生端，默认**不在本次范围**，需确认。

## 8. 逐页验收清单

对**每个**页面 × 8 维度打分并留证：

1. 导航结构、功能分组、页面衔接
2. 布局、区域比例、对齐、阅读顺序、空间分配
3. 信息层级、主次、内容密度、留白、渐进展开
4. 字体、字号、字重、行距、长文本阅读
5. 组件形态、组合方式、视觉与交互一致性
6. 图标、图表、图形的实际作用（是否有意义）
7. 动效、操作反馈、加载/空白/错误/成功状态
8. 桌面与移动端的布局、交互与整体协调

另加四项硬检查：变化是否充分 / 主要内容是否突出 / 操作是否自然 / 功能是否保留。

证据：`design-review/v6-redesign/screens/` 下 1280 与 390 截图，逐页对比 `_shots/baseline`。

## 9. 边界

- 只做前端，**不接真实数据**；字段定义以后端为准（见后端盘点）。
- 演示数据要丰富、跨页连贯；示例与真实数据清楚区分。
- 门户页构图与品牌基本保留，只做协调性精修。
- 完成后推送 `新前端4` 分支。
