日期：2026-10-14 ｜ 评审方式：**只读**——Playwright 截图 + DOM/像素实测，未修改任何源码

## 1. 判决：为什么它"像十几年前的造物"

三条，每条都可核对。

### 判决 1 ｜整个界面没有任何"边缘"——分层与阴影全部低于人眼阈值

设计语言自认有三层表面（`CRAFT-BRIEF.md:443-453`：L0 `#f7f6f6` / L1 `#ffffff` / L2 `#fafafa`）。
实测这三层之间的关系，全部落在 **1.04–1.08 : 1**：

| 关系 | 实测对比度 | 判据 |
|---|---|---|
| L1 纸面 `#ffffff` 压在 L0 页底 `#f7f6f6` 上 | **1.079 : 1** | 感知边缘通常需 ≥1.3:1 |
| L2 `#fafafa` 压在 L1 `#ffffff` 上 | **1.044 : 1** | 无边缘 |
| 结构色 `--c-border` `#e1e5ee` 压在纸面上 | **1.262 : 1**（`tokens.css:197`） | 细线勉强 |
| `--c-border` 压在页底 `#f7f6f6` 上 | **1.17 : 1** | 几乎消失 |
| 阴影 `--e-1` 峰值 vs 白（实测像素 `#f6f6f6`） | **1.081 : 1** | 不是阴影，是脏 |

像素直接验证（`chat-1280.png`）：
- 纸面左缘 x=286…292 是一段 `#ffffff → #fcfcfc` 的衰减——**7px 内只暗了 1 级灰**（`--e-1` = `0 1px 2px rgba(13,13,13,.06)`，`tokens.css:277`）。
- 行动卡左缘 x=357…363 是 `#fdfdfd → #f6f6f6`——**同样只是 1 级灰**（`--e-2`，`tokens.css:278`）。
- 侧栏内部像素 `(140,600)` = `#f7f6f6`，侧栏外侧 `(250,600)` = `#f7f6f6`：**导航栏和页面底完全相同，没有任何边界**。

白底占屏幕像素的 **91.7%–96.4%**（5 个路由实测，`probe.json → pixelQuota.whitePct`）。
在一个 96% 是白的界面上，1.26:1 的线和 1.08:1 的影**不存在**。
结果就是一整片没有形状的白——这不是"极简"，这是**没画完**。

> 关键区分：这不是"影太少"的问题。`CRAFT-BRIEF.md:666` 明确"不给所有卡片加阴影"是对的。
> 问题是**该有的三处也只有 1 级灰**（纸面 / 行动卡 / composer），于是"纸面有影、卡无影"这条规则在屏幕上**看不出差别**。

### 判决 2 ｜字号阶梯是倒的：最小的字承担最多的内容

实测每页可见文本节点的字号分布（`probe.json → fontSizes`）：

| 页面 | 12px | 14px | 16px | 20px | 30px | 12px 占比 |
|---|---|---|---|---|---|---|
| `/chat` @1280 | 46 | 61 | 2 | 7 | 0 | **40%** |
| `/chat` @390 | 53 | 47 | 2 | 7 | 0 | **49%** |
| `/profile` @1280 | **232** | 93 | 34 | 6 | 2 | **62%** |
| `/profile` @390 | **223** | 67 | 34 | 6 | 2 | **62%** |
| `/report` @1280 | 75 | 100 | 26 | 8 | 1 | 36% |
| `/plan` @1280 | 16 | 137 | 10 | 4 | 1 | 10% |

`tokens.css:110-123` 的注释定义得很清楚：16px 才是"学生空间正文/对话"。
实测 16px 在 chat 上只有 **2 个**节点，在 profile 上是 34 / 375。
**真正用来读的那一档几乎没被用**，而"来源/时间/注解"那一档（12px）占了四到六成。

更糟的是**标题小于正文**：`workspace.css:27` 与 `:93` 把 `h2` 写成 `font-size: var(--fs-12)`：

```css
.desk-group h2 { color: var(--c-text-3); font-size: var(--fs-12); font-weight: 400; }  /* workspace.css:93 */
.desk-history__head h2 { font-size: var(--fs-12); font-weight: 500; }                   /* workspace.css:27 */
```

派生的后果：`<h1>30 / <h2>20 / <h3>16` **中间没有档**（六档是 12/14/16/20/30/38）。
所以每一个节标题只能选"和正文一样大（16）"或"跳到 1.5 倍（20）"，
这让整页读起来像一份**规格表**：大量同等重量的小字 + 偶尔一个跳出来的大号句子。
需求方说的"文字罗列""平"（`DESIGN-LANGUAGE.md:88`）——根因不是字多，是**字号阶梯没有中段**。

### 判决 3 ｜配图不是缺，是"零"

5 个路由 × 2 档，一共 **10 张页面实测：`<img>` / `<picture>` / `<canvas>` / `<video>` 数量 = 0**（`probe.json → images`）。

这是学生端"陪一个学生走过一段过程"的产品（`DESIGN-LANGUAGE.md:136`），
却没有任何一张图、一个人、一处场景。顾问在真实页面上**没有形象**——
`/chat` 只渲染出 `.chat-who`（头像 ＋ 姓名 ＋ 职责，`dialogue.css:157-158`），
截图上就是一行灰色小字，没有脸、没有状态、没有在场。

所以需求方对"配图"的直觉是**对的但说反了**：不是配图难看，是根本没有配图；
而且因为缺图，整个产品失去了唯一能压住"一片白"的重量。

**判决一句话**：它像十几年前的造物，不是配色旧，不是配图丑，
而是**这个界面放弃了"用形状说话"**——没有边界、没有中段字号、没有图像，
只靠 1px 的 1.26:1 灰线和一个 12px 的字号去区分所有东西。

## 2. 按优先级排序的问题清单

格式：问题 / 证据 / 严重度 / 具体改法 / 归属（**旧结构**＝迁移 C2 后会消失；**根子**＝迁移后依然在）

### P0

**1. 分层与阴影全部低于感知阈值（≤1.08:1）**
- 证据：上表实测；`tokens.css:277-279`（`--e-1`=6% / `--e-2`=8%）；像素扫描 `chat-1280.png` 纸面左缘与行动卡左缘各只有 1 级灰。
- 严重度：**毁掉整体观感**。这是"白花花一片、什么都立不起来"的直接原因。
- 改法（三条一起改，只改量不改结构）：
  ```css
  /* tokens.css — 保持三层不变，只把"分得开"调到能看见 */
  --c-border: #d4dae4;        /* 1.26:1 → 约 1.45:1，发丝线才开始存在 */
  --c-border-strong: #b9c1cc;
  --e-1: 0 1px 2px rgba(13,13,13,0.10), 0 1px 1px rgba(13,13,13,0.06);
  --e-2: 0 6px 16px -4px rgba(13,13,13,0.14), 0 2px 4px -2px rgba(13,13,13,0.08);
  ```
  并给纸面与页底的关系补一条**非阴影**的分层手段：`.ws-chat-flow` 加 `outline: 1px solid var(--c-border)` 之外的 `background: var(--c-surface)`，同时把页底压到 `--gray-100`（`#ebedf2`，1.171:1）——**页底必须比纸面明显暗**，纸面才浮得起来。
- 归属：**根子**。迁移 C2 也不会自动修好（C2 用的是同一套 `--c-border/--e-*`）。

**2. 中段字号缺失，12px 承担 40–62% 的内容**
- 证据：上表；`tokens.css:118-123`；`workspace.css:27,93` 把 `h2` 写成 12px。
- 严重度：**毁掉整体观感**（阅读密度均匀、无落点）。
- 改法：**不新增字号档**（`CRAFT-BRIEF.md:668` 明令禁止）。
  改用「同字号 ＋ 字重/颜色/宽度」造中段，并把 12px 的用途收死到"时间、来源、序号"：
  ```css
  /* 节标题落到 16px 常规重，靠位置与间隔分段，不再靠跳档 */
  .ws-section-head h2, .ws-section-title { font-size: var(--fs-16); font-weight: var(--fw-semibold); }
  /* 需要更弱的层级时用颜色，不用字号 */
  .ws-section-head h2 + p { font-size: var(--fs-14); color: var(--c-text-3); }
  /* 禁止把标题写成最小档 */
  .desk-group h2 { font-size: var(--fs-12); }  /* ← 保留：它确实是"眉标"不是标题，改成 <p> 或 span */
  ```
  真正要做的是**把 `h2` 的语义与视觉分开**：`workspace.css:27,93` 的 12px 元素不是标题，是 eyebrow——把标签名从 `h2` 换成 `p`，标题层级立刻回到 `<h1>30 → h2 20 → h3 16`。
- 归属：**根子**。

**3. 全站零图像**
- 证据：`probe.json` 5 路由 × 2 档 `images: []`；`_shots/design-review-v7/*.png` 肉眼可核。
- 严重度：**毁掉整体观感**。这是唯一能立刻改变"便宜感"的手段。
- 改法：不必加照片。**顾问需要一个在场形象**——C2 已经做好了（`directions/c2-hbu/shots/avatar-idle|thinking|speaking.png`，40px 与 72px 两档均已验证）。
  把 `.chat-who` 的 40px 头像占位（`dialogue.css:155` `.chat-turn__avatar--gap` 已经预留了 40×40）真正用上，并在**空态**（`/chat` 首屏）放一张顾问卡。空态目前是整个产品最贵的一屏，却什么都没有。
- 归属：**旧结构**（C2 迁移即解决）——但空态顾问卡是**根子**，不迁移不会有。

**4. 图表刻度字实测 1.98:1 —— 真实无障碍缺陷**
- 证据：`probe.json → chat@390.lowContrast`：8 个节点 `"0"/"20"/"40"/"60"`，12px，`#a2a4a6` on `#e1e5ee` = **1.98:1**。
  根因：`--c-text-4`（`#a2a4a6`）在 `tokens.css:204` 被限定"**只给图标/分隔符**"，却被当文字印在 `--c-surface-3` 轨道上。
- 严重度：**无障碍失败**，同时让图表看起来像没渲染完。窄屏是重灾区。
- 改法：刻度文字改用 `--c-text-3`（`#61666b`，在 `#e1e5ee` 上 ≥4.5:1）；
  ```css
  .chat-bars__grid i, .chat-bars__grid span { color: var(--c-text-3); font-variant-numeric: tabular-nums; }
  ```
- 归属：**根子**。

### P1

**5. 主内容与导航抢"最大焦点"**
- 证据：`chat-1280.png`——侧栏「新建咨询」是**实心蓝填充**（`workspace.css:85`，`background: var(--c-primary)`），
  而对话流里唯一的整体性动作「加入行动计划」是**白底蓝字**（同一张图内两个按钮的 `bg` 实测为 `rgb(0,88,167)` vs `rgb(255,255,255)`）。
  侧栏宽 220px，是两个入口里**更重**的那个。
- 严重度：高。产品主循环（对话）被一个壳层按钮压住，用户第一眼落在导航上。
- 改法：`workspace.css:85` 的 `.desk-new-chat` 退成描边按钮（`border: 1px solid var(--c-border-strong); background: var(--c-surface); color: var(--c-text)`），
  只在 `/chat` 之外的路由保留实心；并把 `--c-primary` 的实心配额真正执行 `CRAFT-BRIEF.md:496`（≤1.5%）。
- 归属：**根子**。

**6. 面板没有"凹槽"，composer 与纸面同亮**
- 证据：`dialogue.css:418-420` 的设计意图是凹槽 `background: var(--c-surface-2)`。
  实测像素 `(600,815)` = `#fafafa`，而它上方的纸面 `#ffffff` —— **1.044:1**，凹槽看不见。
  凹槽本身没写成 `text-shadow`/`inset`，`--e-2` 又是 1 级灰。
- 严重度：高。输入区是每次使用都看的地方，它"贴"在页面上，整个对话就显得没做完。
- 改法：
  ```css
  .dialogue-page .ws-composer {
    background: var(--c-surface-2);
    box-shadow: inset 0 1px 2px rgba(13,13,13,0.06), var(--e-2);  /* inset 才是"沉下去" */
  }
  ```
  关键是 **inset**：外阴影只会让它"浮起来"，与"凹槽"语义相反。
- 归属：**根子**。

**7. 控件高度无律：同屏出现 32 / 36 / 38 / 40 / 41 / 42 / 44 / 46 / 60 px 九种高度**
- 证据：`probe.json → controlHeights`（plan@1280: `32×9, 38×2, 40×18, 41×2, 42×2, 44×32, 46×1, 53×1`）；
  根因之一：`workspace.css:188` `.app--workspace .btn { min-height: 42px }` —— **低于 44px 触控硬约束**，
  而 `CRAFT-BRIEF.md:322,389` 反复要求 44px。
- 严重度：高。控件高度不齐是"手搓感"最直接的来源。
- 改法：`workspace.css:188` 的 42px 收到 44px；把全站按钮归到两档：
  ```css
  .app--workspace .btn { min-height: 44px; }
  .app--workspace .btn--sm { min-height: 36px; }
  ```
  并删除 `40/41/42` 三档的一次性值（`redesign.css`、`experience.css` 里的字面量）。
- 归属：**根子**。

**8. 页面最大容器宽度有三个值，且与令牌不一致**
- 证据：`--w-content: 1200px`（`tokens.css:183`，几乎无人用）；
  `.app--desktop .ws-page { max-width: 1180px }`（`redesign.css:3`）、`1160px`（`workspace.css:256`）、
  报告中实测第 4 个值 `1020px`（`geometry.json → report@1280.containers['.ws-page'].maxWidth`）。
- 严重度：中高。跨页切换时内容列会左右跳。
- 改法：只留 `--w-content`，全部写成 `max-width: var(--w-content)`；把 1020px 那条查出来并掉。
- 归属：**旧结构**。

### P2

**9. 侧栏导航与页面底同色，且侧栏内没有唯一"工作面"**
- 证据：像素 `(140,600)` 与 `(250,600)` 同为 `#f7f6f6`；`.desk-sidebar` 计算样式 `background: rgba(0,0,0,0)`。
  注意：`experience.css:3` 的 `.desk-sidebar { background: transparent }` 在 `main.ts:6-7` 的加载顺序下**覆盖**了 `workspace.css:67` 的 `background: var(--c-surface)`。
  另外激活项 `experience.css:13` 给了 `box-shadow: var(--e-1)`——**子项有影、容器没有**，层级是反的。
- 严重度：中高（导航读不出边界，像 HTML 默认布局）。
- 改法：把 `experience.css:3` 的 `background: transparent` 删掉（或改成 `var(--c-surface)`），
  并给侧栏一条 `border-right: 1px solid var(--c-border)`（或按新的 `--c-border` 用 `--e-1`）；激活项的 `--e-1` 去掉。
- 归属：**根子**（且这是**规范已写、被后来文件覆盖**的一处真实回归）。

**10. 标题字距超出项目自己写的上限**
- 证据：`CRAFT-BRIEF.md:536` 明写"负字距只给 ≥20px 的字号，且**不超过 −0.02em**"，
  实际：`workspace.css:258` 与 `:312` 用 `−0.025em`；`redesign.css:6` 用 `−0.02em`（合规）。中文满框字在 −0.025em 会出现部件粘连。
- 严重度：中（不是致命，但违反自定规范）。
- 改法：`workspace.css:258,312` 的 `-.025em` 统一收到 `-.02em`。
- 归属：**根子**。

**11. `--em` 字距用在中文品牌字上**
- 证据：`workspace.css:78` `.desk-brand strong { letter-spacing: .12em }`——中文"职引"被拉散。
  `CRAFT-BRIEF.md:658` 与 `:535` 都禁止中文正字距。
- 严重度：中（品牌字是全站第一眼）。
- 改法：品牌字改 `letter-spacing: 0`，靠字重与字号立它；需要仪式感时只给 12px 短标签用 `0.06em`。
- 归属：**根子**。

**12. 字重出现第四档 700，令牌里只有三档**
- 证据：`tokens.css:130-132` 只有 400/500/600；实测 `/profile` 有 **15 个 700**（`geometry.json` → `fontWeight: 700 ×15`；`strong.cjs` 实测：`78%` 30px/700、`p7-meter__fact` 12px/700×3、14px/700×11）。
  根因：`<strong>` 未被覆盖，用浏览器默认 `bold`。
- 严重度：中（同一屏里同种强调有两种黑度，看起来"没对齐"）。
- 改法：`base.css` 补一条 `strong, b { font-weight: var(--fw-semibold); }`。
- 归属：**根子**。

### P3（旧结构，迁移后消失，此处只登记不计分）

**13. `/chat` 底部留白过大 —— 已挪到迁移后**

## 3. 分层判断：是配色、配图，还是别的？

需求方问："是配色、配图的原因，还是什么？"——三个都过一遍，用实测回答。

### 配色：**不是主因。它是唯一做对的一项。**

| 指标 | 实测 | 判断 |
|---|---|---|
| 白/灰占比 | 91.7% … 96.4% | 严格符合"白灰为底与结构色" |
| 蓝配额 | 1.29% … 1.62%（`pixelQuota.bluePct`） | 在 `CRAFT-BRIEF.md:496` 的 ≤1.5% 配额内 |
| 校徽蓝 `#0058A7` | 对白 **7.109:1**（`tokens.css:50`） | 合格，能直接写字 |
| 文字对比度 | `#1e232c` 15.8:1 / `#4b5157` 8.03:1 / `#61666b` 5.80:1 | **全部通过 AA** |
| 大面积深蓝导航 | 无（侧栏 `#f7f6f6`） | 符合要求 |
| 唯一色相缺陷 | `--c-text-4` 当文字用 → 1.98:1 | 单点缺陷，见 P0-4 |

`CRAFT-BRIEF.md:501` 曾估算"现状蓝色超过 25%"——**那是估算，实测只有 1.3–1.6%**。
这一轮工艺整改在配色上不但达标，而且**过度达标**：把仅有的强调色也压到了几乎看不见。
**结论：拿配色去解释"丑"是误判，改配色不会改善观感。**

### 配图：**方向对，但事实说反了。**

10 张页面实测图片数量为 **0**。不是"配图难看"，是**没有配图**。
这一项**确实**是主因之一，而且是最容易见效的（C2 的头像资产已经做好并验证过 3 种状态）。

### 真正的主因：**层级（hierarchy）——具体说是"结构量低于感知阈值"**

它不是配色问题（配色合规）、也不只是配图问题（配图是其中一条）。
主因是三件事同时发生：

1. **形状层面**：分层/描边/阴影全部 ≤1.26:1 → 界面没有边界（判决 1）。
2. **文字层面**：六档字号里 12px 承担 40–62%，16px 正文几乎不用，标题可以比正文小 → 界面没有落点（判决 2）。
3. **图像层面**：图片为零 → 界面没有重量（判决 3）。

`DESIGN-LANGUAGE.md:88` 自己诊断得很准：**"文字罗列的根因不是字多，是平——所有信息等距、等权、同形。"**
这份评审的补充是：**整改把"等距等权同形"写成了规范，但给每个手段挑的量都在阈值以下。**
规范是对的，量是错的。**"平"没有被治好，只是被重新命名成了"三层表面"。**
所以"还是丑"是必然的——上一轮改的是"有没有规则"，这一轮要改的是"量够不够看见"。

## 4. 与已选定方向 C2-hbu 的差距

选定方向：`redesign-demo/design-review/v6-redesign/directions/c2-hbu/index.html`（口径见 `PLAN.md:117-153`）。

### 差距 1 ｜顾问的"在场"完全没有进入真实页面
C2（`shots/1280-blue.png`）：顶部一张顾问卡，含**卡通头像、名字、职责、"正在想"状态点、三个状态切换**。
真实页：`.chat-who` 只有 12px 灰字（`dialogue.css:157`）＋ 40px 头像占位**空着**（`dialogue.css:155`）。

### 差距 2 ｜结论块的尺度差一个数量级
C2：结论约占屏宽 68%、字号量级明显在 30px 以上，配一条左侧色条，是整页的锚。
真实页：`.chat-block--lead` 为 `--fs-20`（`dialogue.css:225`），实测宽 584px。截图上它是一个略大的句子，不是锚。
→ 加上 20px 与首屏 H1 的 30px 只差 1.5 倍，"主张"和"页标题"分不开。

### 差距 3 ｜外壳完全不同：没有顶部搜索、没有主题/密度切换器、没有品牌条
C2：顶栏有搜索框（⌘K）、右侧有主色/主题/密度三组切换、页面最顶一条品牌色横条。
真实页：顶栏只有「学生空间 / 咨询对话」面包屑 ＋ 搜索图标 ＋ 通知 ＋ 演示数据 ＋ 账号；
无切换器，无品牌条。`--brand-stripe`（`tokens.css:282`）已定义但**首页已不在应用内使用**。

### 差距 4 ｜证据卡的精度
C2（`shots/1280-red-lower.png`）：条形图有 0/33/67/100 刻度、右侧大号 tabular 数值（72/61/54）、单位降档、脚注说明刻度。
真实页：`.chat-bars__rows` 已是 88px/1fr/44px 网格（`dialogue.css:374`）、轨高 10px（`:377`）——**结构对了**，
但刻度字 12px 用 `--c-text-4` 掉到 1.98:1，数值与单位的对比也没建立起来。

### 差距 5 ｜右侧栏在 C2 里是"有重量的纸"，真实页只有 236px 无边界窄列
C2：两张成果卡约 350px，有边界、有内距、有进度条与"看全部成果 →"。
真实页：`.dialogue-rail` 236px，两张 71px 高的窄卡（`geometry.json → railItems`），无容器、无进度条，
且缩在 1180px 布局里最右——与 700px 阅读列之间留下 20px 缝和一条空带。
→ 迁移时建议把 rail 宽度按 C2 提到 300–350px，并**给整列一个容器**，否则它永远像附属物。

## 8. 结论

按 `ui-reviewer` 的收尾口径：

- **Block。** 不是因为品味，而是因为 P0-4 是**真实的无障碍失败**（图表刻度 1.98:1），且 P0-1/P0-2 说明"看得见"这一层尚未建立。
- 一屏里**能真正改变观感**的只有 3 件：**把边界调到看得见（P0-1）**、**把 12px 的内容降下来 / 把 16px 用起来（P0-2）**、**给顾问一张脸（P0-3）**。
  其余 11 条都是配套，不做也不会显著变丑——**宁少而准**，请只按这三件排期。
- 需求方那句"还是丑"是对的判断；错的只是归因。**不是配色，不只是配图，是"形状"这一层从来没有被画出来。**
