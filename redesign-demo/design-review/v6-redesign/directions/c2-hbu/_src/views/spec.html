「活」怎么判定：两类页面，两种活

这一节是整份样张最根本的判定口径，其余所有规矩都从它推出来。核别的页面时，先判它属于哪一类，再按那一类的落点去数。

1 个测试 · 2 类页面 · 4 个落点

第 0 步：截屏测试

截一张静止图。如果信息一点没丢，这个界面就是死的；活的界面静图一定会丢东西 —— 因为它此刻正在生成、正在思考、正在交接、正在推进。

这条测试的价值在于把"感觉"变成可判定的东西，也直接否掉了"加过渡动画"这条路：淡入、位移、数字滚动都不影响截屏结果，所以全都不是"活"。静态界面只有一个时态（现在时）；活的界面有三种 —— 进行时（正在发生）、完成时（刚发生了什么）、将来时（接下来会怎样）。中间状态可见，就活了一半；只给最终态，就是死的。

第 1 步：这是哪一类页面

对话页 过程可见
数据页 组织可见

对话页

天生有一个主体（顾问）和一条时间线（你一句我一句）→ 只要让主体显得在动就活了。它的活 = 过程可见。

数据页

画像 / 报告 / 方向 / 计划 / 日历 / 资讯都是静态名词的陈列：没有主体、没有时间线。它的活 = 组织可见。

常见错法：给数据页搬来对话页那套（流式、头像、气泡）。它根本不成立 —— 数据页照对话页做，只会得到一页会动的静态陈列。

第 2 步：数据页数这 4 个落点，每页至少命中 3 个

#落点用哪些件在页面上表现成什么
①结构显形.sec .kv .tbl .tl .cmp .delta不是一个列表，是信息的形状：谁支撑谁、差多少、连到哪
②组织权交给用户.lens同一批信息按来源 / 时间 / 主题 / 贡献重新分组（条目被搬动，不是换列表）

第 3 步：9 条自查，逐条过

1静图会丢什么信息？丢了什么就说明这页活了。

2有没有"进行时"（正在发生的事可见）？

5组织方式能被用户改变吗？

6状态与不确定性被看见了吗？

7每一处动效，能回答"这里发生了什么"吗？答不上来的删掉。

8prefers-reduced-motion 下有可用形态吗？

9桌面 1280 与手机 390 都成立吗？

允许且鼓励的动效只有一类：它回答"发生了什么" —— 视角重组的 FLIP 搬动、勾选导致的状态迁移（进度推进 / 剩余重算 / 下一件浮出）、进行时标记（.tl__i--now / .tag--live / 骨架）、数值与关系真的变了之后的过渡。第 7 条自查就是它们的准入线。

禁忌清单：10 条，见到就退

前 5 条是"不许动"（它们都不影响截屏结果，所以都是装饰）；后 5 条是"配额"（超了就等于全页没有重点）。这一节是审阅时最省事的一节：随便挑一条，都能在一分钟内判定。

#禁止为什么怎么判
1fade 进场、元素位移进场、给静态界面加"过渡感"不影响截屏结果，所以不产生信息刷新一次，看有没有东西在"进场"
