# c2-hbu · 职引学生端全站界面样张

**双击 [`index.html`](index.html) 打开**（纯静态、离线可用、无外部依赖）。

这是需求方已经选定的视觉方向 **c2（陪伴感 × 河大配色）** 从"单页对话样张"扩成**覆盖学生端全部界面**的可点原型。

## 一、打开后怎么用

| 你想要的 | 怎么做 |
|---|---|
| 走遍全部界面 | 顶栏第二行「**全部界面**」（移动端是底部「更多」）——门户、登录、账号设置、提醒、工具页、使用指南、设计规范、异常页这些**不在学生导航里**，只从这里进 |
| 切主色 / 主题 / 密度 | 顶栏第二行那三组开关：校徽蓝 ↔ 官网红、浅色 ↔ 深色 ↔ 跟随系统、常规 ↔ 紧凑 |
| 换组织方式看同一批信息 | 页面上带「按来源 / 按时间 / 按主题 / 按对判断的贡献」的按钮组 —— 切换时条目是**被搬动的**，不是换一份列表 |
| 看一条信息有多结实 | 每条信息旁的来源 chip（从哪来）与把握档（有多结实、是否过期、是否冲突） |
| 看更细 / 看原文 | 「摘要 / 细节 / 原文」三档（三层**同时**在纸上，只是看得多细由你定） |

配色口径：**校徽蓝 `#0058A7`**（从官方校徽 PNG 像素实测）、**官网红 `#96000E`**（官网 `layout.css` 显式色值）。导航不用大面积深蓝；红色只用于"需要你注意"；**完成不给颜色奖励**。

## 三、设计方法（这一版和"加动画"的区别）

判定口径来自 [`../../DESIGN-LANGUAGE.md`](../../DESIGN-LANGUAGE.md)，核心是**截屏测试**：

> 截一张静止图。如果信息一点没丢，这个界面就是**死的**。

- **对话页的活 = 过程可见**（谁在说、在想、在交接）
- **数据页的活 = 组织可见** —— 数据本来就不动，但"看"的方式可以动
- 反例（明确禁止）：页面淡入、位移进场、数字滚动、持续背景运动、粒子、发光边框、指示线滑动、自动轮播
- 允许的动效只有一类：**能回答"这里发生了什么"**（同一批信息换了组织方式、勾掉一件事之后进度推进、正在生成/正在交接）

数据页统一用**四个落点**（每个页面至少命中三个）：

| # | 落点 | 在哪 |
|---|---|---|
| ① | 结构显形 | 判断 ↔ 它依赖的证据；自身/要求/差距同一把尺子；里程碑 ↔ 任务 |
| ② | 组织权交给用户 | `按来源 / 按时间 / 按主题 / 按贡献` 重组同一批信息 |
| ③ | 粒度与溯源 | 摘要 ↔ 细节 ↔ 原文；每条信息写着从哪来、什么时候记的 |
| ④ | 状态与不确定性 | 依据充分 / 待验证 / 信息不足 / 已过期 / 彼此冲突，都显形并给落点 |

## 四、源文件与工具（改这个样张时要看的）

```
index.html                 ← 产物，不要手改（会被 build 覆盖）
_src/
  BRIEF.md                 ← 视图作者契约（怎么写一个界面，唯一权威）
  DEMO-DATA.md             ← 演示数据简报（20 个界面共用同一份事实）
  views.json               ← 视图登记表（导航、目录、标题都读它）
  shell/                   ← 外壳：head / body-a / body-b / tail
  views/<key>.html         ← 每个界面的主区内容（一个视图一个文件）
  css/00-view-shell.css    ← 多视图外壳样式
  css/10-data-page.css     ← 数据页共享组件层
  css/<key>.css            ← 各视图私有样式
  js/<key>.js              ← 各视图私有行为（用 window.C2 的接口）
  app.js                   ← 外壳行为：路由 / 全部界面目录 / 视角重组 / 粒度缩放 / 即时反馈
_tools/
  c2.css                   ← 样式基线（已批准，只读）
  build.mjs                ← 组装 + 门禁（id 重复 / 失效链接 / 未定义令牌）
  probe.mjs                ← 只读探针：JS 异常 / 横向溢出 / <44px 触控目标 / 视角重组 /
                             某个元素的实际盒与计算样式（--sel）
  shot-views.mjs           ← 按视图 × 宽度 × 主色 × 主题 × 密度 截图
  inspect.mjs              ← 逐视图盘点：行数 / 根元素 / div 配平 / 分区块数 / 面包屑是否合规
  extract.mjs              ← 一次性拆分脚本（保留供复核）
  fix-crumbs.mjs           ← 一次性迁移：把面包屑统一成「分组 › 当前页」（保留供复核）
```

常用命令（在 `directions/c2-hbu` 下）：

```powershell
node _tools/build.mjs                  # 全量组装 + 门禁
node _tools/build.mjs --strict         # 门禁升级为失败（交付前跑）
node _tools/build.mjs --only report    # 只装一个视图 → _shots/preview-report.html（多作者并行用）
node _tools/probe.mjs --shell                    # 全部界面目录 + 21 个界面逐个路由一遍
node _tools/probe.mjs --views --width 1280       # 逐视图：高度 / 横向溢出 / <44px / 视角重组
node _tools/probe.mjs --views --width 390
node _tools/probe.mjs --tap --view report        # 盘 <44px 的可点元素（区分控件与正文行内链接）
node _tools/probe.mjs --lens --view profile      # 盘视角重组：每个视角的组数与搬动条数
node _tools/probe.mjs --wrap --view tools        # 盘横向溢出链（找出到底是哪个元素撑破的）
node _tools/probe.mjs --sel "#pfLensT"           # 量某个元素的实际盒与计算样式
node _tools/inspect.mjs                          # 盘点 21 个视图的落地程度与结构完好度
node _tools/shot-views.mjs --views all --widths 1280,390 --full --out _shots/all
node _tools/shot-views.mjs --views all --widths 1280 --accent blue,red --theme light,dark --out _shots/axes
```

另外：**批准基线自带的 `_tools/verify.cjs` 仍应通过**（它含交互断言、对比度实测、1280/1024/390 三档溢出检查）。
本轮重构后实测：全部断言通过，对比度 blue/dark 最低 5.52:1、red/dark 5.31:1、用户气泡 4.74:1。
⚠️ 它每次运行都会重写 `_tools/contrast-report.json` —— 那是工具产物，不是设计变更。

纪律（上一轮踩过的坑，别复发）：不要手改 `index.html`；不要用跨文件覆盖改别的视图；
不要靠"加动画"交差；改视觉**先量再改**（`probe.mjs --sel`）。

## 五、已知限制（诚实列）

- 这是**静态样张**：数据写死在标记里，交互是演示级的（勾选、筛选、重组、切换是真的，但不落库）。
- 深色主题下红蓝两套的气泡填充相同（`#1b1b1d`），色相只在 1px 边上 —— 这是 c2 靶子带过来的已知限制。
- 门户页按硬约束保持克制（**从门户进入直达对话页**），不是营销落地页。
- `_tools/c2.css` 与 `chat.html` 是**已批准的基线**，本轮没有改动它们的设计。
