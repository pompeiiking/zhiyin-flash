# 当前前端全站检查与修改清单

日期：2026-10-15。检查对象：`redesign-demo`，分支「新前端4」，基线提交 b5a2a04。

本轮是检查与设计整理，尚未修改应用页面。以当前运行版本为基准；C2 及其像素、布局要求仅为历史材料，不再作为验收目标。交接文档仍用于确认业务范围，用户最新要求覆盖其中冲突的视觉和语言要求。

## 一、最新需求与整体判断

保留现有业务能力和红蓝灰白视觉体系，改善整个学生端的美观、易用性、数据一致性和移动体验。范围是 20 个功能区块、22 个页面，逐项考虑结构、布局、信息层级、文字、组件、图形、交互状态和响应式。

新增的两项要求贯穿全站：

1. 语言自然、中性、清楚，适度正式；避免过于口语，也避免工程术语和不必要的专业表达。
2. 默认界面减少信息，优先展示普通用户关心的内容。详细依据通过附近的悬浮小卡片查看，尽量减少下拉菜单和层层展开。

当前主要问题并非颜色不统一，而是说明和统计挤占操作位置、局部状态存在不同计算口径、部分文案承诺超出实际行为。应先修正行为与数据，再调整信息层级，最后统一视觉和文字。直接把内容全部隐藏，会掩盖问题而不能解决问题。

保留的优点：页面入口完整；同一批资料支持不同组织方式；来源与不确定性已有基础；信息更正可保存；提醒支持稍后处理；有新账号与空状态路径；主要页面没有根容器水平溢出。这些基础适合继续完善。

## 二、默认信息与浮层的全站规则

### 默认保留什么

页面首先回答三个问题：当前情况怎样、哪些事项需要注意、接下来能做什么。默认展示核心结论、关键状态、截止时间以及主要操作；数量统计只保留能帮助决策的部分。

不得藏进浮层：表单必填条件、影响操作的限制、失败原因、待确认或不可靠的结论提示、重要截止日期、保存与取消按钮。需要用户比较的核心指标也应同时可见，不能依次悬停才能比较。

### 哪些内容放到附近的小卡片

来源、更新时间、计算口径、术语解释、关联材料、判断依据、较短的历史变化说明。采用与对应信息邻接的查看入口，避免页面到处堆叠问号。较长内容提供「查看完整记录」，再进入侧栏或独立页面。

鼠标悬停或键盘聚焦可打开简短说明；含链接、按钮或需要持续阅读的卡片允许点击固定。手机轻触入口打开同一内容。卡片应自动避开屏幕边缘，不遮挡触发对象和关键操作；鼠标从入口移动到卡片时保持打开；支持关闭按钮、Esc、点击外部关闭以及正确的焦点返回。不能只用 hover，也不能把可交互内容塞进只能阅读的 tooltip。

短说明使用小卡片，完整资料或编辑使用侧栏/对话框，筛选与动作使用明确控件。不要把所有现有折叠组件机械地替换成浮层。已有直接可见、能支持决策的信息应继续保留。

## 五、共性视觉与交互修改

- **P2 信息层级**：先移除重复解释和重复统计，再调整首屏；不能以缩小字号容纳更多信息。普通页面以一项主要操作为中心，次级操作靠近对应内容。
- **P2 组件一致性**：统一信息浮层、详情侧栏、编辑对话框的职责；卡片不必每块都有边框、背景和标题。点击目标建议达到 44px 左右，结合相邻间距验证，而非仅凭小于 44px 就宣称违反 WCAG。
- **P2 表单可读性**：学籍资料弹层背景为白色 78% 透明度，底层表格可透出。提高输入面板的不透明度，重新检查浅/深主题；当前仅确认视觉干扰，未量化为对比度失败。
- **P2 有意义的动态**：保留真实处理、组织方式切换和操作结果的变化；档案进入时从零滚动到目标数字没有新增信息，可取消。浮层用稳定、短促的定位变化，避免持续晃动和抢焦点。
- **P2 长列表**：24 条资讯、24 条待办不是虚拟滚动的充分理由；优先提供清晰筛选、分组、保留阅读位置与批次，避免为了数据丰富让页面无限增长。
- **P3 样式维护**：多层全局覆盖造成组件标准与实际样式不一致。按组件归属逐步收敛 tokens 与断点，避免继续堆覆盖规则。性能需要单独测量，不将文件较大直接等同于页面卡顿。

## 六、统一语言风格

标题准确描述内容，按钮用「动作＋对象」，状态说明写清结果与下一步。表达亲切但不过度劝导，不评价用户，不用模糊代词替代关键对象。用户原话可以保留原意并标明出处，不应将系统用语机械套到原始记录中。

| 当前表达 | 建议表达 |
|---|---|
| 哪个方向现在站得住 | 哪些方向更符合当前条件 |
| 现在最该补的，是把经历讲清楚，不是再加一门课 | 当前优先完善项目经历与成果说明 |
| 这一页最不结实的一条 | 岗位供给信息仍需核实 |
| 现在补哪一条最划算 | 建议优先补充的信息 |
| 这一周到底动了几次 | 本周行动记录 |
| 次动了手 | 项行动已完成或有进展（先修正统计口径） |
| 它撑起的判断 | 该信息支持的判断 |
| 你自己写下的 24 条 | 个人目标与待办，共 24 项 |
| 标记为待重算 | 标记为待更新 |
| 快照、依赖关系、服务回包 | 当前记录、关联依据、读取结果（按具体语境修改） |
| 去做、回头看 | 行动安排、复盘记录 |

无需把「来源」「依据」「待核实」等有用概念全部删掉；将计算方式放入卡片，仍保留必要的可信度提示。界面不标注演示数据，但未提供的信息不能显示成已验证事实。

## 七、建议实施顺序与验收

1. **先处理正确性**：F01—F07、F11，统一当前档案、任务、阶段、执行历史和统计日期；导出内容与页面一致。
2. **修复主要使用路径**：对话输入区、真实处理状态、手机触摸与比较布局。输入框/发送按钮不重叠；有历史长对话时仍能直接输入。
3. **全站减少默认信息**：按逐页清单重排，先让用户看见结论和操作；来源、计算说明和短详情迁移到统一浮层。移动端轻触、桌面鼠标和键盘均能完成查看。
4. **统一文案与视觉细节**：逐元素修改标题、按钮、提示、空白/加载/失败/成功状态，保持一种语气；清除重复统计、技术泄露和无信息价值的动画。
5. **回归与交付**：全部路由检查桌面/手机，覆盖编辑后导出、权重刷新、任务完成/重开、跨周复盘、提醒偏好、失败重试及浮层焦点。保留新账号隔离；确认前端字段覆盖。实施完成提交并推送「新前端4」。

本报告不把页面打开成功等同于功能完成，也不把所有更深信息默认隐藏作为减密度的验收。应确认用户能完成任务，同时随时找到必要依据。
