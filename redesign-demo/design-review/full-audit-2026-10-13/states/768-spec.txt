设计规范

重设计的全部视觉口径都在这里。三条硬约束：主色不超过 3 种（蓝 / 红 / 深灰）、 正文对比度 ≥ 4.5:1、组件里不出现任何颜色字面量。本页色值直接从 :root 读取（当前 --blue-500 = #154494），所以它永远等于界面真实用色。

一、三支主色（就这三个）
蓝 · 主色 · 河大校徽蓝

--blue-500 / --blue-600

参考： 河北大学校徽本体（从校徽矢量图渲染出的 PNG 里量得：蓝色像素 98.3% 落在同一值上）

主按钮、链接、当前步骤、图表主序列。校徽蓝 #154494 对白底 9.19:1 —— 够深，所以它既是品牌色也是文字色，不再分"图形档 / 文字档"两支；悬停压深到 #113a7d。

红 · 注意色

--red-500

参考： 河北大学官网 layout.css 的实际主红（出现 57 次）

给需要注意的地方：截止日、门槛提示。白底 9.12:1。学生空间的品牌标记也沿用这支红。

深灰 · 骨架

--gray-900 / --gray-500 / --gray-200

参考： DeepSeek --ds-color-text-primary 与实测中性灰阶

文字、描边、结构全部由这三档承担。界面里 90% 的面积是灰的，颜色只在少数几处出现。#1e232c 带一点蓝调，与主色同族。

四、皮肤：三条轴，只换令牌不动结构

顶栏右侧的「皮肤」按钮，或按 ⌘K 搜"皮肤"。选择记在本地， 页面的 <html> 上只多出几个 data-* 属性。

轴	属性	档位	换什么	边界
主题	data-theme	浅色 / 深色 / 跟随系统	全部颜色 + color-scheme + 阴影 + 描边强度	深色的边框比浅色更强（浅色黑 10% → 深色白 12–20%）；深色靠提亮表面分层，不靠阴影
主色	data-accent	河大蓝 / 河大红	--c-primary 一族 + 图表主序列 + 焦点环	红做主色时"注意"仍是红，但语法不同：主色是实心，注意是浅底 + 左侧竖线
风格	data-style	极简 / 柔和 / 紧凑	圆角、阴影、卡片内距、行高、入场位移	不动颜色、不动层级、不动字号档位

3 × 2 × 3 = 18 种组合，全部只改值：颜色、圆角、阴影、间距、表面层级。 凡是要改 DOM 顺序、条目数量、组件是否存在 的，都不是皮肤，是分支 —— 所以这里没有"去掉这一块"这种档位。

五、动效：只动"状态真的变了"的地方

判据是频率：一天看几十次的东西不动（导航条、按钮、列表项自身）； 动的是"数字变了""话正在出来""这一步推进了"。所以命令面板刻意没有开合动画。

场景	数值	来源 / 取舍
路由切换	opacity + translateY 6px，160ms ease-out	曲线实测自 Linear --ease-out-quint；只做入场不做退场
列表逐条入场	间隔 40ms、位移 8px、单条 240ms ease-out	间隔取 30–80ms 经验区间中值；上限 8 条，再多就只是慢
数字滚动	420ms ease-out（逐字按字数夹 320–900ms）	number-flow 默认 900/450ms 属"数据揭示"，单个数字压到 420ms
进度 / 分值条	transform: scaleX，250ms ease-out	Material medium1；用 transform 而非 width，避免触发布局
步骤推进	圆圈填色 180ms、连线 240ms、对勾 0.9→1 淡入	Carbon 步骤条：当前步半填充圆、已完成空心圆加对勾
悬停（颜色）	150ms ease	shadcn --default-transition-duration: .15s 与 Resend 同值
按下反馈	scale(0.98)，150ms ease-out	按钮按下 100–160ms；只缩 2%，不做"弹一下"
浮层 / 下拉	180ms ease-out，scale 0.97 → 1，origin 在触发点	禁止 scale(0)：Geist 浮层缩放起点是 0.96
换肤	切换瞬间禁用一切过渡 → 整页 160ms 淡入	给颜色挂全局 transition 会让各元素各自跑；color-scheme 规范上是 discrete，不可插值
键盘发起的动作	不做动画	命令面板（⌘K）刻意没有开合动画 —— Raycast 也没有，这是对的

曲线只有三条，都取自生产 CSS 实测：--ease-out: cubic-bezier(0.23, 1, 0.32, 1)（Linear 的 ease-out-quint）、--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)、 --ease-drawer: cubic-bezier(0.32, 0.72, 0, 1)。 UI 动效一律 < 300ms（数字滚动属"数据揭示"，单独放宽到 420ms）。 prefers-reduced-motion 下：去掉位移与逐条入场， 门户的装饰层整层不渲染（只停动画、保留模糊与遮罩会触发 Chrome 的绘制缺陷，整页变白）。

开始第一个问题
九、明确不做的（附理由，防止下一版又加回来）
不做	为什么
手写体（站酷快乐体）与手写字标题	评审原话：抛弃现有手写类不符合简洁要求的设计元素。手写体让严肃的就业数据读起来不专业。
roughjs 手绘框、抖动的圆角、手绘光标	同一件事：手绘是"草稿"的语气，而这份界面要传递的是"可被盘问的数据"。
第四种色相（紫/青/橙…）	主色不超过 3 种的硬约束。需要区分层级时，用同一色相的深浅与灰阶，不引入新色相。
彩色阴影、玻璃拟态、大渐变	颜色一多，"哪条更重要"就说不清了。层次靠 1px 描边与灰阶，不靠光效。
emoji 当图标	跨平台字形不一致，且与"可被盘问"的气质冲突。只用一处标记：文字或极简 SVG。
渐变进度条 / 彩色仪表盘	分值条只用一个颜色 + 一条门槛线 —— 用户要读的是"差几分"，不是"好不好看"。
