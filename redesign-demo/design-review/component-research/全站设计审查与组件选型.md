# 职引：全站设计审查与组件选型

核查日期：2026-10-13。对象：`新前端2` 衍生工作区的 `redesign-demo`，包含此前的对话层级调整。

## 1. 这次要解决什么

目标是让职引成为清晰、舒展、有辨识度的职业咨询与行动工作空间。设计从用户当前要完成的事出发，同时检查布局、阅读顺序、层级、密度、文字、控件、反馈、动效、响应式和跨页衔接。组件资源用于支持这些决定。

保留现有蓝、红、灰配色；门户保持现有构图。主要阅读与操作面保持安静，视觉丰富度来自真实的比较、日程、来源、进展和记录。用户应能很快看懂“我现在有什么情况、为什么得到这个建议、接下来做什么”。

本文件是研究与改造方案，**不是已落地的界面说明**。本次没有批量安装组件库或改写业务页面。

### 证据与范围

- 逐项检查 `src/router.ts` 的 **16 个路由条目**，包括门户、12 个学生业务页面、指南、规范及兜底页；报告与方向共享文件，按两个任务分别审查。
- 检查应用壳、桌面与移动导航、搜索、登录、账号、提醒、抽屉、表单、任务、图表、来源、空状态和动效实现。
- 对照已有桌面、移动截图及最新对话截图。`desktop-v5` 是 10 月 12 日的历史截图，导航和部分页面已经调整；以当前源码为准。**本次没有把历史图冒充新截图，也没有完成全站最新浏览器走查。**
- 实际请求用户调研文档推荐的 `registry.directory/items.json`：取得 36,645 个条目、91 个 registry。它与说明页的数量不同，且条目缺少发布日期，不能用目录排序证明“最新”。
- 阅读官方组件正文、示例和部分 registry 源码。请求记录在 [evidence.json](evidence.json)，复查脚本在 [research.mjs](research.mjs)。HTTP 成功、正文可读、源码取得、视觉验证是不同证据。
- 用户两份文档用于理解产品和资源。文档中的接服务、注册账号、安装 MCP 等建议不是本次操作授权。

## 2. 近期资源如何选

先判断是否支持真实功能、是否改善层级和使用体验，再比较维护时间、Vue 兼容性、样式可控性和依赖成本。同等适用时优先近期稳定版本。以下日期来自 npm 官方包元数据的对应版本发布时间，**不是每个组件的诞生时间**。

| 候选 | 核实版本 / 发布日期（UTC） | 在职引的定位 | 取舍 |
| --- | --- | --- | --- |
| [Reka UI](https://reka-ui.com/docs/overview/releases) | 2.11.0 / 2026-10-05 | 原语与交互基础 | 项目已使用；首选保持配色与 CSS 自主权。部分新增原语文档标 Alpha，应逐项判断。 |
| [Nuxt UI](https://ui.nuxt.com/docs/releases) | 4.11.3 / 2026-10-01 | 页面组织、消息、表单与复合组件参考 | 支持纯 Vue/Vite，但依赖 Tailwind；先参考结构，不为单个控件迁移全站样式。 |
| [shadcn-vue](https://www.shadcn-vue.com/docs/changelog) | CLI 2.8.2 / 2026-08-08 | 可编辑 Vue 组件与排版参考 | 8 月明确新增 Typeset、Questionnaire；CLI 日期不能代替所有组件更新日期。 |
| [PrimeVue FileUpload](https://primevue.dev/fileupload/) | primevue 5.0.2 / 2026-09-29 | 导入、数据表、时间线的备选 | 与当前简洁视觉需重新协调；npm 授权字段为 `SEE LICENSE IN LICENSE.md`，不直接宣称最新包整体 MIT。 |
| [FullCalendar Vue](https://fullcalendar.io/docs/vue) | 7.1.1 / 2026-10-06 | 完整月历、周视图、日程引擎 | 复杂排课候选；先验证课程节次适配与新版本 API，避免沿用 v6 示例。 |
| [Schedule-X Vue](https://schedule-x.dev/docs/frameworks/vue) | calendar 4.9.1 / 2026-09-29 | 另一套月/周/议程日历 | 外观适合研究；Temporal、主题及插件边界需核实，不默认引入高级插件。 |
| [Vue ECharts](https://github.com/ecomfe/vue-echarts) | 8.3.2 / 2026-10-09 | 多维报告图表的扩展选项 | 数据与交互增加后再引入；少量静态图可以保留现有 SVG。 |
| [Motion for Vue](https://motion.dev/docs/vue) | motion-v 2.6.0 / 2026-10-05 | 复杂布局变化与共享元素动效 | 普通切换优先 CSS / Vue Transition；出现明确需求再加依赖。 |
| [TanStack Vue Table](https://www.shadcn-vue.com/docs/components/data-table) | 9.2.8 / 2026-10-08 | 大量课程、成绩的排序筛选 | 小数据表无需全功能引擎；按使用功能引入。 |

**建议组合：现有 Reka 交互基础 + 自有职引组件外观 + shadcn-vue 与 Nuxt UI 的复合结构参考。** 日历和图表按实际复杂度独立选择。全站保持一套排版、表面与交互规则，避免多库默认皮肤混用。

## 3. 全局设计判断

### 导航与页面关系

当前“咨询 / 画像与诊断 / 方向选择 / 行动与安排 / 复盘与成长”的分组方向合理，匹配产品循环。保留任意阶段进入的能力，不把五阶段做成必须依次通关的进度条。

需要改的是导航密度和视觉优先级：功能分组作为稳定入口；历史会话按近期分组、限制初始数量并提供全部历史入口，避免无限列表挤压功能。页头表达当前位置与本页动作；导航布局、皮肤、年级演示等设置集中到账号/设置入口。移动端保持少量主要入口，“更多”可发现全部功能。

参考 [shadcn-vue Sidebar](https://www.shadcn-vue.com/docs/components/sidebar) 的分区与状态结构，以及 [Nuxt Sidebar](https://ui.nuxt.com/docs/components/sidebar) 的响应式模式。这里选择结构与交互，不照搬其示例品牌。

### 页面有四种主布局

| 类型 | 适用页面 | 内容组织 |
| --- | --- | --- |
| 阅读与咨询 | 对话、报告 | 集中的阅读列，按需查看证据与成果；长报告有目录，对话不常驻画像侧栏。 |
| 比较与决策 | 方向 | 同一比较项下看到所有方向；当前选择稳定可见，风险与依据就近展示。 |
| 执行与安排 | 今日、阶段计划、课表、待办 | 任务或时间网格占主要宽度，操作紧邻对象，说明移到按需展开区域。 |
| 查询与记录 | 画像、资讯、学籍、复盘、工具 | 先组织与筛选内容，再展示列表；详情、来源和编辑保持上下文。 |

参考 [Nuxt Page](https://ui.nuxt.com/docs/components/page)、[DashboardPanel](https://ui.nuxt.com/docs/components/dashboard-panel) 的内容与滚动分区。右列只在提供“本页确实需要同时参照的内容”时存在，不再默认放几段说明文字。

### 视觉与文字

- 同一页面先突出当前问题/结论/任务，再展示支撑信息，最后给来源与操作说明；标题层级和间距应同时表达关系。
- 建議初始阅读列约 680–800px；比较、表格和日程按需要更宽。这是待验证的设计参数，不是新的全站固定宽度。
- 正文按现有中文字体体系优化，主要阅读文字以 16px 为起点；辅助信息约 13–14px，避免靠大量小字换密度。重要状态不能只用颜色表示。
- 减少“容器里再套同样容器”。页面底、主要工作面、需要关注的局部区域形成不同层级；描边、圆角和阴影服从功能。
- 每个独立操作区一个最明确的主动作，其余动作有轻重；资讯的本地筛选与读取数据应有不同名称和位置。
- 空状态、错误与成功提供实际下一步。已有记录不因刷新被整页加载骨架遮掉。

这里采用 [Ant Design Proximity](https://ant.design/docs/spec/proximity/)、[Alignment](https://ant.design/docs/spec/alignment/)、[Contrast](https://ant.design/docs/spec/contrast/) 的关系、对齐与主次原则；这是本项目的设计判断，不是对规范文案的直接复制。

## 4. 逐页审查与布局方案

### 4.1 门户 `/` — 保留，局部精修

文件：`PortalView.vue`、`PortalProposalView.vue`、`PortalExample.vue`；同时检查可切换的 `PortalClassicView.vue`。

现有左侧服务说明、右侧真实咨询示例的构图符合用户已认可的方向。保持主标题、开始咨询和示例之间的层级。仅检查示例切换的可发现性、键盘操作、移动排序、登录入口与进入咨询的连续性。引导示例应显示“问题 → 判断依据 → 可做的一步”，由用户主动切换。

候选：[Nuxt PageColumns](https://ui.nuxt.com/docs/components/page-columns) 用于研究响应式；现有 Tabs / 示例组件保留。无需为了资源数量换掉已合适的门户。

### 4.2 咨询对话 `/chat` — 第一优先级

文件：`ConversationView.vue`、`dialogue.css`、`EvidenceList.vue`、`InfoSheet.vue`。

上一轮已区分用户与顾问、交接与行动，但当前长回复仍主要按空行分段。主标题、角色说明、各轮角色标识、引用工具和输入区需要重新协调密度。顶部成果/画像继续按需打开，右侧画像不常驻。

布局：顶部简短说明与会话动作 → 稳定阅读列 → 固定输入区。顾问结论、问题/选项、行动建议、依据和交接各有对应表面。连续同顾问回复可合组；交接标记低占位，原因按需展开。报告与大段成果进入对应页面，在聊天保留摘要与入口。

候选：

- [Message / Bubble](https://www.shadcn-vue.com/docs/components/message)：借鉴消息行、正文、头像、工具的分工，不把每类内容都套成同样气泡。
- [Typeset](https://www.shadcn-vue.com/docs/typeset)：按结论、段落、列表、表格建立阅读节奏。它负责排版，不能替代内容结构与安全渲染。
- [Questionnaire](https://www.shadcn-vue.com/docs/components/questionnaire)：单题补充信息时支持单选、多选、自由填写与跳过；仅在后端选项语义支持时采用。
- [Marker](https://www.shadcn-vue.com/docs/components/marker)：交接、处理状态用轻量事件行。
- [Message Scroller](https://www.shadcn-vue.com/docs/components/message-scroller)：比较历史恢复、流式跟随、返回最新的行为；已有暂停跟随能力保留。
- [ChatPrompt](https://ui.nuxt.com/docs/components/chat-prompt) / [Attachment](https://www.shadcn-vue.com/docs/components/attachment)：统一输入动作与材料状态；文件名、类型、大小、移除都可辨识。
- [Sources](https://elements.ai-sdk.dev/components/sources) 与 [Plan](https://elements.ai-sdk.dev/components/plan)：按需证据与可执行结果参考。维持已有后端、附件限制与任务接口。

### 4.3 个人画像 `/profile` — 从字段清单到可理解的档案

文件：`StudentView.vue`、`ConfidenceBadge.vue`。

现在按“学校/咨询/行为/本人填写”切换来源，这对核验有用，但初次阅读不易了解自己的能力、经历和目标；缺口在侧栏也比较分散。

布局：身份摘要和更新时间 → 重要待补充项 → 按信息主题分组的字段 → 每项按需展开来源、可信度、时间与更正。来源仍可筛选，作为辅助维度，不删除任何来源功能。可信度由文字与小标识表达；完整度表示已知字段数量，不暗示能力评分。

候选：[Item](https://www.shadcn-vue.com/docs/components/item) 组织字段行，[Nuxt FormField](https://ui.nuxt.com/docs/components/form-field) 研究更正的标签/错误层级，[Reka Dialog](https://reka-ui.com/docs/components/dialog) 保持编辑上下文。主题分组需核实字段模型后落地。

### 4.4 诊断报告 `/report` — 结论、差距、依据三个层次

文件：`AssessmentView.vue`、四个 `charts/*.vue`。

当前优先提升项已经突出，但“差 4 分”缺少同屏的基准背景；依据中多层折叠影响全局阅读；历史版本的选择与当前详细内容容易混淆。

布局：短结论＋最关键差距与建议 → 清晰的章节导航 → 各维度解释 → 按需分值与证据。用“自身值 / 要求值 / 差距”同一刻度表达；版本页突出变更内容、来源时间、影响章节。详细内容的版本不匹配时应明确标注。打印呈现完整内容，不受屏幕折叠状态影响。

候选：[Typeset](https://www.shadcn-vue.com/docs/typeset)、[Nuxt Page](https://ui.nuxt.com/docs/components/page)、[Changelog 风格的 Timeline](https://ui.nuxt.com/docs/components/timeline)。图表比较 [Vue ECharts](https://github.com/ecomfe/vue-echarts) 与现有 SVG；优先保留能清楚表达门槛的条形图，不以新库替代解释。

### 4.5 方向方案 `/directions` — 增强比较能力

文件：`AssessmentView.vue`、`DirectionCompare.vue`。

三张方向卡必须在角色、匹配依据、主要风险、可采取动作上对齐。当前三个强主色选择按钮争抢注意；选择后的影响说明在下方，可能离点击位置较远。移动对照表只能看到很少比较内容。

布局：当前选择摘要 → 一致的比较项 → 主攻/平行/保底方向 → 选择后的关联变化与下一步。采用真实单选语义和统一确认反馈。桌面可并列比较，移动端突出两个方向逐项对照或纵向比较，保留查看全部三个方向的入口；不靠全屏横向滚动。

候选：[Reka RadioGroup](https://reka-ui.com/docs/components/radio-group)、[Tabs](https://reka-ui.com/docs/components/tabs)、原生语义表格。数据仅三列时，TanStack 并无明显收益。机会象限只在有可解释的真实坐标时显示，不能以固定坐标制造精确感。

### 4.6 今日行动 `/home` — 执行优先

文件：`TodayView.vue`、`TaskList.vue`、`TaskOverview.vue`。

当前重点任务有层级，但会在任务列表再出现；完成横幅、最近完成区、状态概览也存在重复。任务来源、时间、截止和状态同排时缺少优先级。

布局：当下最适合的一件事 → 其他待执行与等待任务 → 完成记录。重点任务在列表中明确标记，避免像两件任务。截止/阻塞靠近任务标题，来源与依据按需查看。完成的变化应在原位置可理解，同时保留恢复入口。概览收紧为辅助行，不抢主任务空间。

候选：[Item](https://www.shadcn-vue.com/docs/components/item)、[Reka Checkbox](https://reka-ui.com/docs/components/checkbox)、[Reka Progress](https://reka-ui.com/docs/components/progress)、[Sonner](https://www.shadcn-vue.com/docs/components/sonner) 的撤销反馈。采纳/拒绝、拆小、等待、完成与恢复全部保留。

### 4.7 阶段计划 `/plan` — 让阶段与任务就近对应

文件：`RoadmapView.vue`。

当前“今日/阶段”下又有“里程碑/任务/来源”，信息被多层切换分隔。侧栏的大段跳转说明占据空间，里程碑与相应行动难同时参照。

布局：阶段目标、时间窗和当前重点 → 可展开的里程碑与相关任务 → 来源说明。进度要有真实分母/完成依据；只有实际顺序成立时才连成步骤，不强行套学习闯关进度。

候选：[Timeline](https://ui.nuxt.com/docs/components/timeline)、[Stepper](https://ui.nuxt.com/docs/components/stepper)、[Progress](https://reka-ui.com/docs/components/progress)。优先时间线与局部展开；需要后端提供里程碑—任务关联时列为接口条件。

### 4.8 日历与课表 `/schedule` — 时间网格取得完整宽度

文件：`ScheduleView.vue`、`lib/academic.ts`。

当前月份固定为 2026 年 10 月，月格与周课表缺少日期导航；课表被说明侧栏挤窄，跨节课程在多个格重复，手机阅读也吃力。

布局：时间导航＋月/周/议程切换 → 全宽日期/课程工作面 → 点击后的当日事项与建议。手机版优先当日/议程，以日期选择辅助导航。课程、行动、截止、复盘用名称/标识区分，沿用蓝红灰。空白课格仍不宣称空闲时间。

候选比较：

- [Reka Calendar](https://reka-ui.com/docs/components/calendar)：日期选择，不等于完整事件日历。配自有议程列表是最轻方案。
- [FullCalendar Vue](https://fullcalendar.io/docs/vue)：完整时间网格与事件展示候选。节次需有真实时间映射，原始节次仍可查看。
- [Schedule-X Vue](https://schedule-x.dev/docs/frameworks/vue)：比较月/周/议程与主题适配。高级插件不能默认假设免费可用。
- [ReUI 日历＋事项列表源码](https://registry.directory/api/markdown/keenthemes/reui/c-calendar-22)：已取得源码，用于研究两者如何连接；React 参考，不直接安装。

先确定节次数据和真实日程更新能力，再选择引擎；不能为了美观编造课程时间。

### 4.9 学籍与资料 `/academic` — 导入流程成为可检查的过程

文件：`AcademicView.vue`。

资料概况、核验说明、撤回说明分散；导入弹窗同时摆两份长 JSON，初次使用成本高。文件选择目前是原生控件，缺少统一材料列表与结果预览。

布局：资料快照与来源时间 → 课程/成绩表 → 按需核验。导入拆为“选择材料 → 预览识别结果 → 确认”，突出可读取类型与错误位置。只有完成真实读取后才显示真实进度和结果；演示 JSON 模式保持标注。

候选：[Nuxt FileUpload](https://ui.nuxt.com/docs/components/file-upload) 与 [PrimeVue FileUpload](https://primevue.dev/fileupload/)；前者适合研究轻量材料区，后者比较完整选择/验证过程。表格比较 [Data Table](https://www.shadcn-vue.com/docs/components/data-table) 与现有原生表格；导入步骤参考 [Stepper](https://www.shadcn-vue.com/docs/components/stepper)。学信网验证码是完整字符串，不能误改成短信 OTP 六格输入。

### 4.10 待办与目标 `/notes` — 简单而完整的记录工具

文件：`NotesView.vue`。

快速输入合理，但说明侧栏比列表更占注意；完成项目与未完成项目混排。每行一直显示删除图标，操作层级偏重。

布局：记录类型＋快速输入 → 未完成列表 → 可收起的已完成列表。移动端操作始终可发现；次要动作在菜单中，删除支持合适的本地撤销/确认。保留两类草稿、重复提交处理、创建时间与完成恢复。

候选：[Input Group](https://www.shadcn-vue.com/docs/components/input-group)、[Item](https://www.shadcn-vue.com/docs/components/item)、[Checkbox](https://reka-ui.com/docs/components/checkbox)、[Toast](https://reka-ui.com/docs/components/toast)。已有功能不支持目标进度时，不新增虚假的百分比环。

### 4.11 岗位资讯 `/intel` — 信息源清楚的查询页

文件：`IntelView.vue`。

当前本地关键词筛选与“读取示例”在同一个提交表单；条目均为标题/正文/来源，类型、更新时间和摘要没有充分分层。侧栏常驻两段说明，内容区不够舒展。

布局：搜索与筛选条 → 结果数量/排序 → 有摘要、类别、来源、时间的条目 → 按需详情。将职业匹配置于明确工具入口；信息事实与个人匹配判断保持边界。正文没有图片字段时，靠排版和信息分类丰富界面，不添加虚构公司照片或 Logo。

候选：[Nuxt BlogPost / BlogPosts](https://ui.nuxt.com/docs/components/blog-post)、[Reka Combobox](https://reka-ui.com/docs/components/combobox)、[Empty](https://ui.nuxt.com/docs/components/empty)、[Sheet](https://www.shadcn-vue.com/docs/components/sheet)。只借文章条目的标题/摘要/来源层级；筛选类型、排序与分页需对应实际数据/接口。

### 4.12 复盘与记录 `/review` — 从事实自然进入调整

文件：`ReflectionView.vue`、`AchievementsSection.vue`。

统计、待复盘卡、近期完成与执行时间线分散；“原因”默认选中可能让人把系统预设当成已确认归因。成就页应继续由真实行为驱动。

布局：需要复盘的任务和实际结果 → 用户确认原因 → 调整建议和动作 → 连续执行记录。原因使用明确单选，未确认与已确认分开。最近完成放入时间线，不另重复一列。完成记录突出事实、时间与相关行动，不加入签到、积分、庆祝粒子。

候选：[RadioGroup](https://reka-ui.com/docs/components/radio-group)、[Questionnaire](https://www.shadcn-vue.com/docs/components/questionnaire)、[Nuxt Timeline](https://ui.nuxt.com/docs/components/timeline) / [PrimeVue Timeline](https://primevue.dev/timeline/) 的节点结构。记录保持纵向，方便移动阅读。

### 4.13 工具 `/tools` — 小型功能目录

文件：`ToolsView.vue`。

当前只有两个模块；使用大表面和两条文字行导致界面显空。改为紧凑入口：图标、用途、关联数据和进入动作。仅展示后端已发布模块，不填充不存在的工具。

候选：[Item](https://www.shadcn-vue.com/docs/components/item) 与 [PageColumns](https://ui.nuxt.com/docs/components/page-columns)。模块少时不用复杂网格或轮播。

## 6. 动效、适配与协调性

建议的动效预算：按钮/焦点约 120–160ms，视图/局部展开约 160–220ms，面板约 200–260ms。具体时长需试验；优先让变化可追踪，不给每个卡片加独立入场。复杂任务移动可以参考 [Motion Layout](https://motion.dev/docs/vue-layout-animations)，简单变化继续使用已有 Vue Transition。

桌面不能为了填满宽度塞说明侧栏；手机不能只把三列缩成窄条。方向改纵向比较，日程改议程，报告目录按需展开，编辑容器避开软键盘。320–390px、常见桌面和放大文字均需验证。焦点、Esc、点击背景、返回焦点、箭头选择和读取状态提示由同一交互规范约束。

跨页动作命名保持一致：对话“加入行动计划”之后可“查看行动”；画像更正后可知影响了哪些内容；方向选择后进入关联计划；任务完成进入行为记录；复盘调整回到任务。所有状态只表达真实发生的事件。

## 7. 四个优先原型

这四个原型检验不同页面布局，完成后再推广到其他页面。

```text
对话：  会话标题 / 按需成果
        用户内容
        顾问结论 → 问题或可做的一步
        依据（展开） / 工具
        材料 + 输入 + 发送

方向：  当前选择 / 可调整
        比较项      主攻      平行      保底
        依据、风险与下一步按同一顺序
        选择变化 → 关联计划

日程：  日期导航 / 月·周·议程
        完整宽度的日期或课程工作面
        选中日期的事项 / 建议（按需）

资讯：  搜索 / 类型筛选 / 更新时间
        结果概况
        标题 → 摘要 → 来源与时间 → 详情
```

原型验收不只看漂亮：新用户能找到入口；用户知道为什么得到建议；一个明确动作能完成；回退、错误、空数据和触屏也完整；页面有视觉区分但属于同一产品。后端暂不提供的关联/排序/进度能力明确记为依赖条件。
