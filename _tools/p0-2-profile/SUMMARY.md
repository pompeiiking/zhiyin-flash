## 1. 判据：正文 vs 标注

两条，缺一不算正文（写在 `StudentView.vue` 样式块头部注释里）：

- **① 有没有主张**：这段字自己承载一条要读进去的信息（字段名 / 判断 / 状态 / 动作 / 说明），
  还是只在给别的信息当坐标（时间 / 来源 / 序号 / 计数 / 刻度 / 徽章）？
- **② 换掉它信息会不会丢**：删掉「靠 A 的」只剩一排依赖边、删掉「待补充」缺口卡照样成立 → 标注；
  删掉「专业」「下一步：…」整行/整卡就不知道在说什么 → 正文。

`tokens.css` 登记的 12px 用途是「来源 / 时间 / 注解」，评审口径再收成「来源 / 时间 / 序号 / 计数 /
徽章 / 图表刻度 / chip」。**命中标注的一律留在 12px，不为压比例而放大**。

## 9. 还原正确性怎么保证的

1. 动任何东西之前先备份原文件：`_tools/p0-2-profile/StudentView.vue.orig`，
   SHA256 `358149FB…7084`，与 `git diff` 空、`git rev-parse HEAD=a914bcf` 时的 HEAD 版本一致。
2. 需要"改前"数字时用 `_tools/p0-2-profile/roundtrip.mjs`：写入改前版本 → 校验 SHA256 →
   等 3s 让 vite 重编译 → 跑测量 → **在 `finally` 里无条件写回改后版本并再校验 SHA256**，
   不匹配就把退出码置 3。每次运行的输出都打印了两侧的哈希，实测三次全部 `OK 校验通过`。
3. 改后文件的最终哈希 `1B1DAD6B…F09F`，与 `roundtrip` 报告一致；
   收尾再用 `git status` 确认只有这一个文件被改。

   底栏书签）。它们多为时间/计数，按判据**应该保留**；但其中 `.ws-bookmarks span`（"对话/行动/方向"）
   与 `.desk-brand div > span`（"生涯规划与就业指导"）是**能读的导航文字**，值得另开一轮在
   `workspace.css` 里讨论。
3. **`h3` 的 `-0.01em`（16px = -0.16px）** 是 V7 评审 P2-10 那类"负字距用在 <20px"的残留，
   来自全局样式，本轮无权改。CRAFT-BRIEF 4.1 的字面口径是"负字距只给 ≥20px"。
4. **`.p7-meter__how p` 实测 line-height 1.8**：它来自 `base.css` 的 `p` 规则（0,0,1 但后加载）
   盖掉了本文件 `--lh-normal`(1.7) 的声明。不属本任务，但同一类"规范被后来文件覆盖"的病还在。
5. **`p7-block__tag` 的 22×22px 方块**在 14px 下只剩左右各 2px 余量，横向窄屏没出问题，
